0. 本文范围与阅读方式

本文把一次完整解锁从设备就绪到终帧的每一个阶段展开：每一步主机发什么（协议层命令/参数）、设备做什么（判定/窗口/超时）、灯带显示什么（颜色+图样）、蜂鸣什么、异常时怎么收场。两条解锁主线（UNLOCK_MULTI 同步解锁 / LOCKER 后台编排）共用同一套判定内核与灯语语义，差异只在编排粒度。Round_011 起 0x08 ONE_SHOT 单标签流程已废除——单标场景即 UNLOCK_MULTI epcCnt=1（解锁窗 W=2min），同一流程同一布局，无独立单标通道（详见 §4 迁移指引）。

协议层视角声明：本文只描述主机可观测行为（命令、参数、响应、推送帧、灯语、蜂鸣、时序窗口）。设备内部实现（芯片型号、引脚、总线、寄存器）不属于协议层内容，一律不出现——需要时参见源码与硬件文档。
读者建议：上位机开发者按 §2→§7 顺序读；现场/店员培训只需 §1（灯语表）+ §6（失败对照表）+ §8（时序图）。

1. 灯语设计总则 — 方案 A "五色叙事"（Round 011）

设计目标：让完全不懂设备的普通人只看灯就能回答三个问题——"现在轮到谁了？它干完了吗？出事了吗？"。

颜色一句话语义图样规则
白该你了（设备在等人放标/等人操作）慢闪=等放标（等待中）；常亮=软标消磁等待（流程已过半）
蓝该我了（设备自己在读标签）慢闪=盘点校对进行中；单闪 200ms=刚解码到一张标签（无论对错）
绿对了单闪=命中一张期望标签；常亮=磁块升起开锁保持；三连闪=结账完成
红出事了快闪 3s=EPC 失配（标签不对，不升起）；双闪 1s=链路断/消磁失败；常亮=设备故障锁定
黄设备自检类（工程/未完成，非故障）慢闪=回零中/未放标或窗满收尾（2s）；快闪=行程测试或安全回退；粉红=行程开关错误（工程）
灭待机/回降/结束"正在工作"绝不用全灭表达
时序叙事链（正常人一次结账看到的灯）： 白慢闪（放标）→ 蓝慢闪（在读）→ 蓝单闪（读到了）→ 绿单闪（对了）→ 绿常亮（升起来了）→ 白常亮（软标消磁）→ 白单闪（消掉一个）→ 绿三连闪（办完了）→ 灭。
两条铁律：① 一色一义，不撞色（绿=成功、红=出错绝不挪用）；② 闪=需要你注意或正在活动，常亮=状态稳定。

2. 通用前置：复位后设备就绪时序

T=0s     复位/上电
T~4-7s   设备自检 POST：电机/行程/UHF/AM 逐个探测 + UHF 自动上电并下发持久化配置
         （主机此刻拿不到 USB 枚举——等枚举成功即可用，无需先发 OPEN/SET_CONFIG）
T~7.2s   USB 就绪，可发首条命令
T~7.3-12s 后台回零（上行触上行程→下行触下行程建立基准）
         灯语: 黄慢闪; 期间 MOVE/TEST/开锁类命令回 BUSY
T~12s    回零完成; IO_DIAG homing=2 (READY); 全部命令正常受理
         全部自检通过 -> 蜂鸣 1s（任一失败静默，错误由灯语/自检位图表达）
主机侧建议：枚举成功后轮询 IO_DIAG (0x10) 直到 homing=2（0/1=进行中，3=失败），再开始解锁业务；homing=3 时任何运动类命令都会被拒绝（err=7 HOMING）。

3. 流程一：UNLOCK_MULTI (0x0A) 同步解锁 — 唯一开锁通道（单标/多标）

场景：客户付款后来结账。上位机把结账清单（m 张硬标签 EPC + 软标数）单帧下发，客户把标签放到开锁器上（光电触发），设备持续比对：清单内 EPC 稳定确认 → 绿灯升起开锁（逐张推 0x0B 回传）；清单外 EPC 独占 → 红闪不升起（推 0x0C 回传，不终止）。硬标段预算 W=2min+30s/额外标签（m=1 即单标 2min），全部确认（n==m）立即进入软标段；每个软标对应一次解码，次数用完即结账完成。单命令同步阻塞，过程推送事件帧，主机也可 QUERY/GET_PROGRESS/CANCEL。

3.1 请求与解锁窗（协议层）

LOCKER_CTRL (0x0D) · sub=0x0A UNLOCK_MULTI
[0A, tmoL,tmoH, holdL,holdH, softCnt, epcCnt, epcLen, epcCnt*epcLen 字节]

tmoMs     单轮盘点时限      0→1000  上限 10000
holdMs    解锁窗 W 覆盖     0=按公式; 非0 → min(host, 240000)
softCnt   软标消磁数        0=跳过软标段
epcCnt    期望标签数 m      1~4 (1 即单标流程)
epcLen    单条 EPC 长度     1~12

解锁窗 W = 120000 + (m-1)*30000 ms  (首标签 2min, 每多一标签 +30s)
W 自光电触发时刻起算, 兼任光电等待窗与校对预算;
全部确认 (n==m) 硬标段立即结束 — W 是预留上限, 不是最短等待

3.2 全阶段详解（含灯语/蜂鸣/推送帧）

阶段设备行为（协议层）灯语蜂鸣推送帧
⑴ 前置 + 受理Locker/UHF/电机均空闲 + 已回零（否则 BUSY 附三模块状态 / HOMING 附 switchErr）；受理即推 0x0F 受理帧（含实际生效 W）——0x0F EVT_START
⑵ 光电门控：等放标红外光电检测到放标（200ms 去抖）才继续；窗=W，窗满 → err=11 NO_IR（不升起、不碰 UHF/AM，磁块原位）白慢闪（该你了）—NO_IR 无推送，直接终帧 + 黄慢闪 2s
⑶ 消磁准备
(softCnt>0)		AM 探链 + 强制"检测模式"——校验通过前只检测不消磁，防止残留消磁模式在校对期误消软标继承白慢闪—失败红双闪 + 终帧 err=10
⑷⑸ 持续校对
(每标签独立状态机)		UHF 上电+连续盘点（扫描窗内强制 session=S0，结束还原）。PENDING → TRACKING → CONFIRMED：双门限确认（连续在场 3s 且累计读到 ≥2 次；单轮漏读不打断累计）；离场超 3s 回 PENDING 重算。CONFIRMED 单向掩码：后续读到静默忽略。首张确认即升起（绿常亮，保持至硬标段结束，之后回蓝慢闪等余下）；每确认一张推 0x0B 确认帧（含真 EPC/判据耗时/流程耗时 = 比对结果回传上位机）。外来 EPC 不升不计数；连续 3 轮外来独占且无清单标签 → 推 0x0C 失配帧（不终止，窗 W 兜底；再见清单标签重新武装）蓝慢闪（该我了）；读到任何标签蓝单闪；每确认一张绿单闪；首确认起绿常亮每确认一张短鸣 200ms0x0B EVT_TAG（逐张）/ 0x0C EVT_MISMATCH
⑹ 硬标段收尾结束原因四种：全部 m 张确认 ALL_OK（n==m）/ 窗 W 满 PARTIAL_TIMEOUT（bitmap 明示）/ CANCEL / UHF 失联 5s。推 0x0D 硬标完成帧 → 回降（免疫打断）回降灭；窗满未收齐 黄慢闪 2s；UHF 失联 红双闪—0x0D EVT_HARD_DONE
⑺ 软标解码
(softCnt>0)		硬标校验已通过，此刻才切 AM 消磁模式；每个软标对应一次解码，计数每 +1 推 0x0E；达标或 5min 软标窗满（以实况结账）出口切回检测模式白常亮；每消掉一个白单闪；消磁失败红双闪—0x0E EVT_SOFT（逐个）
⑻ 回降 + 终帧磁块下行至下行程触点（安全方向，免疫打断）；0x0A 终帧汇总：endReason + bitmap + confirmed/total + 升降步数 + softDone/softCnt + elapsed（自光电触发）。流程结束 AM 自动切回检测模式、扫描会话还原原配置结账完成 绿三连闪 → 灭全部结账完成长鸣 300ms终帧（响应通道）
解锁态响应矩阵：受理帧起至终帧发完，仅 CANCEL / QUERY / GET_PROGRESS（及各 FC 只读命令）放行；其余 LOCKER/MOTOR/UHF/AM 控制类一律 BUSY。

3.3 endReason 判据表（err=0 时，硬标段结束原因）

end含义正常用途
1 ALL_OK全部 m 张确认（n==m）硬标段正常完成的唯一推荐判据
2 PARTIAL_TIMEOUT窗 W 满，部分确认（bitmap 明示哪些已确认）超时兜底，按实况处理
4 UHF_LOST链路失联确认窗（5s）仍坏设备异常
6 ABORTED主机 CANCEL（安全回降后以实况结账，跳过软标段）人工取消

4. 0x08 ONE_SHOT 单标签流程 — Round_011 已废除（迁移指引）

0x08 不再解析任何帧形状，收到一律回 [08, 2] (PARAM)。废除动机：单标/多标本就是同一业务（比对→确认→升起→软标→结账），0x08 独有的"保持期 3s 稳定即结账"判据与 0x0A 的"逐张确认 + n==m"语义不一致，双通道徒增状态机分支面与互斥检查。

迁移指引（主机侧三步）： ① 请求帧从 [08, tmo(2), irWait(2), hold(2), epcLen, epc.., (demagCnt)] 改为 [0A, tmo(2), hold(2), softCnt, 1, epcLen, epc..]（epcCnt=1，原 demagCnt→softCnt）； ② 原"等终帧一问一答"模式不变，新增低频推送帧 0x0F/0x0B/0x0D（softCnt>0 时 0x0E）可忽略或用于进度显示；GET_PROGRESS 布局统一为 [phase, holdMs(3), total, confirmed, bitmap, softCnt, softDone]； ③ 判定语义变化：原 end=7 STABLE_OK（3s 稳定即结账）→ 0x0A end=1 ALL_OK（单标在场连续 3s 且读到 ≥2 次即确认）；解锁窗从 irWait/hold 双窗 → 统一 W=120000ms（holdMs=0 即公式缺省，恰 2min）。
原 0x08 语义速查（仅存档）：ONE_END_* 1=TAG_REMOVED / 2=HOLD_TIMEOUT / 3=TAG_CHANGED / 4=UHF_LOST / 5=DEMAG_DONE / 6=ABORTED / 7=STABLE_OK；对应 0x0A 语义：移除/超时/换标 → PARTIAL_TIMEOUT(2) 按实况，消磁达标 → ALL_OK+软标段，取消 → ABORTED(6)。完整定义见 App_Protocol §13.1。

5. 流程三：LOCKER 编排模式（后台结账）

场景：设备自主跑完整结账会话——主机先配清单（ADD 挂单），START 后设备后台持续扫描，主机异步用 QUERY/GET_EVENT 收事件。适合固定工位无人值守逐张放标。

IDLE --ADD(0x02 清单挂单)--> CONFIGURED        灯: 蓝慢闪 (持续盘点等硬标签)
CONFIGURED --START(0x04)--> 扫描段            逐张放标: 读到=蓝单闪, 命中=绿单闪+短鸣
  首张命中 -> 磁块升起                       灯: 绿常亮 (升起到位回蓝慢闪继续等)
  全部硬标命中 -> SOFT_DECODE (若有软标)      灯: 白常亮
    软标事件: 消磁成功=白单闪 / 失败=红双闪
  -> DONE (绿三连闪+长鸣) -> LOWERING -> IDLE  灯: 回降=灭
任一阶段失败 -> FAULT (红常亮), CANCEL(0x03)可退出
事件经 GET_EVENT(0x05) 异步拉取: MATCH_OK/MISMATCH/HARD_DONE/
  SOFT_USED/TIMEOUT/DONE/FAULT 七类 (事件码见 App_Protocol §13)
状态 (QUERY d[2])语义灯语
0 IDLE空闲灭
1 CONFIGURED已配清单等放标（持续扫描）蓝慢闪（读到=蓝单闪）
2 UNLOCK_HOLD磁块升起，继续等余下硬标签升起中绿常亮 / 扫描段蓝慢闪
3 SOFT_DECODE硬标全解，轮软标（消磁）白常亮（成功白单闪/失败红双闪）
4 DONE结账完成（等待回降）绿三连闪后灭
5 FAULT故障锁定（归因 1~8）红常亮
6 LOWERING回降中灭
与 0x0A 的取舍：要一问一答同步阻塞（结账清单一次下发）用 0x0A；要设备自主后台会话 + 逐张放标用 LOCKER 编排。两者互斥（前置检查保证同一时刻只有一条主线）。

6. 失败路径 → 错误码/灯语映射总表

场景协议层结果灯语（闪后回落）现场含义 / 店员动作
客户一直没放标err=11 NO_IR（0x0A）黄慢闪 2s"没看到东西"—引导客户放标后重发
放了标但拿走/读不到窗 W 满部分确认 end=2 PARTIAL_TIMEOUT（bitmap 明示已确认张）黄慢闪 2s标被拿走或位置不对—重新放
标签不属于本单0x0C 失配帧（连续 3 轮外来独占，推帧不终止）红快闪 3s"这张不对"—核对商品；放对标签即继续，窗 W 兜底
UHF/AM 链路断err=3/4/10（UHF_OPEN/LINK、AM_LINK）；end=4 UHF_LOST红双闪 1s设备级问题—找维保
消磁失败（软标消不掉）0x0E 计数不增 / 事件 SOFT 不到标（软标窗满以实况结账）红双闪 1s软标可能已失效或位置不对—重试或人工处理
升降电机故障/超时err=8 MOTOR_FAULT / err=9 MOTOR_TIMEOUT（附快照+phase+retreat；retreat=0 已安全回降）安全回退中黄快闪；锁定红常亮设备级问题—找维保
未回零/行程开关错误err=7 HOMING（附 switchErr 位图）；IO_DIAG homing=3黄/粉红闪（行程错误最高优先级，盖过一切）装机/维保项—重启观察，复现找维保
流程被主机取消end=6 ABORTED（安全回降后正常回帧）回降中灭正常人工取消，无异常
设备故障锁定（编排模式）Locker QUERY state=5 + FAULT 事件（归因 1~8）红常亮CANCEL 可退出复位重试；复现找维保
安全兜底不变式（所有失败路径共同保证）：① 任何失败不动磁块的阶段（⑴~⑶）失败磁块原位；② 升起后任何失败必先安全回降到下触点再回帧；③ AM 消磁模式只在 EPC 校验通过后进入、任何出口（含失败/取消）切回检测模式——不存在"误消软标"路径；④ 扫描会话强制 S0 且结束还原——改坏配置不可能残留。

7. 进度观测与打断（三条主线通用）

命令内容典型用法

8.2 失败时间线（放错标签）

等放标白慢闪
在读蓝慢闪 · 蓝单闪×N(读到错的)
失配确认红快闪 3s · 磁块不动
0x0C 失配帧回落蓝慢闪 · 磁块不动 · 不终止等窗 W
时序要点:
· 蓝单闪出现在每轮盘点读到标签的瞬间 (闪显槽深1, 连读合并成一次, 不会爆闪)
· 绿单闪(命中)必然紧跟在若干蓝单闪(读到)之后 — "读到了"永远先于"对了"
· 红快闪 3s 期间稳态灯被压制 (闪显优先), 窗口结束回落
· 行程开关错误灯语优先级最高, 会盖过上述一切 (工程态明确优先)
