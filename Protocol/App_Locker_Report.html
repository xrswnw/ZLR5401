一、约束 → 功能设计映射

《约束/Link.txt》定义了开锁器完整运行逻辑。本设计将其拆分为一个可执行的状态机，逐条落到对已实现底层模块的调用：

#约束原文（Link.txt）实现落点模块
1客户付款上位机侧；设备收到「结账任务」即开始协议层
2上位机把结账标签的 EPC 传给开锁器LOCKER_SUB_ADD 逐条下发硬标签 EPC + LOCKER_SUB_CONFIGURE 设软标数量App_Locker
3开锁器接收硬标签 EPC 和软标数量清单缓存于 AppLockerCtx_tApp_Locker
4客户把标签放到开锁器上，光电触发UHF 盘点到放置标签（数据面环形缓冲）App_UHF
5比对 EPC：一致亮绿灯升起开锁；不一致红灯闪烁不升起；结果回传上位机LockMatch 分支 → rise_lock() + 事件 MATCH_OK / MISMATCH 入上报缓冲App_Locker + LED + Stepper
6硬标签预留 2 分钟，每多一个标签 +30s保持窗口 2min + (m-1)×30s，超时回落并上报 TIMEOUTApp_Locker
7读到不同 EPC 且解锁数量 n 达硬标签数 m，进软标阶段hardMatched==hardCount → HARD_DONE → SOFT_DECODEApp_Locker
8每个软标对应一次解码数量，次数用尽结账完成LOCKER_SUB_CONSUME_SOFT 消耗一次；softUsed==softCount → DONEApp_Locker + App_AM

二、已实现模块的复用（不重复造轮子）

硬标签 — UHF 读卡 已提供

App_UHF 控制面/数据面解耦：App_UHF_Inventory() 发起盘点，标签结果经 App_UHF_TagTake() 一条条取出（含 EPC + RSSI）。配置/上电由 App_UHF_Open() 完成并持久化。

开锁器业务仅需在 LockConfigured 态轮询数据面，把取到的 EPC 与清单比对——无需触碰 USART1/0xBB 帧底层。

软标 — AM 解码器 已提供

App_AM 提供解码器配置（阈值/命中次数/频率范围/模式）+ 逐命令同步读写的控制面。软标「按次数解码」由业务层按 1 次/软标 的计数驱动。

初版以 LOCKER_SUB_CONSUME_SOFT 显式上报「解码一次」完成计数；后续可改为调用 App_AM_Query() 自动判定解码成功。

升降开锁 — 步进电机 已提供

App_Stepper 提供 App_Stepper_Move()（方向 + 目标微步数）驱动 DRV8434S。本设计以「升起/下降」两个定步数动作封装 rise_lock() / lower_lock()，步数可配置。

状态指示 — LED 已提供

约束说明 当前硬件为单绿灯（PB4, PW-limb 呼吸），无独立红灯。本设计阶段以 LedHl_GOn() 指示就绪/匹配，红灯闪烁语义在报告中标注为「待硬件确认/红灯 GPIO」待扩展项，逻辑分支已预留（MISMATCH 事件已上报，点灯可后续接入）。

三、业务状态机（App_Locker）

stateDiagram-v2 [*] --> IDLE IDLE --> CONFIGURED: ADD/CONFIGURE 建立任务 CONFIGURED --> CONFIGURED: 匹配→升起+灯, 上报MATCH_OK CONFIGURED --> CONFIGURED: 非清单→不升起, 上报MISMATCH CONFIGURED --> SOFT_DECODE: hardMatched==hardCount (HARD_DONE) CONFIGURED --> IDLE: TIMEOUT / CANCEL SOFT_DECODE --> SOFT_DECODE: 消耗一次软标 (SOFT_USED) SOFT_DECODE --> DONE: softUsed==softCount (DONE) SOFT_DECODE --> IDLE: TIMEOUT / CANCEL DONE --> IDLE: 停留后回落 IDLE --> FAULT: 电机/链路故障 FAULT --> IDLE: 清障
状态语义：IDLE=空闲锁定 · CONFIGURED=可开锁（硬标比对中） · SOFT_DECODE=硬标已全部解锁，软标计数中 · DONE=结账完成 · FAULT=故障。

状态定义

状态值进入条件行为 / 退出
IDLE0上电 / 取消 / 完成默认锁定（磁块回落）；CONFIGURE/ADD → CONFIGURED
CONFIGURED1建立结账任务轮询 UHF 比对 EPC；匹配点亮绿灯升起；全匹配 → SOFT_DECODE；超时/取消 → IDLE
SOFT_DECODE3硬标签 m==n每次 CONSUME_SOFT 消耗一次；次数尽 → DONE
DONE4软标次数用尽停留 5s 后回落 → IDLE
FAULT5UHF 链路/电机故障回落锁定；清障 → IDLE

时间窗计算（约束 #6）

开锁保持窗口 = 2min + (hardCount − 1) × 30s，匹配任一硬标签即刷新该窗口； 窗口内允许重复开锁/取放，超时则磁块回落并上报 LOCKER_EVT_TIMEOUT。

四、协议扩展 — FC_LOCKER_CTRL (0x0D)

在既有 Sw 帧（CRC32 / HID 报告 ID 0x02）之上新增命令，遵循已有 data[0]=子命令, data[1]=err 风格，响应 func = 0x0D ^ 0xFF = 0xF2。

子命令Host→Device说明
CONFIGURE 0x01[cmd, hardL,hardH, softL,softH]清空清单，设软标数量；hardCount 上限预检
ADD 0x02[cmd, epcLen, epc…]追加一条硬标签 EPC（可连续发，条数 ≤16）
START 0x03[cmd]UHF 上电 + 开扫，进入可开锁
CANCEL 0x04[cmd]取消任务，磁块回落回 IDLE
QUERY 0x05[cmd][cmd,err,state,hm, sc,su] 查询状态/计数
CONSUME_SOFT 0x06[cmd]软标解码 1 次（进 SOFT 后使用）
GET_EVENT 0x07[cmd]取一条上报事件（结果/异常回传上位机）

上报事件（GET_EVENT 返回）

事件码含义触发
MATCH_OK 0硬标签匹配，亮绿灯升起比对一致
MISMATCH 1非清单 EPC，不升起比对不一致
HARD_DONE 2硬标签全部解锁m==n
SOFT_USED 3消耗一次软标解码CONSUME_SOFT
TIMEOUT 4开锁窗口超时超时回落
DONE 5结账完成软标次数用尽
FAULT 6故障链路/电机异常

六、待确认 / 后续优化

初版简化（已明确）

  • 硬标签清单用「ADD 逐条」构建，未做单帧批量，避免 HID 56B 限制。
  • 软标阶段 v1 依赖上位机显式上报「已解码一次」，未自动判定解码成功。
  • 光电触发未接独立红外输入，以 UHF 数据面轮询替代（预留 NotifyTag）。

待硬件/需求确认

  • 红灯：当前仅单绿灯；红灯闪烁需确认是否加第二次 GPIO / 驱动。
  • 磁块升降步数 APP_LOCKER_STEP_RISE/LOWER 需按实测行程标定。
  • 软标自动判定：接入 AM 解码成功回执后可由设备自动计数（替代 host 上报）。
  • 清单持久化 / 事件审计日志（掉电不丢）可加 EEPROM。
说明：本报告为初版功能设计；已实现并可编译通过，红色语义与软标自动判定为明确的待确认/后续项。设计基于《约束/Link.txt》与既有模块实际能力，非规划中的高阶需求。
