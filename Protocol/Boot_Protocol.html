🔧 Boot USB 协议规范 — Bootloader IAP 升级

协议版本：PROTO_VERSION = 2

设备层：BOOT（Layer=0）

USB VID:PID：0x5377:0x5378（与 App 相同）

Manufacturer：SW COMPOSITE  |  Product：SwCcrd  |  Serial：SwCcrd

物理层：USB HID Interrupt (Full Speed 12 Mb/s, EP1 IN / EP2 OUT, 64B 包, 16ms 轮询)

帧格式标识：0x53 0x77 ("Sw" LE) + devAddr + reserved + length(LE16) + func(1B) + data(N) + crc32(LE32)

目标读者：上位机开发者（PC 升级工具 / OTA 服务端）

🏗️ 协议栈分层

💡 设计核心

Bootloader 是升级通道的核心。Boot 启动后若 deviceStatus != UPG（无待升级标志的冷启动），跑 2500ms 超时窗口（BOOT_TIMEOUT_MS，Round 014 起 500→2500，覆盖 Mac/Win 1~3s USB 枚举时延），期间主机通过 USB 或 UART 发握手 → 升级启动 → 数据传输 → 校验 → 执行 5 步完成固件更新。若 deviceStatus == UPG（由 App 的 FC_ENTER_BOOT 置位后复位进来），则 stayInUpdate=true 不超时，无限等待升级；可用 FC_EXIT_BOOT (0x09) 退出回 App。

💡 Report ID = 0x02

Boot 发送时第一个字节固定为 0x02（参见 Boot_Usb_HL_Transmit）。Host 接收 64B 报告时，前缀 0x02 是 HID 标准报告 ID，需要先剥除再解析协议层帧。

📦 协议层帧格式

通用帧结构

偏移  字段         长度  说明
0x00   header1     1B    固定 0x53 ('S')
0x01   header2     1B    固定 0x77 ('w')
0x02   devAddr     1B    设备地址 (广播 0xFF, 默认 0x01)
0x03   reserved    1B    保留 0x00
0x04   length      2B    payload 长度 (LE), 含 func + data + CRC32
0x06   func        1B    命令码
0x07   data        N     数据载荷 (N = length - 5)
N+7    crc32       4B    CRC32 (LE), 覆盖前 N+3 字节

总长 = 6 (header+addr+reserved+length 自身) + payload
      = 6 + (1 + data_len + 4)
      = 11 + data_len

★ length 范围: 5 ≤ length ≤ 1029 (5 = FC + CRC32, 1029 = 1024 + 5) ★
★ length 是 payload, 不包括 header/addr/reserved/length 自身 ★

响应帧 (Boot → Host)

响应 = 请求的反向:
  帧结构相同
  func = req_func ^ 0xFF  (例如 0x03 → 0xFC)
  data = 业务结果 (通常第一个字节是 RESULT_OK 或错误码)

★ 响应经"收到帧的同一通道"回 (UART 收 → UART 回, USB 收 → USB 回) ★
★ 帧头定义: PROTO_HEADER = 0x7753 ('Sw' LE) ★
★ 校验失败 / length 越界 → 静默丢弃, 不响应 ★

📋 命令码 (FC) 与响应

Boot 实现的全部 8 个命令（接管 IAP 全流程 + 软件复位）：

⚠️ Boot 端的所有响应使用 Proto_TxResponseTo

Boot 端响应时使用 Proto_TxResponseTo(ch, devAddr, reqFc, ...) 而不是 Proto_TxResponse，因为 Boot 需要把响应回给请求方地址（devAddr 字段），可能与本机地址不同（多机场景）。

🚀 IAP 升级流程

完整升级序列

1. 探测设备 (USB 或 UART)
   └─ 主机枚举 USB HID (VID 0x5377:0x5378)

2. 握手: FC_HANDSHAKE (0x01)
   └─ 接收 12B 响应, 确认 Layer=0 (Boot) / Status=UPG 或 IDLE

3. 进入升级模式 (可选)
   └─ 通过 App 发 FC_ENTER_BOOT (0x02) → App 写 PARAM_STATUS_UPG + 延 50ms + 自动软复位
       → Boot 看到 status=UPG → stayInUpdate=true 无限等待升级 (不超时)
   └─ 或: Boot 冷启动无 UPG 标志时, 在 2500ms 超时窗口内直接发 START 也可
   └─ 进 Boot 后若决定不升级: 发 FC_EXIT_BOOT (0x09) → Boot 校验 App 完好后清 UPG->RUN
       + 复位 → 跳回 App (Round 016)

4. 启动升级: FC_UPGRADE_START (0x03)
   └─ Request data (16 字节):
        [0..3]   FwSize (u32 LE)         // 固件大小 (字节, ≤ 40KB)
        [4..7]   FwCrc32 (u32 LE)        // 期望 CRC32
        [8..11]  FwVer (u32 LE)          // 固件版本号
        [12..15] BindVerify (u32 LE)     // 绑定校验值 (VerifyLevel=FULL 时使用)
        [16]     VerifyLevel (u8, 可选) // 0=FULL / 1=MID(默认) / 2=BASIC
   └─ Boot 处理:
        FwSize 校验 (≤ 40KB = APP_FLASH_SIZE, > 0)
        FlashHl_WriteBegin
        擦除 ceil(FwSize/PAGE) 页 (PAGE=1KB)
        FlashHl_WriteEnd
        若成功 → IapCtx.State = IAP_ERASED → 返回 RESULT_OK
        若失败 → 返回 UPG_ERASE_FAIL

5. 数据传输: 多次 FC_FW_DATA (0x04)
   └─ 每包 Request data (≥4 字节):
        [0..1]   seq (u16 LE)            // 包序号
        [2..5]   addrOffset (u32 LE)     // APP 区偏移 (0..FwSize-1) — Round_098 BUG#4: 原 u16 在固件 >64KB 时无编码, 扩为 u32
        [4..N]   data (N-4 字节)          // 实际固件数据
   └─ Boot 处理:
        检查 state==IAP_ERASED
        检查 addrOffset+dataLen ≤ APP_FLASH_END
        按 4 字节对齐写 Flash (不满 4B 用 0xFF 填充)
        IapCtx.Written += dataLen
        若 Written >= FwSize → state = IAP_DATA_DONE
        返回 [seq(2) + result(1)]
   └─ 主机: 循环发包直到收到足够数据 (按 FwSize 分片)

6. 校验: FC_UPGRADE_VERIFY (0x05)
   └─ Boot 处理 (按 VerifyLevel):
        [BASIC]  Written != FwSize 或 state != DATA_DONE → VERIFY_SIZE_MISMATCH
        [BASIC]  Crc32Calc(APP_FLASH_ORIGIN, FwSize) != FwCrc32 → VERIFY_CRC_MISMATCH
        [MID]    *APP_FLASH_ORIGIN & 0x2FFC0000 != 0x20000000 → VERIFY_VECTOR_INVALID (MSP)
        [MID]    *(APP_FLASH_ORIGIN+4) 越界 → VERIFY_VECTOR_INVALID (Reset)
        [FULL]    Crc32CalcReflect(APP_FLASH_ORIGIN, FwSize, &deviceUidHash, 4) != BindVerify → VERIFY_BIND_FAIL
        全部通过 → state = IAP_VERIFY_OK → RESULT_OK
   └─ 返回 [result + subCode]
        subCode = 0 (通过) / 1 (Reset 向量越界, 仅 VERIFY_VECTOR_INVALID 时填)

7. 执行跳转: FC_UPGRADE_EXEC (0x06)
   └─ Boot 处理:
        若 state != IAP_VERIFY_OK → 返回 VERIFY_CRC_MISMATCH (拒绝跳转)
        ParamSave: deviceStatus=RUN, appCrc32=FwCrc32, appSize=FwSize, upgradeCount++, bindVerify
        NVIC_SystemReset()  →  软复位, 跳新 App
   └─ 返回 RESULT_OK

🚀 FC_UPGRADE_START (0x03) 详细

请求帧

data (16 或 17 字节, LE):
  Offset  字段         长度  说明
  0x00    FwSize       4B    固件大小 (字节, ≤ APP_FLASH_SIZE = 40KB)
  0x04    FwCrc32      4B    期望 CRC32 (覆盖 APP_FLASH_ORIGIN..+FwSize)
  0x08    FwVer        4B    固件版本号 (任意业务定义)
  0x0C    BindVerify   4B    绑定校验值 (VerifyLevel=FULL 时必填)
  0x10    VerifyLevel  1B    可选, 不传默认 MID (0=FULL / 1=MID / 2=BASIC)

frame.length = 5 + 16 = 21 = 0x15 (无 VerifyLevel)
frame.length = 5 + 17 = 22 = 0x16 (带 VerifyLevel)

响应帧

data (1 字节):
  Offset  字段    值       说明
  0x00    result  0=OK     擦除成功, 进入 IAP_ERASED 状态, 可开始 FC_FW_DATA
                1=NO_SPACE   FwSize > 40KB 或 == 0
                2=ERASE_FAIL Flash 擦除失败

完整响应帧: 53 77 ADDR 00 0600 FC result [CRC32 4B]
                                  ↑  ↑
                                  │  └─ result
                                  └─ FC_RSP(0x03) = 0xFC

Flash 擦除策略

/* 仅擦除必要页数, 不动 boot/param 区 */
erasePages = (FwSize + FLASH_PAGE_SIZE - 1) / FLASH_PAGE_SIZE
              = ceil(FwSize / 1024)
for (i = 0; i < erasePages; i++) {
    addr = APP_FLASH_ORIGIN + i * 1024
    if (addr >= APP_FLASH_END) break    // 40KB 越界保护
    FlashHl_ErasePage(addr)
}
⚠️ Flash 擦除的安全保证

擦除范围严格限定在 APP_FLASH_ORIGIN (0x08006000) 之后的 FwSize 字节内，不擦 boot/param 区。即使 FwSize 设错（如 0xFFFFFFFF），循环里的 addr >= APP_FLASH_END 检查保证不会越界到 boot 区。

📦 FC_FW_DATA (0x04) 详细

请求帧

data (≥4 字节, LE):
  Offset  字段         长度  说明
  0x00    seq          2B    包序号 (主机递增, 用于匹配响应)
  0x02    addrOffset   4B    APP 区偏移 (u32 LE, 0..FwSize-1, 从 APP_FLASH_ORIGIN 开始)
  0x04    data         N     实际固件数据 (N = dataLen - 4)

frame.length = 5 + N (N = addrOffset_end - addrOffset, 主机分片决定)

★ 注意: 单包 data 长度受 UART DMA buffer 限制 (1024B) 或 USB HID 64B 限制
★ 推荐每包 ≤ 1024B (UART) 或 ≤ 53B (USB, Report ID 占 1B, frame header 占 6B, seq+off 占 4B)
★ 主机按 FwSize / 单包大小 计算包数, 逐包发到 Written >= FwSize

响应帧

data (3 字节):
  Offset  字段    长度  说明
  0x00    seq     2B    回显主机发的包序号 (确认哪一包已处理)
  0x02    result  1B    0=OK, 2=DATA_FLASH_FAIL, 3=DATA_ADDR_ERR

完整响应帧: 53 77 ADDR 00 0800 FB [seq 2B] result [CRC32 4B]
                                  ↑        ↑
                                  │        └─ result
                                  └─ FC_RSP(0x04) = 0xFB

Boot 处理流程

FC_FW_DATA 收到 →
  检查 state == IAP_ERASED, 否则拒绝
  解析 seq + addrOffset
  dataLen = f.dataLen - 4
  检查 addrOffset + dataLen ≤ FwSize, 否则 DATA_ADDR_ERR
  FlashHl_WriteBegin
  按 4 字节对齐写 (不足 4B 用 0xFF 填充)
  FlashHl_WriteEnd
  写失败 → DATA_FLASH_FAIL
  写成功 → Written += dataLen
            若 Written >= FwSize → state = IAP_DATA_DONE
  返回 [seq(2) + result(1)]
⚠️ Flash 写的 4 字节对齐

STM32 Flash 只能按 4 字节 (1 word) 编程。Boot 在 FlashHl_WriteWord 内部按 4B 对齐写，最后不足 4B 的尾包自动用 0xFF 填充（避免固件尾段被前一次烧写的旧数据覆盖）。

三级校验

级别校验项失败返回
BASIC (VerifyLevel=2)Written == FwSize 且 state=DATA_DONEVERIFY_SIZE_MISMATCH
Crc32Calc(APP_FLASH_ORIGIN, FwSize) == FwCrc32VERIFY_CRC_MISMATCH
MID (VerifyLevel=1, 默认)(APP_FLASH_ORIGIN) & 0x2FFC0000 == 0x20000000 (MSP 在 RAM 区)VERIFY_VECTOR_INVALID, subCode=0

💡 校验级别含义
  • BASIC：开发期, 仅 CRC 校验, 快速验证 flash 内容
  • MID：生产固件默认, 加向量检查确保不烧坏 boot 跳转
  • FULL：量产防伪, 固件与设备 UID 绑定, 防止跨机刷写

Crc32CalcReflect 算法

/* 计算带 suffix 的 CRC32:
 *   CRC32(APP_FLASH_ORIGIN..FwSize) XOR reflect(suffix, suffixLen)
 *
 * 防止跨设备刷写: 即使固件内容相同, 不同设备的 deviceUidHash 不同,
 *   计算结果也不同, BindVerify 校验失败, 拒绝执行 */
uint32_t Crc32CalcReflect(data, len, suffix, suffixLen) {
    uint32_t crc = 0xFFFFFFFF;
    for (uint32_t i = 0; i < len; i++)
        crc = (crc >> 8) ^ table[(crc ^ data[i]) & 0xFF];
    for (uint32_t i = 0; i < suffixLen; i++)
        crc = (crc >> 8) ^ table[(crc ^ suffix[i]) & 0xFF];
    return crc ^ 0xFFFFFFFF;
}

                                  ↑  ↑
                                  │  └─ result
                                  └─ FC_RSP(0x06) = 0xF9

Boot 处理

FC_UPGRADE_EXEC 收到 →
  if (state != IAP_VERIFY_OK) → 返回 VERIFY_CRC_MISMATCH (拒绝)
  ParamSave:
    deviceStatus  = PARAM_STATUS_RUN (1)
    appCrc32      = g_sIap.FwCrc32
    appSize       = g_sIap.FwSize
    upgradeCount++ (升级次数累加)
    bindVerify    = g_sIap.BindVerify
  NVIC_SystemReset()  → 软复位, 跳到新 App (PC = APP_FLASH_ORIGIN + 4, 即新 Reset 向量)
⚠️ ParamSave 失败保护

Boot 不检查 ParamSave 返回值（参数区写失败概率极低，因为之前擦过 APP 区但不动 PARAM 区）。如果发生写失败，设备重启后会回到"默认行为"：Boot 看到 status 不是 UPG → 2500ms 后跳 APP，新固件仍在但参数区为旧值（不影响固件运行，只是升级次数和 bindVerify 没更新）。

🚪 FC_EXIT_BOOT (0x09) 详细 — 退出升级回 App (Round 016)

用途

主机经 App 的 FC_ENTER_BOOT 进入 Boot 升级等待后，若决定不升级，发本指令退出。Boot 校验 App flash 完好后清 UPG 标志 + 复位，自动跳回现有 App，无需走完整升级流程。

请求帧

data = (空, dataLen 必须 = 0)  →  frame.length = 5

响应帧

data (1 字节):
  Offset  字段    值              说明
  0x00    result  0=OK            校验通过, 清 UPG->RUN, 即将复位跳 App
                  1=NO_APP        App flash 无有效镜像 (MSP/Reset 向量非法)
                  2=CRC_MISMATCH  App CRC 与参数记录不符 (flash 被擦除/损坏)
                  2=ENTER_BOOT_PARAM_ERR  ParamSave 写失败 (复用参数错码)

完整响应帧: 53 77 ADDR 00 0500 F6 00/01/02 [CRC32 4B]
                                ↑      ↑
                                │      └─ result
                                └─ FC_RSP(0x09) = 0xF6

Boot 处理

FC_EXIT_BOOT 收到 →
  if (dataLen != 0) → 回 result=1 (参数必须为空), 不复位
  1) MSP 向量合法性: (*APP_FLASH_ORIGIN & 0x2FFC0000) == 0x20000000
     否则 → EXIT_BOOT_NO_APP (1), 不复位
  2) Reset 向量合法性: APP_FLASH_ORIGIN ≤ resetVec < APP_FLASH_ORIGIN + APP_FLASH_SIZE
     否则 → EXIT_BOOT_NO_APP (1), 不复位
  3) CRC 校验 (仅当参数记录 appCrc32!=0 且 appSize!=0 且 appSize≤APP_FLASH_SIZE):
     Crc32Calc(APP_FLASH_ORIGIN, appSize) == appCrc32?
     否则 → EXIT_BOOT_CRC_MISMATCH (2), 不复位
  通过 → deviceStatus = PARAM_STATUS_RUN (1)
       → ParamSave 持久化
       → 回 OK
       → 延时 50ms (等 ACK 发出)
       → NVIC_SystemReset() → 复位后 Boot 读 RUN, stayInUpdate=false,
         2500ms 窗口后 JumpToApp → 跳回现有 App
💡 设计要点

校验逻辑与 main.c::JumpToApp() 完全一致（向量 + CRC），确保flash 正常才跳。校验失败时不复位，避免跳到被擦除/损坏的空 App（此时只能通过完整升级恢复）。CRC 仅在参数有记录时校验；无记录（appCrc32==0）则只做向量校验，仍允许跳。

⚠️ 与 FC_RESET 区别

FC_RESET (0x08) 仅复位，不清 deviceStatus——若当前 status=UPG，复位后仍卡 Boot。要在 Boot 中退出回 App，必须用 FC_EXIT_BOOT (0x09)（清 UPG + 校验 + 跳 App）。

🤝 FC_HANDSHAKE (0x01) 详细

Round 018 协议 (App/Boot 一致): 请求和响应 payload 完全相同, 仅 Layer 字段不同（App=1, Boot=0）。

响应帧

data (28 字节, LE, Round 019 移除冗余 version 字段):
  Offset  字段          类型    说明
  0x00    result        u8      0 = RESULT_OK
  0x01    protoVer      u8      PROTO_VERSION = 2
  0x02    status        u8      IDLE/RUN/UPG/FAULT
  0x03    UID           12B     STM32 唯一 ID (@ 0x1FFFF7E8)
  0x0F    uidHash       u32 LE  CRC32(UID)
  0x13    layer         u8      1 = APP / 0 = BOOT
  0x14    upgradeCount  u32 LE  累计升级次数
  0x18    baudRate      u32 LE  USART 当前波特率

完整响应帧: 53 77 ADDR 00 2100 FE [28B payload] [CRC32 4B]
len=0x21=33 = 1(func)+28(payload)+4(CRC)

Device Status 含义

  • UPG (2)：App 收到 FC_ENTER_BOOT 后写入。Boot 看到 UPG 停留等待升级，超时 = 0 (无限)
  • IDLE/RUN/FAULT：上电默认或上次升级完成。Boot 看到这些状态 → 跑 500ms 超时窗口后跳 APP

⏱ Boot 启动时序

main() {
    Sys_CfgClock()                     // 72MHz PLL
    System_PeriphClkInit()             // GPIO/USART/USB/SPI/DMA 时钟
    __asm volatile ("cpsid i")         // ★ 关中断 (待所有外设初始化完才开)

    SysTickHl_Init()                   // 1ms tick
    BootDispatchInit()                 // 注册 UART transport + 帧回调, 默认通道 USB
    bootStartMs = SysTickHl_GetMs()

    BootLedInit()                      // PB4 LED
    ParamInit(&g_sParam)
    if (ParamLoad(&g_sParam) != 0) {  // 读参数区 (主+影子) 失败
        // 用默认参数重新初始化并保存 (主+影子)
        g_sParam.magic = PARAM_MAGIC;
        g_sParam.version = PARAM_VERSION;
        g_sParam.baudRate = 115200U;
        g_sParam.deviceStatus = PARAM_STATUS_IDLE;
        g_sParam.deviceAddr = PROTO_DEV_ADDR_DEFAULT;
        g_sParam.deviceUidHash = Crc32CalcUid();
        // ... 版本字符串/用户区清零
        ParamSave(&g_sParam);
    }
    ParamSyncVersion(&g_sParam);      // 把代码里版本同步回参数区

    uint32_t baud = g_sParam.baudRate;
    Uart_Init(baud);                   // HOST_UART (USART2)
    Boot_Usb_Init();                   // USB HL + 注册 USB transport (Round 044, 与 App 对齐)
    IwdgHl_Init();                     // 独立看门狗 (未启用)

    int stayInUpdate = (g_sParam.deviceStatus == PARAM_STATUS_UPG);

    __asm volatile ("cpsie i")         // ★ 开中断 (所有初始化完成)

    while (stayInUpdate || (SysTickHl_GetMs() - bootStartMs) < BOOT_TIMEOUT_MS) {
        Proto_Poll();                  // 收帧 → BootDispatch
        if (g_sIap.State != IAP_IDLE && g_sIap.State != IAP_VERIFY_OK)
            bootStartMs = SysTickHl_GetMs();  // 升级中重置超时
        BootLedProcess();              // 1Hz LED 心跳
        IwdgHl_Feed();
    }

    SysTickHl_Stop();
    BootLedOff();
    JumpToApp();                       // 校验 + 关中断 + 清 NVIC + 设 VTOR + 跳
}

超时与跳转决策

BOOT_TIMEOUT_MS = 500ms:
  IDLE/RUN/FAULT:
    → 500ms 内无 EnterBoot, 跳 APP
  UPG (deviceStatus=2):
    → 停留等待 FC_HANDSHAKE/START
    → 收到任何升级命令, bootStartMs 重置 (再给 500ms)
    → 完成升级 (Exec 后) NVIC_SystemReset → APP
    → 主机可以通过 FC_ENTER_BOOT 把 Boot 状态再延 500ms

📋 Boot 协议总结

  • ✅ USB HID Custom 设备：VID 0x5377 / PID 0x5378 (同 App) / "SW COMPOSITE" / "SwCcrd"
  • ✅ 2 个中断端点：EP1 IN (TX) / EP2 OUT (RX)，各 64B，16ms 轮询
  • ✅ 完整 IAP 流程：5 步 (START → DATA → VERIFY → EXEC) + 2 辅助 (HANDSHAKE / DEVICE_INFO)
  • ✅ 三级校验：BASIC / MID / FULL，可按需配置
  • ✅ 设备绑定：FULL 校验时固件与 UID 哈希绑定，跨机刷写被拒
  • ✅ Flash 安全：仅擦 APP 区，不动 BOOT/PARAM 区；addrOffset 严格越界检查
  • ✅ 状态机：4 状态 IDLE → ERASED → DATA_DONE → VERIFY_OK
  • ✅ 错误码：所有 FC 失败都有明确定义 (UPG_*, DATA_*, VERIFY_*)
  • ✅ CRC32 算法：MPEG-2，多项式 0x04C11DB7，init=0xFFFFFFFF，无反射，无最终 XOR (App/Boot 同算法)
  • ✅ USB 通道：App/Boot 均已注册 USB HID transport (Round 044)，主用通道 = USB；UART 仅作为 Boot 备用通道
  • ⚠️ 单帧限制：USB HID Report 64B（含 Report ID），剥后 63B 给协议；协议层帧体 11 + data_len ≤ 63 → 单包 data ≤ 52B。超过 52B 的命令（仅 FC_FW_DATA）需主机分片；其余命令（START/HANDSHAKE/VERIFY/EXEC）均在单包内。
  • ⚠️ UPG 状态停留依赖 ParamSave 成功，Flash 异常会卡死

🛠 上位机 OTA 参考实现 (供工具开发)

1. USB HID 通信约束

// 单包上限计算 (USB HID Full Speed Interrupt):
//   USB Report 总长:        64B  (含 1B Report ID, Boot 端用 Report ID=0x02)
//   协议层可用:             63B  (剥 Report ID)
//   协议帧头:               header(2) + devAddr(1) + reserved(1) + length(2) = 6B
//   payload:                 func(1) + data(N) + CRC32(4) = N + 5B
//   单包 data 上限 = 63 - 6 - 1 - 4 = 52B
//
// 命令单包 vs 分片:
//   FC_HANDSHAKE          1B data  → 单包
//   FC_DEVICE_INFO         0B      → 单包
//   FC_RESET               0B      → 单包
//   FC_UPGRADE_START       16/17B  → 单包
//   FC_UPGRADE_VERIFY      0B      → 单包
//   FC_UPGRADE_EXEC        0B      → 单包
//   FC_FW_DATA             ≥4+data → 主机分片, data 每片 ≤ 52B (推荐 48B 留余)
//
// UART 通道 (备用):
//   波特率 115200 (默认, 参数区 baudRate 可改)
//   1 start + 8 data + 1 stop = 10 bit/byte → 单字节 86.8us
//   单包理论上限受 UART DMA 限制 (1024B), 实际推荐 ≤ 256B 一片

2. 帧结构精确公式

// 发送帧总长 = 6 + (1 + data_len + 4) = 11 + data_len
// 单包 data 上限 52B → 协议帧总长 11 + 52 = 63B (刚好填满 64B Report)
//
// 字段字序 (LE 小端):
//   length(2):   [low byte, high byte]
//   CRC32(4):    [b0, b1, b2, b3]  (LE)
//   uint32_t 值: [b0, b1, b2, b3]  (LE)
//
// CRC32 算法 (与固件 Crc32Calc 一致):
//   poly = 0x04C11DB7
//   init = 0xFFFFFFFF
//   无反射 (no reflection)
//   无最终 XOR (no final xor)
//   覆盖范围: 帧头 + devAddr + reserved + length + func + data (前 N+7 字节)
//   注意: 这是 MPEG-2 风格 CRC32, 与 Python binascii.crc32 不同!

3. 完整 OTA 升级流程 (上位机伪代码)

#!/usr/bin/env python3
# 上位机 OTA 参考实现 (Python 伪代码)
import hid, struct, time

VID, PID = 0x5377, 0x5378
DEV_ADDR = 0x01

def crc32_mpeg2(data: bytes) -> int:
    """与固件 Crc32Calc 一致 (MPEG-2, 无反射/无最终 XOR)"""
    crc = 0xFFFFFFFF
    for b in data:
        crc ^= b << 24
        for _ in range(8):
            crc = ((crc << 1) ^ 0x04C11DB7) & 0xFFFFFFFF if (crc & 0x80000000) else (crc << 1) & 0xFFFFFFFF
    return crc

def build_frame(func: int, data: bytes = b"") -> bytes:
    payload = 1 + len(data) + 4  # FC + data + CRC
    body = bytes([0x53, 0x77, DEV_ADDR, 0x00,
                  payload & 0xFF, (payload >> 8) & 0xFF, func]) + data
    crc = crc32_mpeg2(body)
    return body + bytes([crc & 0xFF, (crc >> 8) & 0xFF,
                         (crc >> 16) & 0xFF, (crc >> 24) & 0xFF])

def send_and_recv(dev, tx: bytes, wait_ms: int = 800) -> bytes:
    """发送 + 异步等响应 (drain 异步 DATA 行, 见 ComforTool daemon)"""
    # 主机: 写入 HID Output Report (自动填 64B)
    padded = tx.ljust(64, b'\x00')
    dev.write(padded)
    # 等设备处理 + 异步返回
    time.sleep(0.15)
    raw = dev.read(64, timeout_ms=wait_ms)
    if raw and len(raw) > 0:
        frame = raw[1:] if raw[0] == 0x02 else raw  # 剥 Report ID
        return frame
    return b""
