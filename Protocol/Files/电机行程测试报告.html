2测量方法

  • 通道：USB HID；单次 MOTOR_QUERY 事务约 90 ms，快于单腿（约 1.1~1.2 s）但慢于触点微时序。
  • 步数捕获：TIM4 硬件计数器（[App_Stepper_Tim4.c](Application/src/App_Stepper_Tim4.c#L148)）每腿复位；在一次往返内 stepsDone 序列呈"升-峰-回落-再升-峰"两个山峰，两个峰 = 上下两腿各自的长度（免竞争）。
  • 墙钟：MOTOR_TEST 接受 → 状态 DONE(2) 的耗时；3/10/12 轮重复求均值。
  • 运动学模型：根据固件 TIM4 S 曲线（[App_Stepper_Tim4.c:26](Application/src/App_Stepper_Tim4.c#L26)）精确重建，与实测交叉验证。

6行程不对称分析

现象：上腿 4085 步 vs 下腿 4324 步，差 239 步 ≈ 0.60 圈。

  • 上腿零抖动（stdev=0）：正程以触达机械止点 KEY_UP 为终点（[App_MotorTest.c:176](Application/src/App_MotorTest.c#L176)），并做 DC 磁制动硬停——止点位置确定，故每次一致。
  • 下腿有抖动（stdev=38）：下行程以触发 KEY_DOWN 为终点，受停驻回位、机械游隙影响，触发位置在小范围浮动。
  • 往返总步数（up+down）随下腿抖动在 4281~4373 之间两个稳定簇（~4285 与 ~4367），进一步印证双腿不对称而非单腿随机抖动。
工程启示：若需对称行程，上腿基准 4085 步（确定性）；下腿留 约 60 圈 裕量。涉及绝对位置/防越程的 MOVE 应以上腿止点为安全基准。

7结论

  • ✓ 上下行程已分别定量：上腿 4085 步/10.21 圈，下腿 4324 步/10.81 圈。
  • ✓ 单程均值 1.20 s，往返墙钟稳定 2.40 s，全程 0 故障（diag1/diag2=0）。
  • ✓ 固件 S 曲线运动学模型与实测交叉吻合（差 < 80ms）。
  • 注意：行程不对称（0.60 圈），标定/防越程保护须区分双腿处理。

若需真正的毫秒级触点时序（5ms 防抖、8ms 磁制动实测波形），需示波器接 KEY_UP/KEY_DOWN 与 STEP 引脚捕获——USB 查询通道无法分辨亚 10ms 事件。

8行程开关保护链与上电自检（追加实测 2026-08-29）

基于本报告腿长基准（上 4085 / 下 4324）落地的保护机制闭环验证 ｜ 固件 hex ZLR5401_202608291936.hex ｜ 覆盖场景：开关在位 / 开关拆除（开路）

8.1 上电两阶段自检（先上后下）设计

  • 阶段1 向上找 KEY_UP（静态已触发则免驱动）→ 阶段2 向下回归 KEY_DOWN 建立绝对基准（[App_MotorHoming.c](Application/src/App_MotorHoming.c)）。驱动参数刻意保护设备：2000 Hz、转矩 40%、每段步数上限 = 腿长实测×2+裕量（上 8970 / 下 9448）、30s 超时。
  • 运行中开关监控：奔向某端超过 腿长×1.15（上 4697 / 下 4973）仍未触发对应开关 → 判开关缺失，置错误位并停机（[App_Stepper.c:170-187](Application/src/App_Stepper.c#L170-L187)）。此监控不依赖位置计数起点，是"开关开路不可感知"（上拉输入，未接与坏断都读高）的唯一兜底。
  • 错误位：switchErr bit0=上缺失、bit1=下缺失；上=黄灯 500ms 闪、下=粉红（R+B）500ms 闪；TEST 被禁（防冲挡块），MOVE 开放给上位机自行决策。

8.3 上电起步瞬态（新发现硬件怪癖）

上电后首次电机驱动有 ~50% 概率在 0~21 步内被 DRV8434S 误停：FAULT_STATUS=0xC0（nFAULT + SPI_ERROR），无 OCP/STL/UVLO/CPUV/OL 等真实电气原因位。与电机位置、方向、负载无关；同一动作稍后执行完全正常。1.5s 上电延时无法消除（非电源稳定问题），疑似上电 USB 重新枚举窗口的电气耦合，根因未最终定位。

修复：起步瞬态判据重试（[App_MotorHoming.c:97-112](Application/src/App_MotorHoming.c#L97-L112)）——判据"走了 <50 步且 DRV 故障寄存器非零"（真实堵转会持续走步直到 TRQ/腿长监控停机、超步/超时各有计数耗尽，均不会长这样），满足则清故障重试一次。3/3 复位验证通过（含 2 次瞬态命中后重试走通）。

8.5 顺带修复的缺陷

  • MOVE 定步数完成不回 IDLE：TIM4 走满设定步数后自动停脉冲，但 App_Stepper_Process 未感知，状态永久停在 RUN（QUERY 上报 RUN、后续 TEST 判 BUSY）。已补 StepperTim4_IsRunning()==0 完成检测 → 断电回 IDLE（[App_Stepper.c:162-171](Application/src/App_Stepper.c#L162-L171)）。
  • MOVE 门控调整：MOVE 不再受行程自检门控，电机完全开放给上位机；switchErr 仅作报警/诊断。TEST 保留门控（防冲挡块）。
