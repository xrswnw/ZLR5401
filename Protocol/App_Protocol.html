App USB Protocol — Host API Reference

应用层通信协议 · 命令 / 帧格式 / 校验 / 子命令 · 完整 API 参考

协议版本：2  |  传输：USB HID Interrupt / 64B 包 / 16ms 轮询 / 报告 ID=0x02

响应规则：响应 func = 请求 func ^ 0xFF（如 0x01→0xFE、0x0A→0xF5、0x0D→0xF2）

1. 帧格式（所有命令通用）

┌──────┬──────┬─────┬─────┬─────────┬──────┬─────────┬─────────┐
│ 0x53 │ 0x77 │ ADDR│ 0x00│ length  │ func │ data    │ crc32   │
│  S   │  w   │ 1B  │RSV  │ LE16     │ 1B   │ N bytes  │ LE32    │
└──────┴──────┴─────┴─────┴─────────┴──────┴─────────┴─────────┘
  0    1    2     3    4     5   6    7..7+N  7+N+1..7+N+4
字段长度说明
header11B固定 0x53（ASCII 'S'）
header21B固定 0x77（ASCII 'w'）
devAddr1B目标设备地址；本机默认 0x01，广播 0xFF
reserved1B固定 0x00；非 0 静默丢弃（Round 018 起强制校验）
length2B LEpayload 字节数 = 1 + N + 4（func + data + CRC32）；范围 5..1029
func1B命令码（见 §3）
dataN命令参数或响应数据，N = length - 5
crc324B LE覆盖前面 N + 7 字节；CRC32 (MPEG-2, poly=0x04C11DB7, init=0xFFFFFFFF, 无反射, 无最终 XOR)
约束
  • 字序：多字节字段（小端 LE），length[lo,hi], crc32[b0,b1,b2,b3]。
  • 校验：CRC 不匹配、length 越界或 reserved≠0x00 → 设备静默丢弃，不响应。

2. USB HID 传输层

端点

EP方向类型包大小轮询
EP1IN（设备→主机）Interrupt64B16 ms
EP2OUT（主机→设备）Interrupt64B16 ms

HID 报告 ID

设备发送的 64B Interrupt Report 第一个字节固定为报告 ID 0x02。主机接收时先剥除这个字节，剩余 63B 才是协议层帧。

HID 描述符

报告描述符: Usage Page 0x8C (Vendor Defined), Collection Application
              Input + Output + Feature (各 64B 或 2B)
接口类    : HID (0x03)
子类/协议  : 0 / 0
单包帧大小限制

帧体 ≤ 63B（剥掉 Report ID）。即 data_len ≤ 63 - 7 = 56 字节的单包可承载。需要更大帧时必须实现 USB 分片协议（本工程不实现）。

3. 命令总览

App 实现 8 个命令。其余命令（FC=0x03/0x04/0x05/0x06/0x09）由 Bootloader 处理（详见 Boot_Protocol.html）。

命令总览 0x0C / 0x0D 为本轮新增（AM 解码器 / 开锁器）。灯控（LED 呼吸灯）无 USB 命令，由本地硬件 PWM（TIM3_CH1）自走，不对外暴露。

FC名称Host → DeviceDevice → Host用途
0x01FC_HANDSHAKE—28B: result/protoVer/status/UID/uidHash/layer/upgradeCount/baudRate发现/存活探测
0x02FC_ENTER_BOOT—1B: result预升级: 置 UPG 标志 + 延时 50ms + 自动软复位进 Boot
0x07FC_DEVICE_INFO—34B: result/addr/hwVersion/version (App层=swVersion)查询版本 / 设备地址
0x08FC_RESET—1B: result软件复位 (空参数, 回 OK 后延时 20ms 再复位)
0x09FC_EXIT_BOOT—1B: result退出升级 (Boot 处理); App 忽略
0x0AFC_MOTOR_CTRLdata 首字节为子命令码同步响应, 见 §10 (subCmd 0x01~0x06)步进电机 DRV8434S 控制
0x0BFC_UHF_CTRLdata 首字节为子命令码同步响应, 见 §11 (subCmd 0x01~0x0A)UHF 超高频 SIM7500 模块控制
0x0CFC_AM_CTRLdata 首字节为子命令码同步响应, 见 §12 (subCmd 0x01~0x05)AM 解码器控制
0x0DFC_LOCKER_CTRLdata 首字节为子命令码同步响应, 见 §13 (subCmd 0x01~0x07)开锁器业务编排
0x0EFC_RGB_CTRLdata 首字节为子命令码同步响应, 见 §14 (subCmd 0x01)RGB 三色灯 G=PA4/R=PA5/B=PA6 控制

响应帧的 func = 请求 func ^ 0xFF（例如 0x01 → 0xFE，0x0A → 0xF5）。

4. FC_HANDSHAKE (0x01)

请求

发送帧（data 为空）:
53 77 01 00 05 00 01  [CRC32 4B]
│                       │
header                   FC=0x01
length=5 (FC + CRC32)

响应 data（28 字节, App/Boot 一致）

偏移字段类型说明
0resultu80=RESULT_OK；其他=错误
1protoVeru8协议版本 = 2
2statusu8设备状态：0=IDLE / 1=RUN / 2=UPG / 3=FAULT
3UID12BSTM32 唯一 ID（96 位）
15uidHashu32 LECRC32(UID)
19layeru81=App（Boot 返回 0）
20upgradeCountu32 LE累计升级次数
24baudRateu32 LEUART 当前波特率

示例响应

53 77 01 00 21 00 FE [28B] [CRC32 4B]
            │       │   └─ func = 0x01 ^ 0xFF = 0xFE
            │       └─ length = 0x21 = 33 = 1(func) + 28(payload) + 4(CRC)

5. FC_ENTER_BOOT (0x02)

请求

53 77 01 00 05 00 02  [CRC32 4B]
                      └─ FC=0x02

响应 data（1 字节）

值含义
0RESULT_OK — 参数已保存，设备将软复位进入 Boot 升级模式
2ENTER_BOOT_PARAM_ERR — Flash 参数区写入失败
后续（预升级指令）

App 收到本命令后：写 deviceStatus = PARAM_STATUS_UPG (2) 到参数区（持久化），回 OK，延时 50ms（等 ACK 经 USB 1ms 帧周期完整推送 + 主机拉走），然后 NVIC_SystemReset() 自动软复位 → Bootloader 接管。Boot 看到 status=UPG 后 stayInUpdate=true，不超时，停留等待升级。

退出 Boot（不升级）

若进 Boot 后决定不升级，主机发 FC_EXIT_BOOT (0x09)（由 Boot 处理）：Boot 校验 App flash 完好后清 deviceStatus=RUN + 复位跳 App。详见 Boot_Protocol.html。

6. FC_DEVICE_INFO (0x07)

请求

53 77 01 00 05 00 07  [CRC32 4B]
                      └─ FC=0x07

响应 data（34 字节, App 层）

偏移字段长度说明
0result1B0=OK
1addr1B设备地址（默认 0x01）
2hwVersion16B硬件版本字符串
18version16BApp 层固件版本（swVersion）

Boot 层响应格式相同，但 version 字段内容为 bootVersion。

7. FC_RESET (0x08)

请求

53 77 01 00 05 00 08  [CRC32 4B]
                      └─ FC=0x08 (data 必须为空)

响应 data（1 字节）

值含义
0RESULT_OK — 已调度复位，延时 20ms 后 NVIC_SystemReset
1RESET_PARAM_ERR — data 非空（必须为空参数）
时序

回 OK 后延时 20ms（让 USB 1ms 帧周期完整推送 ACK + 主机拉走）再 NVIC_SystemReset()，否则 ACK 可能随复位丢失。主机收到 OK 后应等待设备重新枚举。

9. 主机接入样板

9.1 打开设备

// hidapi
handle = hid_open(0x5377, 0x5378, NULL);
// 报告 ID = 0x02, 包长 64
unsigned char report[64];             // 读写都先放 64B 缓冲

9.2 发请求

// 例: FC_HANDSHAKE
uint8_t frame[12];
frame[0] = 0x53; frame[1] = 0x77;            // header "Sw"
frame[2] = 0x01;                              // devAddr
frame[3] = 0x00;                              // reserved (必须 0x00)
frame[4] = 5; frame[5] = 0;                   // length LE
frame[6] = 0x01;                              // FC_HANDSHAKE
// frame[7..10] = CRC32 覆盖前 7B
uint32_t crc = crc32_mpeg2(frame, 7);         // MPEG-2, 无反射, 无最终 XOR
memcpy(frame + 7, &crc, 4);                   // CRC32 LE
hid_write(handle, frame, 12);

9.3 收响应

int n = hid_read(handle, report, 64);
if (n >= 64 && report[0] == 0x02) {
    // 报告 ID 剥除后, 剩余 63B 是协议帧
    parse_frame(report + 1, n - 1, handle);
    // response func = request func ^ 0xFF
}

10. FC_MOTOR_CTRL (0x0A) — 步进电机 DRV8434S 控制

本命令把步进电机（TI DRV8434S 双极步进驱动）暴露给上位机。data 区首字节为子命令码 cmd（0x01~0x06），其后为参数。所有响应同步返回：data[0]=cmd，data[1]=err（0=OK），其余随命令。通信接口自选：SPI3（SCK=PB3 / MISO=PB4 / MOSI=PB5），片选 NSCS=PD2（手动 GPIO，帧间高电平≥500ns），STEP=PB6 / DIR=PB7 / nSLEEP=PB8 / ENABLE=PB9。步进走 GPIO STEP/DIR（SPI 仅用于寄存器配置，非 SPI 步进）。

10.1 子命令总览

cmd名称Host → Device (data)Device → Host (data)说明
0x01MOVE[cmd, dir, stepsL, stepsM, stepsH][cmd, err]启动运动: dir=0(CW)/1(CCW), steps=24bit 微步数, 0=持续运行
0x02STOP[cmd][cmd, err]停止并关断输出
0x03SPEED[cmd, hzL, hzH][cmd, err]设定微步/秒 (1~2000)
0x04TORQUE[cmd, pct][cmd, err]转矩百分比 (6~100)
0x05QUERY[cmd][cmd, err, state, fault, diag1, diag2, stepsDoneL, stepsDoneH]查询状态/故障/已走微步数
0x06CLEAR[cmd][cmd, err]清除故障并回到 IDLE

10.2 QUERY 响应字段

字段说明
err0=OK
state0=IDLE(停止) / 1=RUN / 2=FAULT
faultDRV8434S FAULT 寄存器原始值 (bit7=FAULT, bit5=UVLO, bit4=CPUV, bit3=OCP, bit2=STALL, bit1=过温)
diag1诊断寄存器1 (OCP 位置)
diag2诊断寄存器2 (OTW/OTS/STALL/OL)
stepsDone本次运动已完成的微步数 (16bit, 溢出截断; 持续运行意会)
错误码 (data[1])
0=OK, 1=参数错误, 2=器件处于故障状态。

11. FC_UHF_CTRL (0x0B) — UHF 超高频 SIM7500 模块控制

本命令把超高频（UHF）RFID 读写模块 SIM7500（芯联创展 / Silion，基于 Impinj E710 平台，EPC Class 1 Gen2 / ISO 18000-6C）暴露给上位机。data 区首字节为子命令码 cmd（0x01~0x0C），其后为参数。所有响应同步返回：data[0]=cmd，data[1]=err（0=OK），其余随命令。通信经 UART4（PC10=TX / PC11=RX，115200-8-N-1，TTL）的 EX10 通用 0xFF 帧（FF + len + cmd + data + CRC16）。模块控制引脚：UHF_EN=PB12（高电平上电）、UHF_REG_OUT2=PB13 / UHF_REG_IN1=PB14 / UHF_REG_IN2=PB15、UHF_NRST=PC6、UHF_OUT1=PC7。板上无 MCU 天线切换脚（SIM7500 天线选择经模块命令）。

控制面 / 数据面解耦：状态机（IDLE/READY/INVENTORY/READ/WRITE/ERROR/ANT_CHECK）由设备内部管理。开放/设置时下发功率、频段、Gen2(Session/Target/Q)；OPEN 时同步执行回波检测判断天线连接。盘点/读写标签结果缓存在设备标签缓冲，主机经 GET_TAGS 取走。

0x01OPEN[cmd][cmd, err]上电 + 下发配置 + 回波检测，进入 READY（告警仍可用）

0x05WRITE_TAG[cmd, epcLen, epc.., bank, addr, len, data..][cmd, err]写标签：按 EPC 定位，写 len 字节到 bank/addr
0x06STOP[cmd][cmd, err]停止当前操作
0x07QUERY[cmd][cmd, err, state, link, totalTags]查询状态/链路/累计标签数
0x08GET_CONFIG[cmd][cmd, err, power, ant, checksum, session, target, q, band]读取当前配置

12. FC_AM_CTRL (0x0C) — AM 解码器控制

本命令把 AM 解码器（复用表 / 电能 / 计量读表模块）暴露给上位机。data 区首字节为子命令码 cmd（0x01~0x05），其后为参数。硬件经 USART1（RS485，经 SP3485 收发，PA9=TX / PA10=RX，方向控制 PA8，0x2A 0xA2 帧族）与解码器通信。所有响应同步返回：data[0]=cmd，data[1]=err（0=OK），其余随命令。16 位参数值高字节在后：(H<<8)|L。

0x02SET_CONFIG[cmd, thrH,thrL, hitH,hitL, freq, delayH,delayL, len, invert, syncH,syncL, volt, mode][cmd, err]设置配置并持久化
0x03GET_PARAM[cmd, amCmd][cmd, err, amCmd, valH,valL]读单个参数（amCmd 为 AM 命令字）
0x04SET_PARAM[cmd, amCmd, valH,valL][cmd, err]写单个参数
0x05QUERY[cmd][cmd, err, link]总查询，探测链路（link=0 正常）
配置字段 (SET_CONFIG / GET_CONFIG)
字段范围说明

13. FC_LOCKER_CTRL (0x0D) — 开锁器业务编排

本命令把开锁器（硬标签 UHF 开锁 + 软标计数）业务编排状态机暴露给上位机。data 区首字节为子命令码 cmd（0x01~0x07），其后为参数。所有响应同步返回：data[0]=cmd，data[1]=err（0=OK），其余随命令。一帧装不下的多枚硬标签，可先 ADD 逐条追加再 START。

0x01CONFIGURE[cmd, hardCntL,hardCntH, softCntL,softCntH][cmd, err]清空清单、置软标数 N（v1 精简；hardCnt 仅用于预检上限，不写入）
0x02ADD[cmd, epcLen, epc..][cmd, err]追加一条硬标签 EPC（≤12B）
0x03START[cmd][cmd, err]上电 UHF + 开扫，进入可开锁
0x04CANCEL[cmd][cmd, err]取消当前任务，磁块回降、回 IDLE
0x05QUERY[cmd][cmd, err, state, hmL,hmH, scL,scH, suL,suH]查询状态/计数
0x06CONSUME_SOFT[cmd][cmd, err]v1 软标：上位机上报已解码一次
0x07GET_EVENT[cmd][cmd, err, code, epcLen, epc.., hmL,hmH, suL,suH, scL,scH, hcL,hcH]取一条上报事件
QUERY 字段
state：0=IDLE 空闲 / 1=CONFIGURED 已配清单等放硬标 / 2=UNLOCK_HOLD 硬标匹配磁块升起 / 3=SOFT_DECODE 硬标全解进入软标 / 4=DONE 完成 / 5=FAULT 故障。hm=已解锁硬标数 n，sc=软标总数 N，su=已消耗软标数。
事件码 (GET_EVENT code)
0=MATCH_OK 硬标匹配(亮绿升锁) / 1=MISMATCH 非清单EPC(红灯闪不升) / 2=HARD_DONE 硬标全解进软标 / 3=SOFT_USED 消耗一次软标 / 4=TIMEOUT 开锁保持超时 / 5=DONE 结账完成 / 6=FAULT 故障。无待取事件时 err=3 (NO_EVENT)。
错误码 (data[1])
0=OK, 1=忙（非空闲需先取消）, 2=参数非法/超上限, 3=无待取事件。

14. FC_RGB_CTRL (0x0E) — RGB 三色灯控制

控制板载 RGB 三色灯：G=PA4、R=PA5、B=PA6（高电平点亮）。data 区首字节为子命令码 cmd（0x01），其后为参数。响应同步返回：data[0]=cmd，data[1]=err（0=OK），并回显 mask。

cmd名称Host → Device (data)Device → Host (data)说明
0x01SET[cmd, mask, reserved][cmd, err, mask]按位掩码设置三色：mask bit0=G 绿 / bit1=R 红 / bit2=B 蓝，其余位与 reserved 预留（忽略）
颜色掩码示例
0x00=全灭 · 0x01=绿 · 0x02=红 · 0x04=蓝 · 0x03=黄(G+R) · 0x05=青(G+B) · 0x06=紫(R+B) · 0x07=白(G+R+B)。
错误码 (data[1])
0=OK, 1=参数非法/长度不足。
