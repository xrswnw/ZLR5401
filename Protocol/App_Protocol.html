App USB Protocol — Host API Reference

应用层通信协议 · 命令 / 帧格式 / 校验 / 子命令 · 完整 API 参考

协议版本：2  |  传输：USB HID Interrupt / 64B 包 / 16ms 轮询 / 报告 ID=0x02

响应规则：响应 func = 请求 func ^ 0xFF（如 0x01→0xFE、0x0A→0xF5、0x0D→0xF2）

1. 帧格式（所有命令通用）

┌──────┬──────┬─────┬─────┬─────────┬──────┬─────────┬─────────┐
│ 0x53 │ 0x77 │ ADDR│ 0x00│ length  │ func │ data    │ crc32   │
│  S   │  w   │ 1B  │RSV  │ LE16     │ 1B   │ N bytes  │ LE32    │
└──────┴──────┴─────┴─────┴─────────┴──────┴─────────┴─────────┘
  0    1    2     3    4     5   6    7..7+N  7+N+1..7+N+4
字段长度说明
header11B固定 0x53（ASCII 'S'）
header21B固定 0x77（ASCII 'w'）
devAddr1B目标设备地址；本机默认 0x01，广播 0xFF
reserved1B固定 0x00；非 0 静默丢弃（Round 018 起强制校验）
length2B LEpayload 字节数 = 1 + N + 4（func + data + CRC32）；范围 5..1029
func1B命令码（见 §3）
dataN命令参数或响应数据，N = length - 5
crc324B LE覆盖前面 N + 7 字节；CRC32 (MPEG-2, poly=0x04C11DB7, init=0xFFFFFFFF, 无反射, 无最终 XOR)
约束
  • 字序：多字节字段（小端 LE），length[lo,hi], crc32[b0,b1,b2,b3]。
  • 校验：CRC 不匹配、length 越界或 reserved≠0x00 → 设备静默丢弃，不响应。

2. USB HID 传输层

端点

HID 报告 ID

设备发送的 64B Interrupt Report 第一个字节固定为报告 ID 0x02。主机接收时先剥除这个字节，剩余 63B 才是协议层帧。

HID 描述符

报告描述符: Usage Page 0x8C (Vendor Defined), Collection Application
              Input + Output + Feature (各 64B 或 2B)
接口类    : HID (0x03)
子类/协议  : 0 / 0
单包帧大小限制

帧体 ≤ 63B（剥掉 Report ID）。即 data_len ≤ 63 - 7 = 56 字节的单包可承载。需要更大帧时必须实现 USB 分片协议（本工程不实现）。

5. FC_ENTER_BOOT (0x02)

请求

53 77 01 00 05 00 02  [CRC32 4B]
                      └─ FC=0x02

响应 data（1 字节）

值含义
0RESULT_OK — 参数已保存，设备将软复位进入 Boot 升级模式
2ENTER_BOOT_PARAM_ERR — Flash 参数区写入失败
后续（预升级指令）

App 收到本命令后：写 deviceStatus = PARAM_STATUS_UPG (2) 到参数区（持久化），回 OK，延时 50ms（等 ACK 经 USB 1ms 帧周期完整推送 + 主机拉走），然后 NVIC_SystemReset() 自动软复位 → Bootloader 接管。Boot 看到 status=UPG 后 stayInUpdate=true，不超时，停留等待升级。

退出 Boot（不升级）

若进 Boot 后决定不升级，主机发 FC_EXIT_BOOT (0x09)（由 Boot 处理）：Boot 校验 App flash 完好后清 deviceStatus=RUN + 复位跳 App。详见 Boot_Protocol.html。

7. FC_RESET (0x08)

请求

53 77 01 00 05 00 08  [CRC32 4B]
                      └─ FC=0x08 (data 必须为空)

响应 data（1 字节）

值含义
0RESULT_OK — 已调度复位，延时 20ms 后 NVIC_SystemReset
1RESET_PARAM_ERR — data 非空（必须为空参数）
时序

回 OK 后延时 20ms（让 USB 1ms 帧周期完整推送 ACK + 主机拉走）再 NVIC_SystemReset()，否则 ACK 可能随复位丢失。主机收到 OK 后应等待设备重新枚举。

9. 主机接入样板

9.1 打开设备

// hidapi
handle = hid_open(0x5377, 0x5378, NULL);
// 报告 ID = 0x02, 包长 64
unsigned char report[64];             // 读写都先放 64B 缓冲

9.2 发请求

// 例: FC_HANDSHAKE
uint8_t frame[12];
frame[0] = 0x53; frame[1] = 0x77;            // header "Sw"
frame[2] = 0x01;                              // devAddr
frame[3] = 0x00;                              // reserved (必须 0x00)
frame[4] = 5; frame[5] = 0;                   // length LE
frame[6] = 0x01;                              // FC_HANDSHAKE
// frame[7..10] = CRC32 覆盖前 7B
uint32_t crc = crc32_mpeg2(frame, 7);         // MPEG-2, 无反射, 无最终 XOR
memcpy(frame + 7, &crc, 4);                   // CRC32 LE
hid_write(handle, frame, 12);

9.3 收响应

int n = hid_read(handle, report, 64);
if (n >= 64 && report[0] == 0x02) {
    // 报告 ID 剥除后, 剩余 63B 是协议帧
    parse_frame(report + 1, n - 1, handle);
    // response func = request func ^ 0xFF
}

10. FC_MOTOR_CTRL (0x0A) — 步进电机升降机构控制

本命令控制步进电机升降机构。data 区首字节为子命令码 cmd（0x01~0x06），其后为参数。所有响应同步返回：data[0]=cmd，data[1]=err（0=OK），其余随命令。

10.2 QUERY 响应字段

字段说明

错误码 (data[1])
0=OK, 1=参数错误, 2=器件处于故障状态, 3=忙(TEST 进行中)。
上电行程自检/回零 (无条件完整自检: 先上后下)
上电时电机位置未知; 开全局中断后无论电机停在何处(含已压行程开关), 均执行两阶段自检:
  • 阶段1 向上找 KEY_UP: 验证上行程开关在位/可达 (静态已触发则免驱动)。
  • 阶段2 向下回归 KEY_DOWN: 验证下行程开关并建立下行程绝对基准。
  • 两阶段均通过 → 回零完成（蜂鸣提示已不在回零处）。成功蜂鸣移至 POST 末尾统一判据：电机自检(SPI 回读/器件故障/行程开关) 与 UHF 通信全部通过才蜂鸣 1s；任一失败静默，由错误灯语表达（AM 通信/参数 CRC 不参与蜂鸣判据，仅记错误位）。
  • 任一阶段失败(超腿长未触发 / 堵转撞硬挡被 TRQ 停机 / 超步 / 超时) → 置 switchErr 对应位并立即返回(不继续后续阶段), 此时 TEST 回 MOTOR_ERR_FAULT(防冲挡块), 对应错误灯闪, 无蜂鸣。MOVE 不受此门控(开放给上位机), 但运行中开关监控会在超腿长未触发时置位并停机。CLEAR 清错误位。
自检驱动优先保护设备: 低转速(2000Hz)低转矩(40%) + 每段最大步数上限(腿长实测×2+裕量: 上 8970 / 下 9448 微步) + 30s 超时; 堵转由 TRQ 监测(~600ms 降速 + ~2.4s 停机)兜底。上电后首次驱动存在间歇性瞬态(被电机驱动瞬态故障误停, 与位置/负载无关), 每阶段起步若在 <50 步内因 DRV 故障停机则自动清故障重试一次。
运行中开关监控 + 灯色指示 (新增)
  • 正向(奔上)超过上腿限制 LEG_UP_LIMIT 未触上开关 → 置 switchErr.bit0; 反向(奔下)超下腿限制未触下开关 → 置 bit1.
  • 灯色(500ms 闪烁): 上行程错=黄, 下行程错=粉红.

11. FC_UHF_CTRL (0x0B) — UHF 超高频读写模块控制

本命令控制超高频（UHF）RFID 读写模块（EPC Class 1 Gen2 / ISO 18000-6C）。data 区首字节为子命令码 cmd（0x01~0x0C），其后为参数。所有响应同步返回：data[0]=cmd，data[1]=err（0=OK），其余随命令。

控制面 / 数据面解耦：状态机（IDLE/READY/INVENTORY/READ/WRITE/ERROR/ANT_CHECK/GETBUF）由设备内部管理。开放/设置时下发功率、频段、Gen2(Session/Target/Q)；OPEN 时同步执行回波检测判断天线连接。INVENTORY 为多标签同步盘存（0x22，带内部超时）→ 0x29 取回缓存，设备内部同步阻塞完成整段流程后，把全部标签内联在响应里直接带回——上位机一次请求即可拿到场内所有标签，无需分步拉取、无主动上报。

11.4 盘点错误码与同步语义

INVENTORY 为同步阻塞：设备在单请求内完成 0x22 多标签盘存（超时 timeout，缺省 1000ms）→ 0x29 取回缓冲 → 解码(EPC 长度取自 PC 高 5 位 (pc>>11)*2) → 把全部标签内联在响应里不规则带回。无主动上报。err 取值：

err含义
0OK，紧随其后 count L,H + 每条 [rssi, epcLen, epc..]（rssi 0~255，epcLen 6~16）
1 PARAM参数非法
2 BUSY设备忙（其它操作进行中），需稍后重试
3 NOT_READY未 OPEN / 已下电
4 LINKUHF 模块链路异常
5 NO_TAG场内无标签（0x22 返回 0）
6 TIMEOUT盘存超时
SCAN_START 为自动扫描 / 识别测距：设备持续连续盘点，每轮复用 INVENTORY 的 0x22→0x29 流程，标签连同 rssi 持续写入数据面缓冲。设备不主动上报——主机按需用 GET_TAGS 拉取取走（每次拉完缓冲即清空），据此判断标签是否在识别范围内或测距。cycle 既作每轮 0x22 盘存超时也作轮询间隔。识别到标签即蜂鸣 50ms 提示（非阻塞，到期自动停；靠近则每轮 beep，远离不响，用于测距判定）。扫描中发起单次 INVENTORY 会返回 BUSY；先 SCAN_STOP 再单次盘点。
扫描中可打断改配置：自动扫描中的 SET_CONFIG（如改功率）不立即下发（避免打断 0x22→0x29 时序），而是返回 OK 挂起；由设备在本轮盘点结束回 READY 后、下一轮盘点前插入下发配置，下发完成即继续自动盘点。故主机收到 SET_CONFIG 的同步 OK 即表示已接受，实际下发在下轮盘点前生效。也可 SCAN_STOP 后改配置（停扫时也会补发挂起配置）。

12. FC_AM_CTRL (0x0C) — AM 消磁器控制

本命令控制 AM EAS 消磁器（Deactivator）。data 区首字节为子命令码 cmd（0x01~0x09），其后为参数。16 位参数值高字节在后：(H<<8)|L。

设备语义（实测）：这是 消磁器（检测标签→消磁/报警），不读标签唯一 ID。读回全部参数走总查询 0x63（真读回存储值，非回显）；逐参数命令单独发仍是回显。cmd17 是设备主动上报的消磁结果：2A A2 17 01 01 07 5B0 5B1 5B2 5B3 5B4 00 00 校验。5B 字段 FF FF FF FF FF = 消磁失败（标签无法消磁，持续连发重试上报）；单帧/非 FF 字段 = 消磁成功（仅一帧后停）。GET_STATUS 据此分类：≥3 帧连发 FF×5 判失败、单帧/静默判成功、静默 >300ms 复位空闲。

13.1 0x08 单标签流程（Round_011 已废除）

0x08 子命令不再解析任何帧形状，收到一律回 [cmd, 2] (PARAM)。单标签场景统一改用 0x0A UNLOCK_MULTI：epcCnt=1 即单标，解锁窗 W=120000ms 恰为 2min。废除动机：单标/多标两条通道共享同一光电门控与"命中即升起"逻辑，语义重复且双通道互斥检查徒增状态机分支面；0x08 独有的"保持期 3s 稳定即结账成功"判据与 0x0A 的"逐张确认 + n==m 结束"业务语义不一致，易产生结账误判。保留 0x08 码位显式回 PARAM（区别于未知子命令），便于上位机探测协议升级。

13.2 UNLOCK_MULTI (0x0A) 同步解锁流程（唯一开锁通道）

业务闭环（上位机视角，单标/多标同一流程）：

1. 客户付款
2. 上位机把结账清单 (m 张硬标 EPC + 软标数 softCnt) 单帧下发给开锁器
3. 客户把标签放到开锁器上, 光电 (PC4) 触发
4. 持续比对: 清单内 EPC 稳定确认 -> 绿灯升起开锁 (逐张推 0x0B 回传);
   清单外 EPC 独占 -> 红闪不升起 (推 0x0C 回传, 不终止流程)
5. 硬标段预算 W = 2min + 30s/额外标签 (m=1 即单标 2min);
   全部确认 (n==m) 硬标段立即结束进入软标段 (W 是预留上限, 非最短等待)
6. 软标段: 每个软标对应一次解码 (AM), 每次推 0x0E;
   次数用完 (或软标窗 5min 满, 以实况结账) -> 结账完成回 0x0A 终帧

请求：[cmd, tmoL,tmoH, holdL,holdH, softCnt, epcCnt, epcLen, epcCnt*epcLen 字节] — tmoMs 每轮盘点时限（0→1000，上限 10000）；holdMs=0 时解锁窗 W 由公式计算，非零取 min(上位机值, 240000)；softCnt 软标消磁数（0=跳过软标段）；epcCnt 期望标签数 m（1~4，1 即单标流程）；epcLen 1~12。

解锁窗 W：holdMs=0 → 120000 + (m-1)*30000 ms（首标签 2min，每多一标签加 30s），绝对上限 240000ms；非零时取 min(上位机值, 上限)。W 自光电触发时刻起算，兼任光电等待窗与校对预算。

流程（固件 App_LockerUnlock.c）：

⑴ 前置检查 (Locker/UHF/电机空闲 + 已回零) -> 推 0x0F 受理帧 (含实际 W)
⑵ 光电门控: 等放标 (PC4, 200ms 去抖), 窗=W; 窗满 -> err=11 NO_IR
⑶ 消磁准备 (softCnt>0: AM 探链 + 强制检测模式 — 校验期仅检测
    不消磁; =0 跳过)
⑷ UHF 上电/配置 + 连续盘点
⑸ 持续校对: 每标签独立状态机 PENDING/TRACKING/CONFIRMED
    确认判据双门限: 在场连续 3s 且累计读到 >=2 次 (单轮 ~1/4 漏读,
    禁"连续N轮"式判据); 离场超 3s 回 PENDING 重累计
    CONFIRMED 单向掩码: 后续读到静默忽略 (不重报不计数)
    首张确认即升起 KEY_UP (保持至硬标段结束)
    每确认一张: 推 0x0B 确认帧 + 蜂鸣 200ms + RGB 绿单闪
    外来 EPC 不升不计数; 连续 3 轮外来独占且无清单标签 -> 推 0x0C 失配帧
    + 红闪 3s, 不终止 (窗 W 兜底; 再见到清单标签后重新武装)
⑹ 硬标段结束 (n==m ALL_OK / 窗 W 满 PARTIAL / CANCEL / UHF 失联 5s):
    推 0x0D 硬标完成帧 -> 回降 KEY_DOWN (免疫打断)
⑺ 软标解码 (softCnt>0): 入口才切 AM 消磁模式 (EPC 校验已
    通过), 消磁计数每+1 推 0x0E; 达标或 5min 软标窗满 (以实况结账),
    出口切回检测模式 (不再消磁)
⑻ 流程结束回 0x0A 终帧 (13.3): 全部结账完成时长鸣 300ms + 绿三连闪

解锁态响应矩阵：受理帧（0x0F）起至终帧发完，仅 CANCEL / QUERY / GET_PROGRESS（及各 FC 只读命令）被放行，其余 LOCKER 子命令与 MOTOR/UHF/AM 控制类一律回 BUSY。

14. FC_RGB_CTRL (0x0E) — RGB 三色灯控制

控制板载 RGB 三色指示灯（绿/红/蓝三通道）。data 区首字节为子命令码 cmd（0x01），其后为参数。响应同步返回：data[0]=cmd，data[1]=err（0=OK），并回显 mask。

cmd名称Host → Device (data)Device → Host (data)说明

错误码 (data[1])

15. FC_SELFTEST_CTRL (0x0F) — 设备级自检/锁存错误位

设备级健康监控：上电 POST 逐个探测外设（步进电机 / UHF / AM 消磁器），结果沉淀为 16bit 锁存错误位图 errBits；运行期故障（开锁器 UHF 链路故障、未回零）与参数区 CRC 失败亦联动置位。data 区首字节为子命令码 cmd。响应同步返回：data[0]=cmd，data[1]=err（0=OK）。App 专属命令（Bootloader 收到 0x0F 忽略）。

15.1 错误位定义 (errBits, 16bit LE)

bit宏含义置位来源
bit0SELF_ERR_MOTOR_SPI电机驱动配置回读不一致（通信/落配置失败）POST / RERUN 探测
bit1SELF_ERR_MOTOR_FAULT电机驱动器件故障（FAULT 位）POST / RERUN 探测
bit2SELF_ERR_UHF_COMMUHF Open/Query 通信失败POST / RERUN 探测；运行期开锁器 UHF 链路故障
bit3SELF_ERR_AM_COMMAM 消磁器 Query 通信失败POST / RERUN 探测
bit4SELF_ERR_PARAM_CRC参数区 CRC 失败回落默认值仅上电置位（不随探测刷新，只能 CLEAR 手动清）
bit5SELF_ERR_TRAVEL_SW行程开关缺失/回零失败（明细见 QUERY 响应 switchErr：bit0=上 bit1=下）POST / RERUN 探测；运行期开锁器"未回零"故障
bit6~15—预留（恒 0）—

刷新语义：bit0~3、bit5 随 RERUN 探测结果整体刷新（故障已消除则自动清位）；bit4 为引导期事实，仅 CLEAR 可清。

15.2 子命令

cmd名称Host → Device (data)Device → Host (data)说明
0x01QUERY[cmd][cmd, err, errBitsL, errBitsH, motorCommOk, drvFault, uhfLink, amLink, paramCrc, switchErr]读锁存错误位 + 实时诊断快照（无阻塞），字段见 15.3
0x02RERUN[cmd][cmd, err, errBitsL, errBitsH]重探外设并刷新锁存位：阻塞约 3s（UHF 上电+回帧、AM 回帧超时），期间喂狗不复位。仅 Locker/Unlock 空闲时接受，否则回 err=2 BUSY
0x03CLEAR[cmd, maskL, maskH][cmd, err, errBitsL, errBitsH]按掩码清指定位（mask 与 15.1 bit 定义一致，可多选），响应回清位后的剩余位图

15.3 QUERY 响应字段

字段含义
errBitsL / errBitsH锁存错误位图（低/高字节，bit 定义见 15.1）
motorCommOk1 = 电机驱动配置回读一致（查询时实时复核寄存器）
drvFault电机驱动实时故障寄存器（0=无故障）
uhfLinkUHF 实时链路：0=正常 / 1=超时 / 2=CRC 错误
amLinkAM 实时链路：0=正常 / 非0=掉线
paramCrc1 = 本次上电参数区曾 CRC 失败回落默认值（= errBits bit4 的镜像）
switchErr行程开关实时错误位：bit0=上行程错 / bit1=下行程错（同 FC_MOTOR_CTRL QUERY 的 switchErr 字段）
与既有错误通道的关系
FC_MOTOR_CTRL QUERY/HEALTH 已提供电机细粒度诊断（switchErr、堵转、统计），FC_UHF/AM CTRL QUERY 提供各自链路状态；本命令把它们汇总为设备级一键健康位图，供上位机在发现设备（HANDSHAKE 后）或巡检时快速判断"哪里坏了"，无需逐个外设轮询。锁存位保证 POST 期/历史瞬时故障不丢失。
错误码 (data[1])
0=OK, 1=参数错误（长度不足/未知子命令）, 2=BUSY（RERUN 时开锁流程运行中）。
