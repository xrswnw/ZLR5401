App USB Protocol — Host API Reference

应用层通信协议 · 命令 / 帧格式 / 校验 / 子命令 · 完整 API 参考

协议版本：3  |  传输：USB HID Interrupt / 64B 包 / 16ms 轮询 / 报告 ID=0x02

响应规则：响应 func = 请求 func ^ 0xFF（如 0x01→0xFE、0x20→0xDF、0x23→0xDC）

1. 帧格式（所有命令通用）

┌──────┬──────┬─────┬─────┬─────────┬──────┬─────────┬─────────┐
│ 0x53 │ 0x77 │ ADDR│ 0x00│ length  │ func │ data    │ crc32   │
│  S   │  w   │ 1B  │RSV  │ LE16     │ 1B   │ N bytes  │ LE32    │
└──────┴──────┴─────┴─────┴─────────┴──────┴─────────┴─────────┘
  0    1    2     3    4     5   6    7..7+N  7+N+1..7+N+4
字段长度说明
header11B固定 0x53（ASCII 'S'）
header21B固定 0x77（ASCII 'w'）
devAddr1B目标设备地址；本机默认 0x01，广播 0xFF
reserved1B固定 0x00；非 0 静默丢弃
length2B LEpayload 字节数 = 1 + N + 4（func + data + CRC32）；范围 5..1029
func1B命令码（见 §3）
dataN命令参数或响应数据，N = length - 5
crc324B LE覆盖前面 N + 7 字节；CRC32 (MPEG-2, poly=0x04C11DB7, init=0xFFFFFFFF, 无反射, 无最终 XOR)，详见 §18
约束
  • 字序：多字节字段（小端 LE），length[lo,hi], crc32[b0,b1,b2,b3]。
  • 校验：CRC 不匹配、length 越界或 reserved≠0x00 → 设备静默丢弃，不响应。

2. USB HID 传输层

端点

EP方向类型包大小轮询
EP1IN（设备→主机）Interrupt64B16 ms
EP2OUT（主机→设备）Interrupt64B16 ms

HID 报告 ID

设备发送的 64B Interrupt Report 第一个字节固定为报告 ID 0x02。主机接收时先剥除这个字节，剩余 63B 才是协议层帧。

HID 描述符

报告描述符: Usage Page 0x8C (Vendor Defined), Collection Application
              Input + Output + Feature (各 64B 或 2B)
接口类    : HID (0x03)
子类/协议  : 0 / 0
单包帧大小限制

帧体 ≤ 63B（剥掉 Report ID）。即 data_len ≤ 63 - 7 = 56 字节的单包可承载。

5. FC_ENTER_BOOT (0x02)

请求

53 77 01 00 05 00 02  [CRC32 4B]
                      └─ FC=0x02

响应 data（1 字节）

值含义
0RESULT_OK — 已置升级标志，设备将自动软复位进入 Boot 升级模式
2ENTER_BOOT_PARAM_ERR — 置升级标志失败

预升级：设备置升级标志后自动软复位进 Boot（Boot 停留等待升级，不超时）。进 Boot 后不升级时由主机发 FC_EXIT_BOOT (0x09) 退出。

9. 主机接入样板

9.1 打开设备

// hidapi
handle = hid_open(0x5377, 0x5378, NULL);
// 报告 ID = 0x02, 包长 64
unsigned char report[64];             // 读写都先放 64B 缓冲

9.2 发请求

// 例: FC_HANDSHAKE
uint8_t frame[12];
frame[0] = 0x53; frame[1] = 0x77;            // header "Sw"
frame[2] = 0x01;                              // devAddr
frame[3] = 0x00;                              // reserved (必须 0x00)
frame[4] = 5; frame[5] = 0;                   // length LE
frame[6] = 0x01;                              // FC_HANDSHAKE
// frame[7..10] = CRC32 覆盖前 7B
uint32_t crc = crc32_mpeg2(frame, 7);         // MPEG-2, 无反射, 无最终 XOR (见 §18)
memcpy(frame + 7, &crc, 4);                   // CRC32 LE
hid_write(handle, frame, 12);

9.3 收响应

int n = hid_read(handle, report, 64);
if (n >= 64 && report[0] == 0x02) {
    // 报告 ID 剥除后, 剩余 63B 是协议帧
    parse_frame(report + 1, n - 1, handle);
    // response func = request func ^ 0xFF
}

10. FC_MOTOR_CTRL (0x20) — 步进电机升降机构控制

本命令控制步进电机升降机构。data 区首字节为子命令码 cmd（0x01~0x09），其后为参数。所有响应同步返回：data[0]=cmd，data[1]=err（0=OK），其余随命令。

10.1 子命令总览

cmd名称Host → Device (data)Device → Host (data)说明
0x01MOVE[cmd, dir, stepsL, stepsM, stepsH][cmd, err]启动运动: dir=0(CW)/1(CCW), steps=24bit 微步数 (0=持续运行), 走满自动停脉冲回 IDLE. MOVE 不受行程自检门控 (开放给上位机, switchErr 仅作报警诊断). 互斥: 在途 (MOVE 运行中/行程测试中/后台回零中) 再下发一律回 err=3 BUSY, 不替换在途运动 — 改目标先 STOP. 复位后 ~12s 后台回零窗口内回 BUSY
0x02STOP[cmd][cmd, err]停止并关断输出
0x03SPEED[cmd, hzL, hzH][cmd, err]设定微步/秒 (1~2000)
0x04TORQUE[cmd, pct][cmd, err]转矩百分比 (6~100)
0x05QUERY[cmd][cmd, err, state, fault, diag1, diag2, stepsDoneL, stepsDoneH, switchErr, testState]查询状态/故障/已走微步数/行程开关错误位/行程测试态
0x06CLEAR[cmd][cmd, err]清除故障并回到 IDLE
0x07TEST[cmd, passes][cmd, err]行程测试: 正转触碰行程开关→立即反转→触碰 = 1 次往返, 共 passes 次后自动停转, 单程超时 10s. 进行中再下发 (含 MOVE/TEST) 回 MOTOR_ERR_BUSY; 回零未成功回 MOTOR_ERR_FAULT; 后台回零中回 BUSY. 结果经 QUERY 的 testState(2=DONE/3=FAULT)+diag1 取走, 保持至下次 TEST/STOP/CLEAR
0x08HEALTH[cmd][cmd, err, olovState, threshL, threshH, trqL, trqH, reason]读健康/堵转监测: 高负载状态 / 高负载阈值 / 实时转矩计数 / 最近停机原因
0x09STATS[cmd][cmd, err, runSeconds(3B), startCount(2B), lastReason]读运行统计: 累计运行秒数 / 启动次数 / 最近停止原因

10.2 QUERY 响应字段

字段说明
err0=OK
state步进电机态: 0=IDLE / 1=RUN / 2=FAULT. 行程测试进行中 (testState=1) 时 state 恒为 1(RUN); 测试结束 (DONE/FAULT) 后 state 回落为步进态 (通常 IDLE=0), 结果由 testState+diag1 表达, 不再占用 state — 上位机 "等 IDLE" 不会因 DONE 卡住
fault电机驱动故障寄存器原始值 (bit7=FAULT, bit6=SPI_ERROR, bit5=UVLO, bit4=CPUV, bit3=OCP, bit2=STALL, bit1=过温, bit0=开路)。state=FAULT 时为停机瞬间快照（DRV 状态寄存器读后自清，固件在 FAULT 态冻结轮询以防证据被抹掉，归因靠此快照）；IDLE/RUN 时为实时轮询值
diag1行程测试故障原因 (非测试时为 0): 1=步进故障 / 2=挣脱超时 / 3=方向极性错触 / 4=期望触点超时 / 5=RUN中电机停转(外部 STOP/被劫持, 300ms 宽限后判)
diag2诊断寄存器2 (OTW/OTS/STALL/OL)。state=FAULT 时同为停机瞬间快照
stepsDone本次运动已完成的微步数 (16bit, 溢出截断; 持续运行意会)
switchErr行程开关错误位: bit0=上行程错(缺失/超腿长未触发), bit1=下行程错. 由上电回零/运行中开关监控置位; CLEAR 清 0. 置位时 TEST 被禁(冲挡块保护), MOVE 不受门控(上位机自行决策)但运行中开关监控仍会在超腿长未触发时置位并停机.
testState行程测试状态机当前态: 0=非测试, 1=RUN, 2=DONE, 3=测试FAULT. 测试结束后 MT 态保持到下次 TEST/STOP/CLEAR, 供上位机可靠取走结果; state 已回落步进态, 二者不再歧义

10.3 HEALTH / STATS 响应字段

命令字段说明
HEALTH (0x08)olovState高负载监测状态: 0=正常 / 1=持续高负载(待降速) / 2=已自动降速 / 3=高负载停机
thresh高负载 TRQ_COUNT 阈值 (16bit, 默认 400; 越低越接近失速)
trq最近一次转矩计数采样 (12bit, 满刻度 4095=无负载, 越低负载越高)
reason最近停机原因: 0=无 / 1=正常停止 / 2=运行时限 / 3=高负载停机 / 4=DRV故障
STATS (0x09)runSeconds累计运行秒数 (24bit LE, RAM 仅存, 断电清零)
startCount累计启动次数 (16bit LE, RAM 仅存)
lastReason最近停止原因 (同 HEALTH.reason)
错误码 (data[1])
0=OK, 1=参数错误, 2=器件处于故障状态, 3=忙(TEST 进行中)。
上电行程自检/回零 (先上后下)

上电时电机位置未知，开全局中断后无论电机停在何处（含已压行程开关）均执行两阶段自检：

  • 阶段1 向上找 KEY_UP：验证上行程开关在位/可达（静态已触发则免驱动）。
  • 阶段2 向下回归 KEY_DOWN：验证下行程开关并建立下行程绝对基准。
  • 两阶段通过 → 回零完成。任一失败（超腿长未触发/堵转停机/超步/超时）→ 置 switchErr 对应位并立即返回，此时 TEST 回 MOTOR_ERR_FAULT（防冲挡块）；MOVE 不受此门控，但运行中开关监控超腿长未触发仍会置位并停机。CLEAR 清错误位。

自检以保护性参数运行（低转速低转矩 + 每段步数上限 + 30s 超时），堵转由转矩监测兜底。蜂鸣判据在 POST 末尾：电机自检与 UHF 通信全部通过才蜂鸣 1s；任一失败静默，由错误灯语表达（AM 通信/参数 CRC 仅记错误位，不参与蜂鸣判据）。

运行中开关监控 + 灯色指示
  • 正向(奔上)超过上腿限制 LEG_UP_LIMIT 未触上开关 → 置 switchErr.bit0; 反向(奔下)超下腿限制未触下开关 → 置 bit1.
  • 灯色(500ms 闪烁): 上行程错=黄, 下行程错=粉红.

11. FC_UHF_CTRL (0x21) — UHF 超高频读写模块控制

本命令控制超高频（UHF）RFID 读写模块（EPC Class 1 Gen2 / ISO 18000-6C）。data 区首字节为子命令码 cmd（0x01~0x0E，另 0x10），其后为参数。所有响应同步返回：data[0]=cmd，data[1]=err（0=OK），其余随命令。

11.1 子命令总览

cmd名称Host → Device (data)Device → Host (data)说明

0x02CLOSE[cmd][cmd, err]停止并下电
0x03INVENTORY[cmd, timeoutL, timeoutH][cmd, err, count L, count H, (rssi, epcLen, epc..)...]发起一次盘点：设备内部同步完成盘存与取回，标签内联在响应里带回；timeout(ms, 缺省 1000) 为盘存超时
0x04READ_TAG[cmd, epcLen, epc.., bank, addr, cnt][cmd, err]读标签：按 EPC 定位，读 bank/addr 起 cnt 个字
0x05WRITE_TAG[cmd, epcLen, epc.., bank, addr, len, data..][cmd, err]写标签：按 EPC 定位，写 len 字节到 bank/addr

11.2 盘点错误码与同步语义

INVENTORY 为同步阻塞：设备在单请求内完成多标签盘存（超时 timeout，缺省 1000ms）→ 取回缓冲 → 解码 → 把全部标签内联在响应里带回。无主动上报。err 取值：

err含义
0OK，紧随其后 count L,H + 每条 [rssi, epcLen, epc..]（rssi 0~255，epcLen 6~16）
1 PARAM参数非法
2 BUSY设备忙（其它操作进行中），需稍后重试
3 NOT_READY未 OPEN / 已下电
4 LINKUHF 模块链路异常
5 NO_TAG场内无标签
6 TIMEOUT盘存超时

13.1 UNLOCK_EPC (0x10) EPC 解锁流程（EPC 开锁通道）

业务闭环（上位机视角）：

1. 客户付款 -> 上位机把 1 张期望 EPC 单帧下发给开锁器 (0x10)
2. 客户把标签放到开锁器感应区, 红外光电触发 (挡住≥200ms)
3. 持续校对: 0x21 单标签指令逐发轮询 (~27ms/发),
   连续 3 发读到且 EPC 一致 -> 稳定确认 (推 0x0B + 绿单闪, 无蜂鸣)
4. 磁块升起 KEY_UP: 升起期间盘点不停 —
   · 标签稳定在场: 每 3 发命中绿单闪 (无蜂鸣, 2026-09-19 裁决心跳鸣废除)
   · 标签移走 (连续 3 发空射) 或更换 (读到外来 EPC): 停机收起
5. 顶部保持 holdTopMs (默认 3s): 同监守; 期满 EPC 仍在场 -> 周期成功
6. 周期末回降 KEY_DOWN (启动时鸣 800ms) -> 下一轮 (循环模式) 或 终帧
7. 流程完成 (时间到/单轮成功): 蜂鸣 1s + 绿三连闪 + 0x10 终帧

请求：[cmd, epcLen, tmoL,tmoH, winL,winH, holdTopL,holdTopH, rsv0, rsv1,rsv2,rsv3, epc(epcLen 字节)] — epcLen 1~12；tmoMs 单发盘点时限（缺省 100，0→100）；winMs 单轮光电等待窗 W（默认 20000）；holdTopMs 顶部保持时长（默认 3000，0→3000，上限 60000）；rsv0=流程超时秒；epc=期望标签 EPC（12 字节头后紧跟，帧长 12+epcLen）。

rsv0 流程模式：

rsv0=0 单轮: 一轮即结。周期成功 -> ALL_OK; 升起/保持中移除或
  更换 -> EPC_LOST; W 窗满未确认 -> TIMEOUT。
rsv0>0 循环: 受理起 rsv0 秒内周期往复, 流程窗在周期边界判定
  (进行中的周期跑完)。周期间衔接规则:
  · 周期成功后 (回退到底): 须先 "标签移走 (连续 3 发空射) 且红外
    回落" 再重新放标才开下一轮 (防搁置标签无限自动循环)
  · 周期失败后回归: 免移走手势 —
      回退途中标签放回 (连续 3 发读回) -> 中停回退, 半程直接再升
      回退到底后标签重新稳定在场 -> 校对段判定通过即开下一轮
      (再升不依赖红外光路, 稳定在场由校对认证)

流程：

⑴ 前置检查 (Locker/UHF/电机空闲 + 已回零; UHF ERROR 彻底下电重上)
    -> 推 0x0F 受理帧 [phase=1, 实际窗]
⑵ 红外门控: 等放标 (挡住 200ms 去抖), 窗=W(单轮)/流程窗(循环);
    单轮窗满 -> err=11 NO_IR
⑶ 持续校对: 0x21 逐发 (~27ms), 连续 3 发读到一致 EPC -> 稳定确认
    (每周期推 0x0B + 绿单闪, 无蜂鸣; 空射/外来打断计数)
    兜底: UHF 失联 5s 窗
⑷ 升起: 寻触 KEY_UP, 盘点不停 (每 3 发稳定命中绿单闪);
    连续 3 发未读到(移除)/读到外来(更换) -> 停机 + 免疫收起
⑸ 顶部保持 holdTopMs: 同监守; 期满在场 -> 周期成功
⑹ 周期末回退 (免疫, 寻触 KEY_DOWN): 启动时鸣 800ms (失败不鸣);
    成功 -> 回退到底; 失败(循环) -> 回退挂"回归监守", 语义见上
⑦ 统一出口: UHF 停扫 + 回降(若升起) + 0x10 终帧;
    ALL_OK -> 蜂鸣 1s + 绿三连闪

解锁态响应矩阵：受理帧（0x0F）起至终帧发完，仅 CANCEL / QUERY / GET_PROGRESS（及各 FC 只读命令）被放行，其余 LOCKER 子命令与 MOTOR/UHF/AM 控制类一律回 BUSY。

推送事件帧（func=0x23^0xFF=0xDC，data[0]=事件码，经命令来向通道原路回）：

码名称Device → Host (data)说明
0x0FEVT_START 受理[0x0F, 0, phase(1=WAIT_TAG), winMs(3 LE)]命令已受理，含实际生效的解锁窗（单轮=W，循环=流程窗 rsv0×1000ms）
0x0BEVT_TAG 确认[0x0B, seq(=1), epcLen, epc.., confirmed(=1), total(=1), 判据耗时(2 LE ms), 流程耗时(2 LE 秒)]期望 EPC 稳定确认（每周期一帧）：判据耗时=凑齐 3 连所需 ms（在场 ~81ms），流程耗时=自红外触发/再入场至本帧的整秒数（u16 秒，2026-09-19 全协议统一；亚秒诊断看判据耗时）。周期失败不推帧（移除/更换无事件帧，状态经 GET_PROGRESS lastCycle 拉取）

13.4 UNLOCK_AM (0x11) AM 标签解锁流程（AM 开锁通道）

业务闭环（上位机视角）：

1. 上位机单帧下发 0x11 [amCnt, tmo, rsv] — 设备不触碰 AM 解码器 (零控制)
2. 客户把 AM 标签放到感应区, 解码器按自身默认参数消磁 -> 每成功一张推 0x0E + 白单闪
   (无蜂鸣; 单张消磁 0.75~26s 不等, 多帧重试属正常 — 静默 3s 结算)
3. 计数达 amCnt -> 结账 (不动电机): 蜂鸣 1s + 绿三连闪, rise/lower 恒 0
4. 0x11 终帧 (ALL_OK)

请求：[cmd, amCnt, tmoL,tmoH, rsv0, rsv1]（6B）— amCnt 0~255（期望张数；0=直接完成支路：无计数门 0≥0 首查即达标，不耗窗直接结账 ALL_OK）；tmo u16 秒计数窗（>0，受理起算，上限 16000）；rsv0/rsv1 保留位（设备现不解释，终帧原样回显）。

计数判据（2026-09-19 真机修订）：AM 解码器 cmd17 突发静默超 3s 即结算一次成功，帧数不限 — 多帧=同标签补杀重试（实测 1~26 帧均为一张，结局仍是死）；真失败形态为持续连发永不结算，由窗满正确排除（不计入 deactDone）。窗满时若有突发未结算，宽限至多 3s 等其入账（窗末消磁的标签不得漏计）。达标检查优先于窗满（同拍边界）。

AM 解码器零控制（2026-09-19 裁决"AM 设备从上电到结束不要控制，按照默认参数即可，仅在解锁期间监控解锁帧"）：上电零下发（不推参数区/不归一模式），受理不探链/不切模式/不下发参数，出口不还原 — 解码器全程按自身默认参数与自主状态运行，设备仅被动接收 cmd17 计数。解码器静默（含挂起/自锁）只能按窗满结账（不再报 AM_LINK）；上位机仍可经 0x22 SET_MODE/SET_CONFIG 显式配置（流程中回 BUSY）。无 IR 门控 / 无循环模式 / 无升起段监守（已消磁标签必静默，监守无意义）；全程不触碰 UHF，全程不动电机（受理前置仅查业务空闲）。

CANCEL：计数窗内立即 ABORTED（无机械段，无免疫窗口）。

18.1 CRC32 (MPEG-2) 算法

参数值
多项式 poly0x04C11DB7
初值 init0xFFFFFFFF
输入反射 / 输出反射无 / 无
最终 XOR无
覆盖范围帧头 0x53 起至 data 末尾（即 CRC 前的全部 N+7 字节）
附加方式4 字节小端尾附（crc&0xFF 在最前）

参考实现（C）：

uint32_t crc32_mpeg2(const uint8_t *p, uint32_t len) {
    uint32_t crc = 0xFFFFFFFFu;
    for (uint32_t i = 0; i < len; i++) {
        crc ^= (uint32_t)p[i] << 24;
        for (int b = 0; b < 8; b++)
            crc = (crc & 0x80000000u) ? (crc << 1) ^ 0x04C11DB7u
                                      : (crc << 1);
    }
    return crc;                        /* 无反射, 无最终 XOR */
}
