App USB Protocol — Host API Reference

应用层通信协议 · 命令 / 帧格式 / 校验 / 子命令 · 完整 API 参考

协议版本：2  |  传输：USB HID Interrupt / 64B 包 / 16ms 轮询 / 报告 ID=0x02

响应规则：响应 func = 请求 func ^ 0xFF（如 0x01→0xFE、0x14→0xEB、0x15→0xEA、0x16→0xE9）

1. 帧格式（所有命令通用）

┌──────┬──────┬─────┬─────┬─────────┬──────┬─────────┬─────────┐
│ 0x53 │ 0x77 │ ADDR│ 0x00│ length  │ func │ data    │ crc32   │
│  S   │  w   │ 1B  │RSV  │ LE16     │ 1B   │ N bytes  │ LE32    │
└──────┴──────┴─────┴─────┴─────────┴──────┴─────────┴─────────┘
  0    1    2     3    4     5   6    7..7+N  7+N+1..7+N+4
字段长度说明
header11B固定 0x53（ASCII 'S'）
header21B固定 0x77（ASCII 'w'）
devAddr1B目标设备地址；本机默认 0x01，广播 0xFF
reserved1B固定 0x00；非 0 静默丢弃（Round 018 起强制校验）
length2B LEpayload 字节数 = 1 + N + 4（func + data + CRC32）；范围 5..1029
func1B命令码（见 §3）
dataN命令参数或响应数据，N = length - 5
crc324B LE覆盖前面 N + 7 字节；CRC32 (MPEG-2, poly=0x04C11DB7, init=0xFFFFFFFF, 无反射, 无最终 XOR)
约束
  • 字序：多字节字段（小端 LE），length[lo,hi], crc32[b0,b1,b2,b3]。
  • 校验：CRC 不匹配、length 越界或 reserved≠0x00 → 设备静默丢弃，不响应。

2. USB HID 传输层

端点

EP方向类型包大小轮询
EP1IN（设备→主机）Interrupt64B16 ms
EP2OUT（主机→设备）Interrupt64B16 ms

HID 报告 ID

设备发送的 64B Interrupt Report 第一个字节固定为报告 ID 0x02。主机接收时先剥除这个字节，剩余 63B 才是协议层帧。

HID 描述符

报告描述符: Usage Page 0x8C (Vendor Defined), Collection Application
              Input + Output + Feature (各 64B 或 2B)
接口类    : HID (0x03)
子类/协议  : 0 / 0
单包帧大小限制

帧体 ≤ 63B（剥掉 Report ID）。即 data_len ≤ 63 - 7 = 56 字节的单包可承载。需要更大帧时必须实现 USB 分片协议（本工程不实现）。

3. 命令总览

App 实现 8 个命令。其余命令（FC=0x03/0x04/0x05/0x06/0x09）由 Bootloader 处理（详见 Boot_Protocol.html）。

FC名称Host → DeviceDevice → Host用途
0x01FC_HANDSHAKE—28B: result/protoVer/status/UID/uidHash/layer/upgradeCount/baudRate发现/存活探测
0x02FC_ENTER_BOOT—1B: result预升级: 置 UPG 标志 + 延时 50ms + 自动软复位进 Boot
0x07FC_DEVICE_INFO—34B: result/addr/hwVersion/version (App层=swVersion)查询版本 / 设备地址
0x08FC_RESET—1B: result软件复位 (空参数, 回 OK 后延时 20ms 再复位)
0x09FC_EXIT_BOOT—1B: result退出升级 (Boot 处理); App 忽略
0x0AFC_MOTOR_CTRLdata 首字节为子命令码同步响应, 格式见 §8 (subCmd 0x01~0x06)步进电机 DRV8434S 控制
0x0BFC_UHF_CTRLdata 首字节为子命令码同步响应, 格式见 §14 (subCmd 0x01~0x0A)UHF 超高频 SIM7500 模块控制
0x14FC_RFID_14443Adata 首字节为子命令码异步响应, 格式见 §8 (subCmd 0x00~0x02/0x10~0x13/0x20~0x21/0x30~0x35)ISO14443A 射频卡操作

0x16FC_RFID_CTRLdata 首字节为子命令码同步响应, 格式见 §9 (subCmd 0x00~0x03)射频控制原语 (INIT/关/开/延时)

响应帧的 func = 请求 func ^ 0xFF（例如 0x01 → 0xFE，0x15 → 0xEA）。

4. FC_HANDSHAKE (0x01)

请求

发送帧（data 为空）:
53 77 01 00 05 00 01  [CRC32 4B]
│                       │
header                   FC=0x01
length=5 (FC + CRC32)

响应 data（28 字节, App/Boot 一致）

偏移字段类型说明
0resultu80=RESULT_OK；其他=错误
1protoVeru8协议版本 = 2
2statusu8设备状态：0=IDLE / 1=RUN / 2=UPG / 3=FAULT
3UID12BSTM32 唯一 ID（96 位）
15uidHashu32 LECRC32(UID)
19layeru81=App（Boot 返回 0）
20upgradeCountu32 LE累计升级次数
24baudRateu32 LEUART 当前波特率

示例响应

53 77 01 00 21 00 FE [28B] [CRC32 4B]
            │       │   └─ func = 0x01 ^ 0xFF = 0xFE
            │       └─ length = 0x21 = 33 = 1(func) + 28(payload) + 4(CRC)

5. FC_ENTER_BOOT (0x02)

请求

53 77 01 00 05 00 02  [CRC32 4B]
                      └─ FC=0x02

响应 data（1 字节）

值含义
0RESULT_OK — 参数已保存，设备将软复位进入 Boot 升级模式
2ENTER_BOOT_PARAM_ERR — Flash 参数区写入失败
后续（预升级指令）

App 收到本命令后：写 deviceStatus = PARAM_STATUS_UPG (2) 到参数区（持久化），回 OK，延时 50ms（等 ACK 经 USB 1ms 帧周期完整推送 + 主机拉走），然后 NVIC_SystemReset() 自动软复位 → Bootloader 接管。Boot 看到 status=UPG 后 stayInUpdate=true，不超时，停留等待升级。

退出 Boot（不升级）

若进 Boot 后决定不升级，主机发 FC_EXIT_BOOT (0x09)（由 Boot 处理）：Boot 校验 App flash 完好后清 deviceStatus=RUN + 复位跳 App。详见 Boot_Protocol.html。

6. FC_DEVICE_INFO (0x07)

请求

53 77 01 00 05 00 07  [CRC32 4B]
                      └─ FC=0x07

响应 data（34 字节, App 层）

偏移字段长度说明
0result1B0=OK
1addr1B设备地址（默认 0x01）
2hwVersion16B硬件版本字符串
18version16BApp 层固件版本（swVersion）

Boot 层响应格式相同，但 version 字段内容为 bootVersion。

7. FC_RESET (0x08)

请求

53 77 01 00 05 00 08  [CRC32 4B]
                      └─ FC=0x08 (data 必须为空)

响应 data（1 字节）

值含义
0RESULT_OK — 已调度复位，延时 20ms 后 NVIC_SystemReset
1RESET_PARAM_ERR — data 非空（必须为空参数）
时序

回 OK 后延时 20ms（让 USB 1ms 帧周期完整推送 ACK + 主机拉走）再 NVIC_SystemReset()，否则 ACK 可能随复位丢失。主机收到 OK 后应等待设备重新枚举。

8. FC_RFID_15693 (0x15) — ISO15693 射频卡操作

本命令把 ISO15693 射频卡操作打包暴露给上位机。data 区首字节为子命令码 subCmd（0x00~0x08），其后为子命令参数。块大小固定为 4B。

8.1 子命令总览

子码名称Host → Device (data)Device → Host (data)
0x00Inventory 盘点[0x00][0x00][seq][total][result][uidCount][UID 8B…]
0x01ReadBlock 读块[0x01][UID 8B][addr][count][0x01][seq][total][result][data]（可分片）
0x02WriteBlock 写块[0x02][UID 8B][addr][count][data][0x02][seq][total][result]
0x03DSFID 读写[0x03][UID 8B][mode][value?]读:[…][result][dsfid] / 写·锁:[…][result]
0x04EAS 操作[0x04][UID 8B][op][0x04][seq][total][result]
0x05LockBlock 锁块[0x05][UID 8B][addr][0x05][seq][total][result]
0x06StayQuiet 静默[0x06][UID 8B][0x06][seq][total][result]
0x07WriteAFI 写 AFI[0x07][UID 8B][afi][0x07][seq][total][result]
0x08LockAFI 锁 AFI[0x08][UID 8B][0x08][seq][total][result]

mode（0x03）：0=读 / 1=写(带 value) / 2=锁。op（0x04）：0=置位 / 1=复位 / 2=锁定。

8.2 分片协议

USB HID 单包 data ≤ 56B。所有 FC=0x15 响应统一带分片头 [seq][total]（紧跟 subCmd 之后），total=1 即单包。读块响应载荷超 56B 时按每片 payload ≤ 53B 拆分连发：

响应 data = [subCmd][seq][total][payload]
  seq   = 分片序号 0..total-1
  total = 总片数 (1=不分片)
  payload:
    - 读响应: 片0含 [result][data…], 后续片纯 data 续传
    - 其余子命令: total=1, payload=[result]…
约束
  • 写块受 SDK 缓冲限制 count ≤ 8（4*8=32B），单包足够，不分片。
  • 读块 count ≤ 32，count*4 > 53B 时启用分片。
  • 非 0x01 子命令 total 必须为 1，否则 RFID_FRAG_ERR。

8.3 报文示例

Inventory(0x00):
  请求: 53 77 01 00 06 00 15 00 [CRC32 4B]
  响应: 53 77 01 00 10 00 EA 00 00 01 01 [UID 8B] [CRC32 4B]
                       └subCmd └seq └total └uidCount=1
ReadBlock(0x01, count=4, 单包):
  请求: 53 77 01 00 10 00 15 01 [UID 8B] [addr] [count=4] [CRC32 4B]
  响应: 53 77 01 00 0E 00 EA 01 00 01 00 [data 16B] [CRC32 4B]
EAS置位(0x04, op=0):
  请求: 53 77 01 00 0F 00 15 04 [UID 8B] 00 [CRC32 4B]
  响应: 53 77 01 00 08 00 EA 04 00 01 00 [CRC32 4B]

9. FC_RFID_14443A (0x14) — ISO14443A 射频卡操作

本命令把 ISO14443A / Mifare / Topaz 射频卡操作打包暴露给上位机。data 区首字节为子命令码 subCmd，其后为子命令参数。

所有响应统一带分片头 [subCmd][seq=0][total=1][result][data..]（与 §8 15693 同款）；当前实现所有子命令 total=1，单包可发（最大 TransAPDU 响应 ≤ 64B）。

9.1 子命令总览

子码名称Host → Device (data)Device → Host (data)
0x00GetUid 读 UID[0x00][0x00][0][1][result][count][uidType 2B BE][uidLen][uid..][sak]（count=1）
0x01Halt 静默[0x01][0x01][0][1][result]
0x02AuthM1 M1 认证[0x02][uid 4B][authMode 1B][key 6B][blockAddr 1B][0x02][0][1][result]
0x10RATS ISO14443A-4 入口[0x10][0x10][0][1][result][ATS..]
0x11TransAPDU 透传[0x11][apdu 1..64B]（长度由帧 length 隐式给出，无独立 len 字节）[0x11][0][1][result][R-APDU..]
0x12Topaz ReadBlock[0x12][addr 1B][0x12][0][1][result][data 8B]
0x13Topaz WriteBlock[0x13][addr 1B][data 8B][0x13][0][1][result]
0x20WriteBlockM0 写 4B（Ultralight 页，0xA2，无认证）[0x20][blockAddr][data 4B][0x20][0][1][result]
0x21ReadBlockM0 读 16B（Ultralight，0x30，4 页连读，无认证）[0x21][blockAddr][0x21][0][1][result][data 16B]
0x30AuthReadBlockM1 读 16B（Mifare Classic，0x30）[0x30][blockAddr][mode][key 6B][uid 4B]（强制 AuthM1，uid 始终在帧，空=00 00 00 00）[0x30][0][1][result][data 16B]
0x31AuthWriteBlockM1 写 16B（Mifare Classic，0xA0）[0x31][blockAddr][mode][key 6B][uid 4B][data 16B][0x31][0][1][result]
0x32AuthIncrement M1 值块加（0xC1+自动Transfer）[0x32][valueAddr][transAddr][mode][key 6B][uid 4B][value 4B][0x32][0][1][result]
0x33AuthDecrement M1 值块减（0xC0+自动Transfer）[0x33][valueAddr][transAddr][mode][key 6B][uid 4B][value 4B][0x33][0][1][result]
0x34AuthTransfer M1 值块裸提交（0xB0）[0x34][transAddr][mode][key 6B][uid 4B][0x34][0][1][result]
0x35AuthRestore M1 值块恢复（0xC2+自动Transfer）[0x35][valueAddr][transAddr][mode][key 6B][uid 4B][value 4B][0x35][0][1][result]

mode 字段（仅 0x02 AuthM1 与 0x30~0x35 M1 系列的 mode）= authMode：0x60=KeyA / 0x61=KeyB。Auth 前缀命令强制 AuthM1：mode 非 0x60/0x61 一律 RFID_PARAM_ERR。Mifare 值块操作（Increment/Decrement/Transfer/Restore）必须先对所在扇区 AuthM1，故均带 Auth 前缀。M0 (0x20/0x21) 与 Topaz (0x12/0x13) 无 mode/key/uid 字段。blockAddr/valueAddr/transAddr：Mifare Classic 块号（0..63，按扇区）；M0 为页号。

一键 UID 校验（同步时序）：仅Auth 前缀命令（0x30~0x35）帧中带 mode + key + uid 4B，uid 字段始终在帧中 4 字节（空 = 00 00 00 00，不是省略字段）。uid 全 0 → 设备内部 GetUid(REQALL) 盘点拿 uid 再 AuthM1；uid 非全 0 → 用下发 uid 直接 AuthM1（跳过盘点）。主机一条命令完成「盘点→认证→操作」，无需先发 GetUid+AuthM1。M0 (0x20/0x21) 与 Topaz (0x12/0x13) 不带 uid 字段，由设备内部激活卡（无密钥认证）。

GetUid 新格式：响应 result 后为 [count][uidType 2B BE][uidLen][uid..][sak]。uidType = 卡型码（0x0044=MF0 Ultralight / 0x0004=MF1 S50 / 0x0002=MF1 S70 / 0x0344=MF3 DESFire）；uidLen 用于定界 uid/sak 边界（M1 UID 可 4B/7B 级联，长度可变）；保留 sak。当前 count 上限 1。

AuthWriteBlockM1 (0x31) vs WriteBlockM0 (0x20)（底层都只发原始字节）：0x31 走 Classic 0xA0，写 16B 块（数据块/尾块/值块——值块需主机按 NXP 值块格式 [value 4B][~value 4B][value 4B][addr 1B][~addr 1B][pad 2B] 共 16B 组好整块下发）。0x20 走 Ultralight 0xA2，写 4B 页，无认证字段。0x21 走 0x30 读，回 16B（4 页连读），无认证。M0 读写不对称（写 4B/读 16B）符合 Ultralight 物理特性。

值块四件套 (0x32/0x33/0x34/0x35)：电子钱包的增/减/转/恢复。AuthIncrement/AuthDecrement/AuthRestore 走 SDK ISO14443A_Value（opMode=0xC1/0xC0/0xC2），先对 valueAddr 所在扇区 AuthM1，把 value 加/减（Restore 原样读入、忽略 value）到卡内缓冲，再自动 Transfer 到 transAddr。AuthTransfer 为裸 0xB0 提交，仅把卡内缓冲写入 transAddr，依赖前序 Inc/Dec/Restore 已装入缓冲。AuthRestore 用于值块复制：把源值块原值装入缓冲并自动转到 transAddr，帧与 Inc/Dec 同构 17B（value 字段保留，卡端忽略）。

9.3 分片与参数约束

约束
  • 所有子命令 total=1（单包），保留分片头仅为与 15693 对齐。
  • AuthM1 (0x02)：data = 13B（subCmd + uid4 + mode1 + key6 + addr1），dataLen-1 = 12，不符则 RFID_PARAM_ERR。
  • AuthReadBlockM1 (0x30)：dataLen-1 = 12（blk + mode + key6 + uid4），强制 AuthM1、统一长度。uid 字段始终在帧，全 0 内部 GetUid，非 0 用下发 uid。无 authMode=0 免认证路径。
  • AuthWriteBlockM1 (0x31)：dataLen-1 = 28（blk1 + mode1 + key6 + uid4 + data16），强制 AuthM1；Classic 0xA0 写 16B 块。
  • WriteBlockM0 (0x20)：dataLen-1 = 5（blk1 + data4）；Ultralight 0xA2 写 4B 页，无认证（设备内部激活）。
  • ReadBlockM0 (0x21)：dataLen-1 = 1（blk1）；Ultralight 0x30 读 16B（4 页连读），无认证。
  • Topaz ReadBlock (0x12) / Topaz WriteBlock (0x13)：dataLen-1 = 1 / 9（addr1 / addr1+data8）。
  • AuthIncrement (0x32) / AuthDecrement (0x33) / AuthRestore (0x35)：dataLen-1 = 17（valueAddr1 + transAddr1 + mode1 + key6 + uid4 + value4），强制 AuthM1（认证 valueAddr 所在扇区）；Inc/Dec/Restore 后自动 Transfer 到 transAddr。Restore 的 value 字段卡端忽略，建议发 00 00 00 00。
  • AuthTransfer (0x34)：dataLen-1 = 12（transAddr1 + mode1 + key6 + uid4），强制 AuthM1（认证 transAddr 所在扇区）；裸 0xB0，依赖前序 Inc/Dec/Restore 已装入缓冲。
  • TransAPDU (0x11)：APDU 长度 1..64B（dataLen-1），无独立 len 字节，超界 RFID_PARAM_ERR。
  • 设备端作业队列 RFID_A_JOB_QUEUE_LEN = 4，满则回 RFID_BUSY (0x0C)。
  • 协议/射频由 FC_RFID_CTRL (0x16) 显式控制（见 §10），卡操作不再自动切换；主机须先 INIT+OPEN 再发卡操作。

AuthTransfer 一键(transAddr=0x09, KeyA):
  请求: 53 77 01 00 12 00 14 34 09 60 [key 6B] 00 00 00 00 [CRC32 4B]   ← dataLen-1=12, 裸 0xB0
  响应: 53 77 01 00 08 00 EB 34 00 01 00 [CRC32 4B]
AuthRestore 一键(valueAddr=0x08, transAddr=0x09, KeyA) — 值块复制 (0xC2+自动Transfer):
  请求: 53 77 01 00 15 00 14 35 08 09 60 [key 6B] 00 00 00 00 00 00 00 00 [CRC32 4B]   ← dataLen-1=17, value=00000000(卡端忽略)
  响应: 53 77 01 00 08 00 EB 35 00 01 00 [CRC32 4B]
AuthM1(0x02, KeyA, blockAddr=0x04):
  请求: 53 77 01 00 12 00 14 02 [uid 4B] 60 [key 6B] 04 [CRC32 4B]
  响应: 53 77 01 00 08 00 EB 02 00 01 00 [CRC32 4B]   ← result=RFID_OK
  失败: 53 77 01 00 08 00 EB 02 00 01 0D [CRC32 4B]   ← result=RFID14443_AUTH_ERR(0x0D)
TransAPDU(0x11, apdu=00A40400...):
  请求: 53 77 01 00 0C 00 14 11 [apdu 5B] [CRC32 4B]   ← length 由帧给出, 无 len 字节
  响应: 53 77 01 00 .. 00 EB 11 00 01 00 [R-APDU..] [CRC32 4B]
典型流程

典型 Mifare Classic 读块流程：先 0x00 GetUid → 0x02 AuthM1(同一卡 uid + 对应扇区密钥) → 0x30 AuthReadBlockM1。认证只对当前会话有效，换扇区需重新 Auth。一键模式（强制 AuthM1、统一 uid 字段）：Auth 前缀命令帧中固定带 mode + key + uid 4B（uid 空时由设备内部盘点），单条命令完成「盘点→认证→操作」。值块：用 0x32/0x33 增减、0x35 恢复（均含自动转），0x34 裸提交。

10. FC_RFID_CTRL (0x16) — 射频控制原语

本命令把射频底层的 4 个控制原语暴露给上位机，由主机自行编排时序（取代旧版设备内自动 RF cycle）。data 区首字节为子命令码 subCmd，其后为参数。

所有响应同步（收到即执行并立即回包，不入作业队列），格式 [subCmd][0][1][result]。卡操作命令（FC=0x14/0x15）不再自动切换协议或控制射频——主机须先用本命令把射频置好，再发卡操作，否则 SDK 因 RF 关闭返回 RFID_TIMEOUT/NO_TAG。

10.1 子命令总览

子码名称Host → Device (data)设备动作Device → Host (data)
0x00INIT 协议初始化[0x00][proto]清 Crypto1On 残留 + 协议 Init + 置 curProto[0x00][0][1][result]
0x01CLOSE 关射频[0x01]关闭天线[0x01][0][1][result]
0x02OPEN 开射频[0x02]打开天线[0x02][0][1][result]
0x03DELAY 延时[0x03][ms u8]（0..255ms）阻塞延时（阻塞主循环）[0x03][0][1][result]

proto（0x00）：0x01=ISO15693 / 0x02=ISO14443A。INIT 内部先清 CRYPTO1ON 位（清掉 14443A Mifare 认证后的流密码残留）再调对应协议 Init，属于"初始化为干净状态"的内部步骤。

10.2 典型时序（复刻旧自动 RfCycle）

切到 14443A 并读卡 (等价旧 RfCycle):
  ① CLOSE   53 77 01 00 06 00 16 01 [CRC32 4B]   → func=0xE9 data=01 00 01 00
  ② INIT    53 77 01 00 07 00 16 00 02 [CRC32 4B]  ← proto=0x02(14443A)
            → func=0xE9 data=00 00 01 00
  ③ DELAY   53 77 01 00 07 00 16 03 06 [CRC32 4B]  ← 6ms 稳定
            → func=0xE9 data=03 00 01 00
  ④ OPEN    53 77 01 00 06 00 16 02 [CRC32 4B]
            → func=0xE9 data=02 00 01 00
  ⑤ GetUid  53 77 01 00 06 00 14 00 [CRC32 4B]    ← FC=0x14 卡操作
            → func=0xEB data=00 00 01 00 01 [uidType 2B][uidLen][uid][sak]

同协议内连续卡操作无需重复 INIT/OPEN（curProto 已置）；切协议（14443A↔15693）才需重走 ①~④。

10.3 约束

约束
  • 同步阻塞：DELAY 会阻塞主循环指定毫秒，期间到达的 USB 帧缓存在解析器，DELAY 结束后下一轮处理。建议 ≤ 255ms（单次上限）。
  • 开机默认关射频：上电后 RF 关闭，主机须显式 OPEN 后才能读卡；不发控制命令直接发卡操作 → RFID_TIMEOUT(0x05)。
  • INIT 无失败码：协议 Init 始终成功（仅配寄存器），故 INIT 成功恒回 RFID_OK；仅 proto 非法时回 RFID_PARAM_ERR。
  • 非法 subCmd → RFID_SUBCMD_ERR(0x01)；缺 subCmd/参数 → RFID_PARAM_ERR(0x02)。

12. 主机接入样板

12.1 打开设备

// hidapi
handle = hid_open(0x5377, 0x5378, NULL);
// 报告 ID = 0x02, 包长 64
unsigned char report[64];             // 读写都先放 64B 缓冲

12.2 发请求

// 例: FC_HANDSHAKE
uint8_t frame[12];
frame[0] = 0x53; frame[1] = 0x77;            // header "Sw"
frame[2] = 0x01;                              // devAddr
frame[3] = 0x00;                              // reserved (必须 0x00)
frame[4] = 5; frame[5] = 0;                   // length LE
frame[6] = 0x01;                              // FC_HANDSHAKE
// frame[7..10] = CRC32 覆盖前 7B
uint32_t crc = crc32_mpeg2(frame, 7);         // MPEG-2, 无反射, 无最终 XOR
memcpy(frame + 7, &crc, 4);                   // CRC32 LE
hid_write(handle, frame, 12);

12.3 收响应

int n = hid_read(handle, report, 64);
if (n >= 64 && report[0] == 0x02) {
    // 报告 ID 剥除后, 剩余 63B 是协议帧
    parse_frame(report + 1, n - 1);
    // response func = request func ^ 0xFF
}

13. FC_MOTOR_CTRL (0x0A) — 步进电机 DRV8434S 控制

本命令把步进电机（TI DRV8434S 双极步进驱动，SPI2 控制）暴露给上位机。data 区首字节为子命令码 cmd（0x01~0x06），其后为参数。所有响应同步返回：data[0]=cmd，data[1]=err（0=OK），其余随命令。通信引脚自选：SCK=PB13 / MISO=PB14 / MOSI=PB15 / NSS=PB12，nFAULT=PB6，nSLEEP=PB7。步进走 SPI（SPI_STEP/SPI_DIR），无需 STEP/DIR 引脚。

13.1 子命令总览

cmd名称Host → Device (data)Device → Host (data)说明
0x01MOVE[cmd, dir, stepsL, stepsM, stepsH][cmd, err]启动运动: dir=0(CW)/1(CCW), steps=24bit 微步数, 0=持续运行
0x02STOP[cmd][cmd, err]停止并关断输出
0x03SPEED[cmd, hzL, hzH][cmd, err]设定微步/秒 (1~2000)
0x04TORQUE[cmd, pct][cmd, err]转矩百分比 (6~100)
0x05QUERY[cmd][cmd, err, state, fault, diag1, diag2, stepsDoneL, stepsDoneH]查询状态/故障/已走微步数
0x06CLEAR[cmd][cmd, err]清除故障并回到 IDLE

13.2 QUERY 响应字段

字段说明
err0=OK
state0=IDLE(停止) / 1=RUN / 2=FAULT
faultDRV8434S FAULT 寄存器原始值 (bit7=FAULT, bit5=UVLO, bit4=CPUV, bit3=OCP, bit2=STALL, bit1=过温)
diag1诊断寄存器1 (OCP 位置)
diag2诊断寄存器2 (OTW/OTS/STALL/OL)
stepsDone本次运动已完成的微步数 (16bit, 溢出截断; 持续运行意会)
错误码 (data[1])
0=OK, 1=参数错误, 2=器件处于故障状态。

14. FC_UHF_CTRL (0x0B) — UHF 超高频 SIM7500 模块控制

本命令把超高频（UHF）RFID 读写模块 SIM7500（芯联创展 / Silion，基于 Impinj E710 平台，EPC Class 1 Gen2 / ISO 18000-6C）暴露给上位机。data 区首字节为子命令码 cmd（0x01~0x0A），其后为参数。所有响应同步返回：data[0]=cmd，data[1]=err（0=OK），其余随命令。通信接口自选：USART1（PA9=TX / PA10=RX，115200-8-N-1，TTL）。模块控制引脚：UHF_EN=PA8（高电平上电）、UHF_ANT=PC13（0=ANT1 / 1=ANT2）。模块侧采用 UHF RFID 通用 0xBB 帧族（头 + len + cmd + data + CRC16）。

控制面 / 数据面解耦：状态机（IDLE/READY/INVENTORY/READ/WRITE/ERROR）由设备内部管理，盘点/读写的标签结果缓存在设备标签缓冲，主机经 GET_TAGS 取走。主机仅下发操作与配置，不参与标签搬运。

14.1 子命令总览

cmd名称Host → Device (data)Device → Host (data)说明
0x01OPEN[cmd][cmd, err]上电 + 下发配置，进入 READY（模块使能）
0x02CLOSE[cmd][cmd, err]停止并下电
0x03INVENTORY[cmd][cmd, err]发起一次盘点（异步，标签入缓冲）
0x04READ_TAG[cmd, epcLen, epc.., bank, addr, cnt][cmd, err]读标签：按 EPC 定位，读 bank/addr 起 cnt 个字
0x05WRITE_TAG[cmd, epcLen, epc.., bank, addr, len, data..][cmd, err]写标签：按 EPC 定位，写 len 字节到 bank/addr
0x06STOP[cmd][cmd, err]停止当前操作
0x07QUERY[cmd][cmd, err, state, link, totalTags]查询状态/链路/累计标签数
0x08GET_CONFIG[cmd][cmd, err, powerDbm, antenna, checksumEn, session, target, q]读取当前配置（功率/天线/校验等）
0x09SET_CONFIG[cmd, powerDbm, antenna, checksumEn, session, target, q][cmd, err]设置配置并持久化（重启保留）
0x0AGET_TAGS[cmd, count][cmd, err, total L, total H, (epcLen, rssi, epc..)...]取标签缓冲；count=0 取全部，>0 取前 count 条

14.2 配置字段 (SET_CONFIG / GET_CONFIG)

字段范围说明
powerDbm5~30发射功率 (dBm)，SIM7500 可调范围 5~30 dBm
antenna0~1天线: 0=ANT1 / 1=ANT2
checksumEn0~11=启用模块帧 CRC16 校验; 0=关闭
session0~3Gen2 session S0~S3
target0~1Gen2 target: 0=A / 1=B
q0~15Gen2 Q 值; 0=模块默认

14.3 QUERY 响应字段

字段说明
err0=OK
state0=IDLE / 1=READY / 2=INVENTORY / 3=READ / 4=WRITE / 5=ERROR
link0=链路正常 / 1=超时 / 2=CRC 错误
totalTags累计盘点到标签总数（8bit 截断）
错误码 (data[1])
0=OK, 1=参数错误, 2=忙（已有操作进行中）, 3=未就绪, 4=链路错误, 5=未读到标签, 6=超时。
存储与持久化
SET_CONFIG 设置后写入设备参数区 userParam（偏移 0），断电重启自动加载最后配置（magic 0x5548）。上位机可用 GET_CONFIG 校验。
