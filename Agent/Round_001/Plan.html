ZLR5401 · 空白工程改造实施方案

将当前基于 GD32/AnyID 的 RFID 旧工程，梳理为「仅保留 Boot 升级 / 握手复位 + USB 驱动」的空白工程，供新项目开发。
Rule Demand #001 Target: STM32F103C8T6 (GD32 兼容) App+Boot 双区 USB HID 传输
结论（先给结果）：当前工程骨架本身已相当干净——AnyID 仅残留 3 处头文件 include guard，R321 已不存在，GD32 仅 2 处注释/宏。真正需要做的是 ①还原工程名（Sccd→ZLR5401）、②剥掉 RFID/DES/蜂鸣器等旧应用层保留 USB+协议+握手复位、③备份。改动集中在 Application；Bootloader 基本不动。下方给出完整分步计划与执行后验收，本轮只出方案，不执行，待您审阅。

1.2 工程结构

  • Application/：App 固件。现含 USB 驱动栈 + 完整 RFID 应用层。
  • Bootloader/：Boot，含 IAP 升级 + 握手，负责跳转 App。自包含，无 Common 依赖。
  • Sdk/：STM32F10x StdPeriph Lib + arm-none-eabi（基准，不可改）。
  • Protocol/：协议文档（Boot_Protocol.html / App_Protocol_V1.0.docx）。
  • TrashCan/：回收站（含之前移除的旧产物）。

1.3 GD32 兼容性说明（保留，不删）

MCU 实际为 GD32F103C8T6（与 STM32F103 引脚/寄存器兼容，使用 STM32F10x StdPeriph 驱动）。App_Config.h:33 的 MCU_PART "GD32F103C8T6" 是硬件事实、非旧工程杂质，应保留。仅清理写法使描述中性：注释 "Using GD32F103C8T6 (STM32F10x compatible library)" 可精简保留。版本串 DEV_HW_VERSION/DEV_SW_VERSION "SCCD_V1.0" 中的 "SCCD" 属旧工程名，改为新占位（如 ZLR5401_V1.0 或待新项目定名）。
