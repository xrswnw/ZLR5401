1. 结论小结

当前工程 主流程已按《约束/Link.txt》落地：上位机下发「硬标签 EPC 清单 + 软标数」→ UHF 比对 → 匹配升起绿灯 / 不匹配红灯不升、结果回传 → m==n 进软标 → 次数尽结账完成。 状态机覆盖完整、结构清晰，未发现阻断交付的缺陷。

4. 主要发现（摘录）

P0-1 清单有效期 / 关店清空缺失 约束隐含"结账窗口内放好标签"，但无清单到期强制回 IDLE 或清空策略；无人值守时清单常驻。 对应 Plan §6.1#9 / §6.3#3 的离线/过期策略。需客户确认离线语义后补。
P1-4 反作弊复核缺失 Plan §3.2 明确的重点：磁块升起后若"当前 EPC 被摘换成非清单"，应立即下降 + 报警。 当前升起后不再复核。这是反作弊有效性的核心缺口。
P1-2 R5 窗口语义 每次匹配都整体重置 2min+30s 窗口 → 多标签时总时长超约束意图（"预留总时长" vs "每次顺延"）。
P1-1 软标阶段无超时 进入 SOFT_DECODE 已清空窗口，若上位机不再消耗将永久停留。
