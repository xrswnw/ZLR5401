4. 缺陷修复日志（闭环：发现→修码→备份→烧录→复验）

#1 电机 CLEAR 无法退出行程测试故障/忙态 —— 已修复
  • 现象：TEST 出现故障或卡在 BUSY 后，发 MOTOR_CLEAR(0x06) 返回 OK，但 QUERY 仍恒定上报 state=3 (FAULT)，无法复位。
  • 根因：QUERY 优先上报行程测试态（[App_Dispatch.c:154](Application/src/App_Dispatch.c#L154)），而 MOTOR_CMD_CLEAR（[App_Dispatch.c:178](Application/src/App_Dispatch.c#L178)）只调 App_Stepper_ClearFault() 清步进故障，未调 App_MotorTest_Stop() 复位行程测试态机 → 设备卡死上报 FAULT。
  • 修复：CLEAR 分支补调 App_MotorTest_Stop()，与 STOP 一致地复位测试态。
  • 备份：Round_057_20260827_011900｜编译：OK（ZLR5401_202608270119.hex）｜烧录：J-Link 0x08006000
  • 复验：TEST→FAULT(3) 后 CLEAR → state=0 fault=0；STOP → state=0。全量复测 0 FAIL，无回归。
#2（非缺陷，物理前提）行程测试 TEST 启动即 FAULT diag1=3
  • TEST 启动判 MT_FR_WRONG（方向极性错触）实为正确保护：当下机构停驻在上行程警戒线（KEY_UP 按下），正程启动会被 start_leg(0) 拦截以防越过警戒线。
  • 处置：需人工将机构移离行程端点居中后再跑 TEST 往返（G12）。非固件缺陷。
