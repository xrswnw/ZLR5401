1. 需求解读与现状盘点

需求: 在现有 HID 控制通道之外,扩展一路 CDC(USB 虚拟串口 VCP) 作为日志输出口,替代被停用的 UART4 调试串口 (PC10/11)。
本质: 把当前单接口 CustomHID 设备升级为 HID + CDC 复合(Composite) 设备。HID 继续承担上位机控制/数据通道,CDC 承担调试日志输出。

1.1 当前 USB 设备结构(CustomHID,单接口)

1.3 约束与限制

  • PMA 共 512B: 端点数受 BTABLE(每端点 4B×方向)与缓冲分配约束。新增 3~4 个端点缓冲须重排地址且不超 512B。
  • RAM 20KB: USB FS 收发缓冲在 RAM,CDC 日志缓冲需预留,注意不超限。
  • 单类属性结构: ST USB FS 库 V2.2.1 的 Device_Property 是一套回调,复合设备须在 Class_Data_Setup/Class_NoData_Setup 里按接口号分发,库内核 usb_core.c 无需改。
  • 枚举不得回归: 改后 HID 控制通道行为不得变化。
  • 设备描述符需改复合类(bDeviceClass=0xEF Misc,SubClass=0x02,Protocol=0x01),否则 Host 可能不走各接口类。

2. 目标设备结构设计

2.1 复合设备接口规划

接口类端点用途
IF0HID(0x03) EP1 IN(中断64B)
EP2 OUT(中断64B)		 控制通道(保持现状,上位机协议)
IF1CDC 通信类 ACM(0x02) EP3 IN(通知/中断,16B) CDC 线路编码/控制通知
IF2CDC 数据类(0x0A) EP4 IN(批量64B)
EP5 OUT(批量64B)		 日志数据:设备→PC 用 EP4 IN
端点数: EP0 控制 + 5 个数据/通知端点 ⇒ EP_NUM=6(USBPMA 硬件支持 EP0~EP7,本次只用到 EP5)。

2.2 逻辑数据流

上位机协议(HID 控制)  ←→  EP1 IN / EP2 OUT   (IF0 保持原样)
调试/运行日志          →   App_Log_xxx → CDC 缓冲 → EP4 IN → PC 串口(TTY/USB 串口)
PC → 设备(CDC 收)     →   EP5 OUT(可选,日志命令下发/流控,首版可只留 TX)
关键取舍: 日志口只做单向(设备→PC,CDC TX)即可满足"日志输出"诉求。但为确保 VCP 在 Host 端被标准识别,EP5 OUT 仍建好(VCP 需双向描述符才标准),应用层可不消费、只 ACK。

3. 描述符设计

3.1 设备描述符

bLength            = 0x12
bDescriptorType    = DEVICE
bcdUSB             = 0x0200
bDeviceClass       = 0xEF   (Misc Device / Composite)
bDeviceSubClass    = 0x02  (Common)
bDeviceProtocol    = 0x01  (IAD + Class code in interface)
bMaxPacketSize0    = 64
idVendor / idProduct = 沿用当前(不改 PID,宿主仅需新增枚举)

3.2 配置描述符(IF0 HID + [IAD] + IF1/IF2 CDC)

总长度从 41B 增至约 0x5A(90B),需在 usb_desc.h 更新 CUSTOMHID_SIZ_CONFIG_DESC。

// 目标布局
Config(9)  bNumInterfaces=0x03, wTotalLength=<新值>
├─ IF0 HID(9+9+7+7): 接口 + HID描述符 + EP1 IN(中断64) + EP2 OUT(中断64)  ← 原样保留
├─ [IAD(8)]  : 关联 IF1+IF2 为 CDC 复合功能 (bFirstInterface=1, bInterfaceCount=2, class=CDC 0x02)
├─ IF1 CDC Comm(9):
│   │   bInterfaceClass=0x02, SubClass=0x02(ACM), Protocol=0x00
│   │   EP3 IN(中断, wMaxPacketSize=0x0010=16B, 通知)
│   ├─ Functional descriptors(内联在接口描述符后):
│   │   Header Functional   (5B, bcdCDC 0x0120)
│   │   Call Mgmt Functional(5B, bCallMgmt=0, bIntf=2)
│   │   ACM Functional      (4B, 支持 Set/GetLineCoding + SetControlLineState)
│   │   Union Functional    (5B, bMaster=1, bSlave=2)
├─ IF2 CDC Data(9+7+7):
    │   bInterfaceClass=0x0A, SubClass=0x00, Protocol=0x00
    │   EP4 IN(批量, wMaxPacketSize=64)
    │   EP5 OUT(批量, wMaxPacketSize=64)

4. 类请求调度设计(usb_prop.c 核心改动)

ST 库 Data_Setup0 / NoData_Setup0 通过 pProperty->Class_Data_Setup / Class_NoData_Setup 把类请求交给设备属性层。当前 CustomHID 只处理 HID。改为按 pInformation->USBwIndex0(接口号)分发:

4.1 CustomHID_Data_Setup(数据阶段请求)

if (USBwIndex0 == 0) {            // IF0 HID
    GET_DESCRIPTOR(HID / Report) → 原逻辑
    GET_PROTOCOL              → 原逻辑
} else if (USBwIndex0 == 1) {     // IF1 CDC Comm
    GET_LINE_CODING       → 返回 LineCoding[7](communication)
    GET_COMM_FEATURE/SET  → 按需
}

4.2 CustomHID_NoData_Setup(无数据阶段请求)

if (USBwIndex0 == 0) {            // IF0 HID
    SET_PROTOCOL → 原逻辑
} else if (USBwIndex0 == 1) {     // IF1 CDC Comm
    SET_LINE_CODING         → 收 7B LineCoding(115200/8N1)
    SET_CONTROL_LINE_STATE  → 记录 DTR/RTS(可触发"已打开"事件)
}
需在 usb_prop.c 增加 LineCoding 全局缓冲与标准 CDC 请求号宏:GET_LINE_CODING=0x21 · SET_LINE_CODING=0x20 · SET_CONTROL_LINE_STATE=0x22。

5. PMA 缓冲重排 + 端点初始化

5.1 PMA 缓冲重排(usb_conf.h)

当前占到 0x118 附近。重排以容纳 EP3/EP4/EP5,保证 起始地址 32 位对齐且互不重叠、总占用 < 512B。

BTABLE    @ 0x000  (8 端点×2 方向×4B = 32B  →  0x00~0x20)
EP0 RX    @ 0x020  (64B  → 0x020~0x060)
EP0 TX    @ 0x060  (64B  → 0x060~0x0A0)
EP1 TX    @ 0x0A0  (64B, HID IN)
EP2 RX    @ 0x0E0  (64B, HID OUT)
EP3 TX    @ 0x120  (16B, CDC 通知 IN)
EP4 TX    @ 0x130  (64B, CDC 数据 IN)
EP5 RX    @ 0x170  (64B, CDC 数据 OUT)
合计约 0x1B0 = 432B  <  512B  ✔
具体数值在实现时按 USB_FRAME_LEN=64 与 BTABLE 对齐复核;PMA 需 ≥ 4B 对齐。

5.2 usb_conf.h 端点/回调配置

/* EP_NUM 3 → 6 */
#define EP_NUM  (6)

/* 回调映射 */
#define EP3_IN_Callback   CDC_NotifyIn_User    /* 通知 IN 完成(可空)*/

#define EP5_OUT_Callback  CDC_DataOut_User     /* PC→设备(可选消费)*/

6.3 日志缓冲

建议: CDC TX 用环形缓冲(512B~1KB),由主循环/发送完成中断排出。日志量大时按行/分组切包到 ≤64B 边界。RAM 预算在 20KB 内,追加 ≤1.5KB 可接受。发送用中断驱动,主循环只投递不阻塞。

10. 风险与规避

风险严重度规避
描述符长度/类型错误导致枚举失败 高 抓包/lsusb 逐字段核对;先在 config 描述符加 CDC 数据接口分步验证。
复合设备下 Host 类驱动要求 IAD/正确 union 中 严格按 ACM 标准 functional desc;Mac 对 vendor 复合较宽松。
PMA 地址配错引起缓冲漂移/数据错乱 中 §5 地址表逐项复核 + 实机抓包。
类请求分发改动影响 HID 控制 中 USBwIndex0==0 分支保持原 HID 逻辑不动,最小改动。
日志高频触发主循环阻塞 中 CDC 发送用环形缓冲 + 中断驱动,主循环只投递不阻塞。
RAM 超限 中 控制日志缓冲 ≤1.5KB,必要时减小。

11. 结论

该改动可行。核心是 usb_prop.c(类请求分发)+ usb_desc.c/.h(复合描述符)+ usb_conf.h(端点/PMA)+ App_Usb_HL(CDC 发送 API),不触碰库内核 usb_core.c,不动 Bootloader。
