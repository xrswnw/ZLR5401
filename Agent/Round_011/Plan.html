1. 解锁相关流程总览

设备有两条解锁主线 ( Locker 多标签结账编排 / OneShot 单标签同步开锁 ) 和三个背景流程 ( 回零 / 行程测试 / 行程错误 )。客户能"看见"的灯带语全部来自这五条线。

1.1 OneShot 单标签同步开锁 (客户在场, 交互主流程)

⑴ 前置检查 (Locker/UHF/电机空闲 + 已回零)         → BUSY/HOMING 直接回错误
⑴.5 等红外: 等客户放硬标签 (PC4 光电, 窗=irWaitMs)   ★青慢闪 (现状)
⑴.6 消磁准备 (仅 demagCnt>0: 探链, 保持检测模式)
⑵ UHF 就绪 (必要时上电)                            ★青慢闪 (现状)
⑶ 持续盘点校对 EPC: 反复 0x22 读场内标签       ★青慢闪 (现状)
     读到标签但非期望 → 连续 N 轮 → MISMATCH 红闪 3s 不升起
     校对预算内无任何标签 → NO_TAG
     命中期望 EPC → (此刻才切 AM 消磁模式)
⑷ 升起: 上行至 KEY_UP 触点                   ★绿常亮 (现状)
⑸ 软标消耗: demagCnt 个软标 (AM 消磁 + 红外计数)    ★白常亮 (现状)
⑹ 回降: 下行至 KEY_DOWN                            ★灭 (现状)
     全程完成 → 绿三连闪 1.8s

1.2 Locker 多标签结账编排 (七状态机, 后台运行)

IDLE → CONFIGURED (配清单等放硬标, 持续扫描)          ★青慢闪
     → UNLOCK_HOLD (逐张匹配; 命中→绿单闪+升起)       ★升=绿常亮 / 扫描段=青慢闪
     → SOFT_DECODE (硬标全解, 轮软标: 红外+消磁)      ★白常亮
     → DONE (全部消耗完; 绿三连闪) → LOWERING 回降     ★灭
     → FAULT (8 种故障归因)                           ★红常亮

2. 现状灯语盘点 — 8 色能力与占用

灯带为开关型 GPIO 三色 (G=PA4 / R=PA5 / B=PA6, 蓝通道硬件已回归, RGB_HAS_BLUE=1), 无调光 — 图样 = 颜色 + 周期/占空比。理论 8 色 × (常亮/慢闪1s/快闪0.5s/短闪0.2s) 组合充足, 但客户可见语义应控制在 5 色以内 (见 §4)。

颜色组合当前用途 (状态)当前用途 (事件闪)
绿 G100升起/解锁保持 (常亮)硬标命中 (单闪 200ms) / 结账完成 (三连闪)
红 R010故障 FAULT (常亮)EPC 失配 (快闪 3s) / 消磁失败 (双闪)
黄 G+R110回零 (慢闪) / 行程测试 (快闪)—
青 G+B101扫描等硬标签 (慢闪) ★与"等放标"共用一色—
白 G+R+B111软标等待/红外消磁 (常亮)软标消耗成功 (单闪)
粉红 R+B011下行程开关错误 (闪, 工程语义)—
蓝 B001完全未使用 — 空闲色—
灭000待机 / 回降 / DONE 后—
现状结论: 8 色实际用了 6 色 + 灭, 蓝色完全空闲; 客户主线只占 绿/红/青/白 四色, 工程语义 (黄/粉红) 与客户语义已天然分离。已有仲裁器 (L1 行程错 → L2 事件闪 → L3 稳态 → L4 手动 → L5 灭) 结构完备, 新增灯语只是查表加行 + 调用点改色, 不动架构。

3. 需求建议逐条评估

需求建议现状评估结论
一致 → 绿亮升起开锁绿常亮 (升起)已实现, 语义直观, 保留保留
不一致 → 红闪不升起红快闪 3s + 不升起已实现, 保留保留
等待红外 → 白色青慢闪可行。白目前 = 软标等待 (也是"等人操作"), 把白统一为"等待你的操作"语义, 等放硬标/等软标消磁同色, 普通人记一种就够。建议白慢闪 (等待中) 与软标白常亮 (流程已过半) 区分层级采纳·改白慢闪
等待硬标签解码 → 全灭青慢闪 (与等放标同色, 无法区分阶段)方向对 (该阶段应与"等放标"区分), 但全灭有代价: ①与待机/关机无法区分, 客户放了标却见设备"没反应", 分不清是在读还是死了; ②灯带灭 1-10s 的盘点窗内没有任何"活着"的证据。备选: 蓝慢闪 ("正在读标签") 或 长周期心跳蓝 (3s 周期亮 150ms, 视觉接近"安静的呼吸")决策点 D1
解码成功一个标签 → 闪一下无任何反馈 (仅命中那张绿闪)这是现状最大盲区, 强烈建议新增。客户把标签放上去之后, 现在只有"命中"(绿) 和"失配"(红) 两种结局灯, 中间读到过什么都不说 — 现场极易误判"设备读不到/坏了"。建议每解码一张 (无论是否期望标签) 蓝单闪 200ms, 给"我看到东西了"的即时触觉反馈。闪显槽深 1, 连续多张会合并成一次闪, 恰好不会闪成爆闪新增·蓝单闪
EPC 扫描中 → 展示无独立展示 (与等放标共用青闪)与"等待解码"同一阶段 (⑶ 盘点校对)。即 D1 决定的颜色/图样就是"扫描中"的展示; 若选蓝系, 则形成完整叙事: 白=等你放 → 蓝=正在读 → 闪一下=读到了 → 绿=对了 → 红=错了随 D1
其他实际状态 (开放项)见 §5 表"失败类盲区"NO_IR / NO_TAG / 链路断等失败路径目前灯直接回灭, 现场人无任何失败提示 (仅上位机能看到 err 码) — 建议补, 见 D4决策点 D4

4. 普通人视角: 哪些状态值得亮灯

站在"什么都不懂、只想把标签解开"的使用者角度, 按重要性排序 (①最优先):

#用户心里的问题对应状态现状能回答吗重要性依据
①"我现在该干什么?"等放标 / 等软标能 (青/白), 但两色无"等你"的统一感每单必经, 最高频
②"我放的东西它读到了吗?"盘点中读到标签 (含非期望)不能 — 盲区读不到 vs 设备坏了, 客户无法自救, 直接找店员/售后
③"成功了吗 / 错了吗?"命中升起 / 失配 / 完成能 (绿/红闪/绿三连闪), 语义已直观结局时刻, 决定客户走还是留
④"设备是活的吗?"任何流程进行中 vs 待机/死机部分能; 若采纳"全灭"则不能黑屏焦虑 — 无人值守场景尤其重要
⑤"坏了是什么坏法?"NO_IR/NO_TAG/链路断/机械故障基本不能 (仅失配有红闪; 其余灯直接灭)店员排障第一入口, 但可用声音/上位机兜底
—(工程状态: 回零/测试/行程错)装机调试期状态能 (黄系/粉红, 已与客户语义分离)客户不关心, 维持现状即可
设计原则 (从上面推导, 越少越直观):
  • 一色一义: 绿=成功 / 红=出错 / 白=等你操作 / 蓝=我在读标签 / 黄=设备自检忙 (工程)。粉红仅工程用。
  • 闪=需要你注意或正在活动, 常亮=状态稳定: 慢闪(1s)=等待/进行中, 快闪(0.5s)=告警级, 短闪(0.2s)=瞬时事件确认。
  • 绝不全灭表达"正在工作" — 灭只属于"待机/完成"。
  • 客户可见色 ≤5 (绿红白蓝 + 灭); 超过这个数, 普通人就开始查手册, 设计就失败了。
  • 时序完整性: 灯语叙事链条 白(等你) → 蓝(在读) → 蓝闪(读到了) → 绿(对了/升起来了) → 绿三闪(办完了) / 红闪(不对) / 红常亮(坏了)。

为什么这样分白/蓝: 白 = "该你了" (设备在等人动作 — 放标、消磁), 蓝 = "该我了" (设备自己在干活 — 射频读标签)。绿/红保持不变是因为已经是对的。青色从客户主线退场 (空闲出来, 留给未来扩展), 客户面从 4 色减到 4 色但每色一义、每阶段一色, 阶段推进时灯必变色, 客户永远知道流程走到哪了。

5.3 备选方案 B (严格按需求原案)

等待解码阶段 = 全灭, 其余同方案 A。实现最简单, 但付出: 流程 1~10s 内灯带全黑, 与待机/断电不可区分 (§4 ④); 期间读标闪烁 (蓝单闪) 会成为黑暗中唯一信号, "闪一下然后又黑"体验上像接触不良。若确认现场有屏显/声音兜底告示"扫描中", 此方案可接受。

风险与已知边界:
  • 蓝通道依赖 RGB_HAS_BLUE=1 (PA6 已回归硬件); 若现场批次蓝灯缺失, C_CYAN/C_WHITE/C_PINK 走既有降级路径, 新增蓝图样需同样配降级 (C1 已含)。
  • "读到一张标签闪一下"在 Locker 连续扫描下每轮盘点都会闪 (1s 周期) — 若场上常驻无关标签, 灯会规律蓝闪, 这是预期 ("一直看到那张标"), 但需现场确认不致误解为故障。
  • OneShot ⑶ 盘点循环是阻塞泵 (LockerSeek_Pump 内推进灯), 闪显与稳态切换时序已由仲裁器保证, 无需额外处理。
