ZLR5401 UHF 多标签盘点 · 实施报告

Agent/Round_049  ·  2026-08-26  ·  依据 EX10 协议: 0x22 同步盘存(带超时)+0x29 取缓冲  ·  已编译验证

1. 结论小结

依据厂商协议《EX10系列模块通信协议-2026-01-19》核实并落地 多标签同步盘点，替代此前的单标签 0x21 实现，编译通过（0 error / 0 warning）。

  • 一次请求拿全场：INVENTORY 由单标签 0x21 改为 0x22 同步盘存（在内部超时窗口内盘存场内所有标签）→ 状态机转入 GETBUF → 0x29 取回缓冲，上位机仅一帧交互即返回场内全部标签，状态机自动管理。
  • 超时由 API 提供：新增 App_UHF_InventoryTimeout(ms) 与复用协议的 SET_SCAN.timeout，直接作为 0x22 的 Timeout 域。
  • RSSI 真值：0x29 元数据含 RSSI（有符号 dBm），顺带弥补之前 RSSI 恒 0 的缺口，测距可定量。

2. 需求映射

需求 / 澄清实现代码
仅一帧交互就返回场内标签 内部状态机：INVENTORY(发 0x22) → 响应→GETBUF(发 0x29) → 取回全部标签→READY；标签逐条实时推 PUSH_EPC + 入 TagTake 缓冲 App_UHF.c uhf_inventory_start / decode 0x22/0x29

超时时间 API 提供 App_UHF_InventoryTimeout(ms)；SET_SCAN.timeout 复用为 0x22 Timeout App_UHF.c

3. 协议核实 (EX10 文档 §5.3 / §5.4)

指令发送 Data响应 Data
0x22 同步盘存 [Option(1), SearchFlags(2), Timeout(2)] → 本实现发送 00 00 00 TT HH [status(2), Option(1), SearchFlags(2), TagsFound(1|4)]
0x29 取缓冲 [MetadataFlags(2), ReadOption(1)] → 本实现 00 17 00（含 RSSI） [status(2), MF(2), Option(1), TagCount(1), 每标签块…]

0x29 每标签块（MetadataFlags=0x0017）：ReadCount(1) RSSI(1) AntID(1) Timestamp(4) EPCLen(2) PC(2) EPCID(N) TagCRC(2)。TagsFound>255 时该字段为 4 字节（SearchFlags.BIT4=1）。本实现按 ≤255 单字节处理（场内标签数远小于此，如需可扩展）。

4. 状态机

READY --Inventory(0x22)--> INVENTORY ──0x22响应(tagsFound>0)--> GETBUF ──0x29响应--> READY
                              └──tagsFound==0 / 超时──────────────────────────► READY
GETBUF 同列为忙态: Stop/空闲超时(1500ms) 均可中断回 READY

新增 APP_UHF_GETBUF = 7，纳入 App_UHF_IsBusy()、App_UHF_Stop() 与忙态超时保护，状态机完整闭环。

5. 实时推送 (PUSH_EPC) 带 RSSI

data = [UHF_SUB_PUSH_EPC(0x0F), epcLen, rssi(有符号dBm), epc..]

每读到一帧有效 EPC（0x29 解析出）即经 USB 主动推送，主机实时收到标签及其信号强度。

7. 待实测提示（骨架级风险）

  • 0x22 / 0x29 帧格式依《EX10系列模块通信协议-2026-01-19》编写，尚未在真模块上联调确认；尤其 0x29 元数据块偏移、TagCount 字节位置宜用文档 §5.4 实例核对。
  • 箱内若 >255 标签需处理 4 字节 TagsFound（当前按 1 字节，单天线/测距场景基本不会触达）。
  • 建议上位机先验证一帧 INVENTORY 后逐个 PUSH_EPC 到达即可。
