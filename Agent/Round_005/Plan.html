0. 范围重定位（v2 相对 v1 的关键纠正）

设备真实身份：这是 AM EAS 消磁器（Deactivator），不是读唯一标签 ID 的读写器。 其业务本质 = 「检测到标签 → 消磁(Deactivate) 或 报警」，不读标签唯一 ID。
v1 计划（已作废）v2 计划（本次执行）
把 cmd17 的 5B「ID」当作标签唯一 ID 驱动软标消耗cmd17 5B 字段恒 FF×5，是固定占位，不区分标签；只作为「检测到标签」事件
波形 cmd64 按 4 包重组 400 点→求回波→解 ID实时 4 包不可靠（只见 seq0/1）；波形仅作后台可选项，不承载解 ID
0x88 被动解码作为备选读 ID固件实测不支持 0x88，禁用
——新增：参数配置暴露（本地缓存，勿读回）、工作模式可配（0x50）、cmd17 事件监控上报
结论：本次交付的是「配置 + 模式 + 监控」三件套，不做标签 ID 解码。产品集成若需「检测到标签即触发开锁」，用 cmd17 事件计数即可，无需 ID。

1. 目标

  1. 配置暴露：把消磁器全部可配参数（阈值/命中/频率/延迟/长短/零火/相位同步/解码电压/市电）通过自定义协议暴露给上位机 get/set，断电重启保留（持久化）。
  2. 工作模式可配置：0x50 模式 0=检测/消磁、1=仅检测、2=待机，独立 get/set，持久化，重启复原。
  3. 监控：接收解析 cmd17 主动上报（~1Hz）作为「标签检测事件」，累计计数、标记链路活动；协议层可读状态（事件数、链路、最近时间）。

参数读语义（易错）：设备参数为「回显式」，发空数据会把参数写成 0。 因此 设备端必须本地缓存已写入值，「读配置」返回本地缓存，绝不依赖 0 数据读回。 当前 App_AM_GetParam 实现（发空数据等回显）是错的，本次改为缓存读取。

3. 配置模型

复用现有 AppAMConfig_t（App_AM.h）+ AMUserCfg_t（App_Param.h 持久化，userParam 偏移16，magic 'AM'）。补一个 mainsFreq（市电 0x5D：0=50Hz/1=60Hz）字段。

4. 代码改动

4.1 App_AM_HL.h / App_AM_HL.c — 非阻塞取帧

  • 新增 int AM_HL_TryRecvFrame(uint8_t *cmd, uint8_t *data, uint8_t *len); 非阻塞版（复用 am_uart_peek_frame，无超时等待）。
  • 保留现有 AM_HL_SendFrame/RecvFrame/RxFlush（写参数/链路探测仍阻塞等待回显）。
// App_AM_HL.h 新增
int AM_HL_TryRecvFrame(uint8_t *cmd, uint8_t *data, uint8_t *len); // 0=OK, -1=暂无完整帧
原因：cmd17 被动上报需在 App_AM_Process 主循环里轮询取帧；若用阻塞 RecvFrame 会卡主循环。取到 cmd17 即计数。

4.2 App_AM.h / App_AM.c — 缓存语义 + 模式 + 监控

  • AppAMConfig_t 增加 mainsFreq 字段；APP_AM_CONFIG_DEFAULT 相应补 0。
  • App_AM_GetParam 改为返回本地缓存（按命令查 s_cfg），不再发空数据读回。返回值语义不变。
  • App_AM_SetParam：写后回显校验成功，同时更新本地缓存（cmd 与 s_cfg 字段一一映射）。这样回显校验保留，且缓存即真相。
  • App_AM_SetConfig：逐条下发（含 mainsFreq）；成功后整包写回 s_cfg。
  • 监控：新增 
    uint32_t  App_AM_GetEventCount(void);  // 检测到标签事件累计 (cmd17 次数)
uint32_t  App_AM_GetLastEventMs(void); // 最近一次事件相对上电 ms (0=尚无)
  • App_AM_Process：改为有实际逻辑 —— 轮询 AM_HL_TryRecvFrame；收到 cmd=0x17 即 s_evtCount++、记录 s_lastEvtMs、s_link=OK。收到任何合法帧都视为链路活动。
  • App_AM_Query：修正错误的 AM_CMD_QUERY_ALL(0x3F)（0x3F 无对应命令），改为「探测链路」：若最近收到过 cmd17/合法帧则 OK，否则按超时窗判定。

4.3 App_CustomProtocol.h — 新增子命令

// 追加 (保留原有 0x01..0x05)
#define AM_SUB_GET_STATUS   0x06 /* data:[cmd] 读监控: [cmd,err,link,evtL,evtH,lastL,lastH] */
#define AM_SUB_SET_MODE     0x07 /* data:[cmd,mode] 仅切工作模式(持久化) */

4.4 App_Dispatch.c — 新增处理分支

  • AM_SUB_SET_CONFIG：解析加读 mainsFreq。版本兼容：dataLen>=15 → mode@13,mainsFreq@14；否则 mainsFreq=当前值。
  • AM_SUB_GET_CONFIG：响应追加 mainsFreq 字节。
  • AM_SUB_GET_STATUS：打包 link、evtCount、lastEventMs。
  • AM_SUB_SET_MODE：App_AM_SetParam(0x50, mode) + 持久化模式 + 更新本地缓存。
  • main.c 持久化装载处，映射新增 mainsFreq。

5. 工作模式业务语义（开锁编排）

约定：模式 0x50 不仅写设备，还影响本机开锁业务流程 —— 0=检测/消磁（正常：检测到→消磁→开锁/计数）；1=仅检测（检测到→报警/提示，不消磁不开锁）； 2=待机（远程禁用，锁定不响应）。本次先在上位机侧预留 SET_MODE 接口与文档约定；开锁器业务联动留在后续 Round（App_Locker）。

6. 持久化

  • 复用 AmParam_Save/Load（magic 'AM'，偏移16）。新增 mainsFreq 字节后负载 17B，仍在 172B userParam 内，无需改 magic/offset；LOAD 缺省补默认 0 保证旧记录兼容。
  • 写 Flash 时机：AM_SUB_SET_CONFIG（成功）与 AM_SUB_SET_MODE。
