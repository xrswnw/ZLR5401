ZLR5401 电机测试指令 — 实施计划

Agent/Round_006 · 日期 2026-08-25 · 本文档为设计计划，尚未实施，待评审后执行。

1. 需求理解

新增一条上位机指令，对步进电机进行自动化行程测试：

  1. 增加一条指令：电机测试。
  2. 测试动作：无人工干预下，以最快速度正转到上触点，检测到触点动作后立即反转至下触点触发 —— 这构成 1 次往返。
  3. 帧格式：首字节 = 测试次数 N，单次 = 触发两触点为止（即一次上行程 + 一次下行程）。
  4. 状态机管理：若当前正在测试，收到新测试指令返回忙（BUSY）。

2. 设计要点

2.1 触点检测 — 极性无关，最稳健

行程开关电平：KEY_UP=PC8、KEY_DOWN=PC9，上拉输入、高电平=触发，读取函数 App_NewPeriph_ReadKeyUp/Down() 已可用。

推荐：极性无关检测。每半程不论「正转/反转」，只要检测到任一触点动作即判定到达，随后反转去触发另一触点。 因为每次往返本来就必经两个触点，所以即使固件里「正转」映射到的物理触点与「上触点」相反，动作序列仍等价于「上→下」， 可自校准，不依赖方向位的物理极性，也不引入方向配置项。
（若严格要求「正转必须到上触点、反转必须到下触点」，则需在计划外另行确认 dir=0/CW 对应哪一侧，本文不采用该简化之外的耦合。）

2.2 防抖 / 消重触

  • 行程开关存在机械抖动，不能以单次瞬时读值判定。每次节拍读值，要求触点连续 N 次保持触发（约 20ms）才认定为有效触发。
  • 消重触：一次触发生效后，须等两触点都回到释放（都读数 0）后再允许下一次触发计数，避免在触点仍被压住期间刚反转就误把同一触点再计一次。

2.3 运行参数

  • 测试期间把步进速度提到最高：App_Stepper_SetSpeedHz(2000)（沿用 STEPPER_MAX_HZ=2000 上限），转矩设 100%：App_Stepper_SetTorquePercent(100)。
  • 运动用「持续运行」：App_Stepper_Move({dir, steps=0})，不停转，仅靠触点触发来反转/停止。

2.4 安全保护（必须）

触点损坏/未接线时不能无限狂转，需两重兜底：
  • 单程超时：自本次方向启动起，规定时间内（如 10 s）仍无触点触发 → 判故障，停止电机。
  • 电机故障：若 App_Stepper_GetState()==FAULT（DRV8434S 报故障/堵转）→ 立即停止测试。
  • 任一保护触发即 App_Stepper_Stop()，状态置 FAULT，并上报。

2.5 指令形态

新增独立功能码 FC_MOTOR_TEST (0x0F)，内部分子命令，与既有电机运动控制 FC_MOTOR_CTRL(0x0A) 分离，清晰表达「整机自检」语义：

子命令值数据说明
TEST_SUB_START0x01[cmd, N]启动测试，N=往返次数（≥1）
TEST_SUB_STOP0x02[cmd]中止测试，回到空闲
TEST_SUB_QUERY0x03[cmd]查询状态/进度
错误码值含义
TEST_ERR_OK0成功
TEST_ERR_BUSY1正在测试，拒绝新启动
TEST_ERR_PARAM2参数非法（N=0 等）
TEST_ERR_FAULT3电机故障 / 触点超时

完成上报方式：START 立即回 [cmd,err]；主机随后轮询 QUERY 取进度与完成。QUERY 响应： [cmd, err, state, total, done]，其中 total=请求次数、done=已完成往返数。state：0=IDLE、1=RUN、2=DONE、3=FAULT。

3. 新增模块 App_MotorTest

独立的应用层状态机模块，主循环周期推进，遵循既有分层（新外设行程开关在 App_NewPeriph_HL.c，电机控制走 App_Stepper.c API）。

3.1 状态机

IDLE ──START(N)──► RUN_UP ──(触点)──► RUN_DOWN ──(触点,完成1次)──┐
                                        done<N ──► RUN_UP (再反转)│
                                        done==N ─► DONE ──(延时)──► IDLE
RUN_* ──(电机FAULT / 单程超时)──► FAULT ──(STOP/CLEAR 或自动复位)──► IDLE
任意非 IDLE —— STOP ──► IDLE

3.2 模块接口（App_MotorTest.h）

void  App_MotorTest_Init(void);                     /* 复位状态=IDLE */
int   App_MotorTest_Start(uint8_t passes);          /* 0 OK / -1 BUSY / -2 PARAM */
int   App_MotorTest_Stop(void);                     /* 中止, 回 IDLE, 停电机 */
void  App_MotorTest_Process(void);                  /* 主循环节拍 */
int   App_MotorTest_IsBusy(void);                   /* 1=正在测试 */
uint8_t App_MotorTest_GetState(void);              /* 0 IDLE/1 RUN/2 DONE/3 FAULT */
void  App_MotorTest_GetProgress(uint8_t *total, uint8_t *done);  /* 进度 */
/* 结果供协议层上报: */
typedef enum { MT_DONE_OK=0, MT_ABORT=1, MT_FAULT=2 } AppMotorTestResult_t;
AppMotorTestResult_t App_MotorTest_GetResult(void);

3.3 实现逻辑（App_MotorTest.c 骨架）

Process() 每 tick(=主循环) 运行:
  if state != RUN: return
  1) 电机故障检测: if App_Stepper_GetState()==FAULT → 停+置FAULT，上报，return
  2) 防抖采样: read KEY_UP/KEY_DOWN;
     if 任一连续保持触发 2~3 次tick → 认为有效触发 (当前只有 1 个方向在跑)
  3) 无触发: 单程计时超时(10s) → 停+置FAULT，上报，return
  4) 有触发(contact_i) :
     - 若本次行程不是「刚从同方向启动」或触点已 re-arm(两触点已释放):
         标记本半程完成; 校正 done / 方向:
         a) 若已完成下行程(一次往返)且 done>=N → 停, DONE, 上报
         b) 否则: 换反向 App_Stepper_Move({ ~dir, 0 }), 进入下一个半程, 清零单程计时 & 触点按下锁存

5. 验证方案

  1. cmake --build Build 编译，确保新增代码无警告/错误。
  2. 烧录后经上位机（或 HID 测试驱动）下发 FC_MOTOR_TEST START, N=1：
    • 应回 [0x01, TEST_ERR_OK=0]；应立即看到电机高速正转→上触点→反转→下触点 一次往返后停止。
    • 反复下发 START：应回 TEST_ERR_BUSY=1（正在测试状态机正确）。
    • QUERY 轮询：state 从 RUN→DONE→IDLE，done 从 0→N。
  3. 边界：N=0 → 回 TEST_ERR_PARAM=2。
  4. 故障保护：断开某一行程开关输入（使触点永不触发），START 后应在 ~10s 超时 → 自动停转并置 FAULT。
  5. 与既有功能回归：电机升降锁、UHF/AM、USB 枚举不受影响（新状态机仅在本指令触发时占用电机）。

7. 待确认点 / 建议

  • 方向极性：本设计为极性无关（任一触点均可触发换向），故无需确认 dir 物理映射。若不希望这样、坚持「正转必须=上触点」，请补充说明。
  • 单程超时阈值：默认 10s，可按机械行程长度调整。
  • 指令形态：默认新增独立 FC_MOTOR_TEST 0x0F；若更倾向并入 FC_MOTOR_CTRL 作第 7 号子命令，可改（更省功能码，但语义混在同一组运动指令里）。
  • 完成后动作：默认执行完自动停转并置 DONE→IDLE。建议在测试过程中若电机堵转/多次超时，应让主机能看到 FAULT 以便排查机械问题。
