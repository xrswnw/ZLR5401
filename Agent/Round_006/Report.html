4. 协议定义

// FC=0x0A 子命令 (新增)
MOTOR_CMD_TEST   0x07   // data: [cmd, passes]  passes=往返次数(1~255)
                        // 流程: 最高速正转→触点→立即反转→触点(完成1次)→重复passes次→停转
                        // 进行中再下发: 回 MOTOR_ERR_BUSY(3)
MOTOR_ERR_BUSY   3      // TEST 进行中

响应：[0x07, err]。可用 MOTOR_CMD_QUERY(0x05) 轮询状态（state 0=IDLE/1=RUN/2=FAULT）。

5. 状态机（App_MotorTest.c）

IDLE ─START(passes)─► RUN ─(任一触点触发, 防抖20ms)─► 换向
      RUN 每完成一次"反转行程" = 1 次往返
      done ≥ passes ─► App_Stepper_Stop() ─► DONE ─(QUERY可读)─► IDLE
      RUN  ─(电机FAULT / 单程10s超时)─► FAULT ─(Stop/重新Start)─► IDLE
  • 极性无关：任一行程开关触发即换向，自校准，不依赖方向位物理正负。
  • 防抖：触点需连续保持 20ms 才判定有效。
  • 消重触：两触点都释放后才允许下一次触发，避免在同一触点反复计数。
  • 保护：单程超时 10s → FAULT；DRV8434S 电机故障 → 立即停转。

7. 硬件验证（USB HID）

设备枚举 0x5377:0x5378 SwCcrd / SW COMPOSITE 正常。 经 /private/tmp/motor_test.py / motor_busy.py 实测： 
START N=1            -> [0x07, err=0]   启动成功
QUERY                -> state=1 (RUN), fault=0x00
START(运行中再次下发) -> [0x07, err=3]   MOTOR_ERR_BUSY ✔
电机触点往返 N 次后     -> 自动停转, state 回到 0 (IDLE), fault=0x00
再次 START           -> err=0   ⚙可再次启动
电机按预期高速正转→行程开关触发→立即反转→触发另一触点，完成往返后停转，未误报故障。

8. 追记：BUSY 验证说明

首次测试脚本在连续两次下发 START 间未加延时，HID 帧缓冲竞争导致第二次读回旧响应而误判"第二次 start 返回 OK"。 经 motor_busy.py（下发间加延时 + 打印原始帧）复核，运行中再下发实际返回 [0x07, 0x03]=BUSY，固件行为正确，非缺陷。

9. 遗留 / 建议

  • 单程超时阈值 10s 为默认值，可依机械行程长度调整（MT_TEST_TIMEOUT_MS）。
  • 防抖时长 20ms（MT_DEBOUNCE_MS）经验值，实机抖动噪声小时可下调。
  • 未触碰看门狗（USE_IWDG=0 保持）。
