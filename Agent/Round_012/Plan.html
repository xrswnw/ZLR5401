1. 背景与设计输入

零售结账六条约束（客户付款 → 上位机传 EPC → 接收硬标 EPC+软标数 → 放标光电触发 → 比对绿升红闪不升+结果回传+2min/30s窗口+m=n → 软标逐个解码计数 → 结账完成）已在 ONE_SHOT 0x08 v2.3（单标签）上闭环验证。本轮将语义泛化为多标签整合主路径，四条 硬性设计约束 + 本轮新增两条：

#约束设计落点
1解锁命令下发后进入解锁态，仅响应停止与状态获取；参照 64B 单帧，限制 EPC 数量§3 / §4
2光电闸门存在，就是 IR（PC4）§7 状态机 WAIT_TAG
3EPC 校对中不响应上位机命令；EPC 稳定确认一张上报一帧；盘点去重+防抖；考虑标签静默可行性§5（核心章）
4状态机严格约束§7
5确认帧内容 = EPC + 序号 + 已确认数/总数 + 用时；每张确认后蜂鸣器响 200ms§3 / §6
6时长、数量等参数全部宏定义，方便后续调整§8

2. 设计总览与定位

现有两条路径的分工保持不变，新路径定位为第三条、面向零售结账的整合主路径：

路径载体定位本轮动作

整体流程一图：

上位机                                设备（阻塞自治）

  │                                     [WAIT_TAG] 待放标, IR 门控, 窗=W
  │<────────── IR 触发(200ms 去抖) ──────

  │<── 确认帧: EPC_i+序号+已确认/总数+用时 ──  + 蜂鸣 200ms
  │<── 确认帧: EPC_j ...                │  (每稳定一张一帧+一声)
  │<── 硬标完成帧: n==m 或 窗满(实况) ───  回降磁块
  │                                     [SOFT] softCnt=0 跳过
  │<── 软标解码帧 ×k / (k==softCnt) ─────
  │<── 结账终帧 ────────────────────────  [DONE] → IDLE, 退出解锁态

3. 命令与帧设计

3.1 64B 单帧预算与 EPC 数量上限

USB HID 单帧 64B，扣帧头/地址/功能码/长度/校验后数据区约 57B。解锁命令固定开销 8B （子命令 1 + 每轮盘点时限 2 + 解锁窗 2 + 软标数 1 + EPC 数 1 + 统一 EPC 长 1）， 剩 49B。典型 12B(96bit) EPC → m ≤ 4 张（12×4=48）；实测标签若 EPC 不足 12B， 按统一 epcLen 动态放宽到 5~7 张。数量上限直接吃单帧容量，不做 ADD 多帧累加（见 D1）。

3.2 解锁命令帧（新子命令 0x0A，func=0x0D）

data[0]    = 0x0A  子命令
data[1..2] = tmoMs     每轮盘点时限 (LE, 0→默认 1000)
data[3..4] = holdMaxMs 解锁窗 W (LE, 0→公式 W=UNLK_HOLD_BASE_MS+(m-1)*UNLK_HOLD_EXTRA_MS)
data[5]    = softCnt   软标数量 N (0→硬标完成即结账)
data[6]    = epcCnt    硬标数量 m (1..UNLK_MAX_TAGS)
data[7]    = epcLen    统一 EPC 字节长 (1..UNLK_EPC_MAX)
data[8..]  = m × epcLen 字节, 依次为期望 EPC (设备内按集合比对, 与顺序无关)

设备在 IDLE 且通过前置检查（回零就绪/电机空闲/UHF/AM 不忙）→ 立即回 ACK 帧 （err=0、phase=WAIT_TAG、W 实际值）并进入解锁态；不满足 → 回 BUSY/错误帧，不进入。

3.3 设备主动推送帧（func=0x0D^0xFF=0xF2）

子码帧名触发data 布局（[0]=子码后）
0x0B确认帧某期望 EPC 达稳定确认判据（每张一帧） seq(1) + epcLen(1) + EPC + confirmed(1) + total(1) + confirmMs(2,LE 自 IR 触发起算) + elapsedMs(2)
0x0C失配事件帧连续 UNLK_MISMATCH_CONFIRM_ROUNDS 轮只读到清单外 EPC 且无任何清单标签在场 epcLen(1) + EPC(最后外来) + rounds(1)
0x0D硬标完成帧n==m 或窗满（部分完成）→ 进回降前 endReason(1) + confirmedBitmap(1, bit i=EPC_i) + confirmed(1) + total(1) + elapsedMs(2)
0x0E软标解码帧每次解码成功计数 +1softDone(1) + softCnt(1)
0x0A结账终帧SOFT 结束/跳过后 err(1) + endReason(1) + confirmedBitmap + softDone + rise/lower steps + elapsed（沿用 ONE_SHOT 终帧风格）

终帧 data[0]=0x0A 与命令子码一致，上位机以"收到 0x0A 回显帧"为流程结束标志 （与 0x08 单标签通道的收帧约定完全同构）。确认帧 seq 按确认先后顺序编号， 上位机匹配以 EPC 为准、不依赖顺序。

3.4 状态获取（0x09 GET_PROGRESS 扩展）

解锁态全程可用：phase + confirmedBitmap + softDone + holdMs + 当前在场标签数。 一次查询即可还原整体进度，帧内塞得下（m≤4 → 位图 1B）。

3.5 响应策略（约束 1 + 3 的合并口径）

"校对过程中不响应上位机命令" 取语义为 不执行，而非不回话：解锁态内除 STOP 与状态获取外，任何命令回 BUSY NAK 单帧（现 dispatch 白名单机制扩展）。 理由：纯静默无法区分"设备忙"与"设备死"，NAK 一帧成本极低且阻塞泵循环内协议层本来就在收发。

5. 多标签校对详细设计（约束 3，核心章）

5.1 每标签独立状态模型

清单内每个 EPC 一条独立记录，四状态：

PENDING ──首次读到──> TRACKING ──判据达标──> CONFIRMED(推帧+蜂鸣) ──> MASKED(终态)
  ^                     │
  │    离场超 PRESENT 窗 │
  └─────────────────────┘   (回 PENDING 重新累计)
FOREIGN: 清单外 EPC → 不计数不升起, 只留最后一条做失配帧诊断
  • 各记录互不干扰：两张同时放、先后放、放一张取走再放下一张，收敛到同一套规则。
  • CONFIRMED → MASKED 单向不可逆（杜绝重报竞态的根本手段）：已确认 EPC 后续读到 一律静默忽略——客户把已解锁标签一直放在设备上无任何副作用。

5.2 稳定确认判据（去重 + 防抖）

实测底数：单轮盘点 ~1s，在场标签单轮漏读率 ~1/4。判据必须同时压住两类误判：

  • 误确认：手挥标签扫过场区（物理上 Gen2 解码成功=标签真实应答，"鬼读"概率极低， 需要防的是"瞬时掠过"）→ 时间维度上要求"稳定"。
  • 漏确认：标签在场但某轮没读到（25% 概率）→ 禁止"连续 N 轮都读到"式判据， 单次漏读清零会让确认时延发散。

双门限判据（时间窗 + 命中数）：

在场判定:   距最近一次读到 ≤ UNLK_PRESENT_WINDOW_MS (默认 3s, 容忍 2~3 轮连续漏读)
确认判定:   TRACKING 起点起, 在场状态持续 ≥ UNLK_STABLE_CONFIRM_MS (默认 3s)
            且累计读到 ≥ UNLK_CONFIRM_MIN_HITS 次 (默认 2)
累计规则:   TRACKING 期间在场判定不破则计数不清零; 离场超窗 → 回 PENDING 重来
时间轴:     轮:  1    2    3    4    5
            读:  √    ×    √    √    (t≈4s 达标, 3s 在场 + 3 hits)

依据：25% 漏读下，在场 3s 至少读到 2 次的概率 >95%；读到即真实，判据实际防的是掠过。 参数全部是宏（§8），台架可调。

5.3 标签静默可行性（结论：设备侧掩码为主，不依赖模块）

层机制可行性结论
设备侧掩码（主设计）CONFIRMED 后移出待比对集合，读到即静默忽略 可靠、必做。v2.2 已有同款机制（已解锁标签重复读静默），直接扩展为每标签记录

5.4 帧流时序（上位机视角）

上位机整程只收不发（STOP/查询除外）。EPC 稳定校对一张接收一帧，直至完成—— 约束 3 的原文即此实现。磁块动作沿用模型甲：首确认即升起，n==m 或窗满回降（动作最少， 复用已验证的寻触时序修复成果）。

6. 蜂鸣器设计（约束 5 新增）

硬件：板载蜂鸣器 PC12（高电平响），驱动 App_NewPeriph_BeepPulse(ms) （立即响、到期自动停，Round_010 起专职业务脉冲——IR 蜂鸣联动已按需求移除， 本设计是新的业务脉冲用途，与被移除的 IR 联动无关）。

事件提示音宏
每张 EPC 稳定确认短鸣 200ms（与确认帧同拍发出）UNLK_BEEP_TAG_MS 200
硬标段完成（n==m）沿用结账完成 300ms 口径UNLK_BEEP_DONE_MS 300
实现要点（必做，否则 200ms 变长鸣）： 蜂鸣脉冲到期由 App_NewPeriph_BeepPulseActive() 推进，当前仅主循环调用 （main.c:199）。本流程是阻塞式，主循环停转 → 脉冲永不到期 → 一触发就长响不止。 必须把 App_NewPeriph_BeepPulseActive() 加入阻塞泵循环（与 App_RgbLedPat_Tick() 同级，RGB 灯语当年进泵循环就是同一原因）。

重触发规则：BeepPulse 为"延长截止时刻"式，两张确认间隔 ≥3s（判据决定）不存在粘连； 若未来缩短判据需注意脉冲重叠=顺延而非叠响，属可接受表现。视觉+听觉同拍：确认时 RGB 绿单闪（复用现有 MATCH_OK 图样）+ 蜂鸣 200ms。

7. 严格状态机设计（约束 4）

IDLE ──解锁命令(合法)──> WAIT_TAG ──IR去抖触发──> VERIFY ──n==m 或 窗W满──> LOWER ──> SOFT ──k==softCnt 或软标窗满──> DONE ──5s──> IDLE
  │                       │                        │                                              softCnt=0 → LOWER 直接→ DONE
  │                       ├─窗W满未触发: NO_IR 帧 → IDLE (零副作用, 未动任何机构)
  │                       └─STOP → IDLE (零成本退出)
  │                                                ├─首确认: 磁块升起(KEY_UP, 内嵌于 VERIFY)
  │                                                ├─STOP/UHF失联>5s/电机故障: 终态帧→LOWER→IDLE
  │                                                └─故障: 诊断冻结快照帧 (现 FAULT 机制照搬)
  └──LOWER/回降段: 免疫一切命令 (安全动作必须走完)

严格性四原则：

  1. 命令响应矩阵封闭（§4 表写死每个状态对 STOP/查询/其他三类的响应，无"视情况"）。
  2. 触发唯一：每条转移仅一个事件可引发（计数达标/窗口超时/STOP/故障四类之一），无竞态。
  3. 单向掩码：CONFIRMED→MASKED 不可逆（根治重报竞态）。
  4. 故障即定格：故障帧携带冻结快照（fault/diag/steps/phase），退出必经安全回降。

窗口公式：W = UNLK_HOLD_BASE_MS(120s) + (m−1) × UNLK_HOLD_EXTRA_PER_TAG_MS(30s) （"预留 2 分钟，每多一标签加 30s" 的直译；m=1→120s，m=4→210s）。命令 holdMaxMs=0 用公式； 非零取 min(host, UNLK_HOLD_MAX_MS)。W 同时兼任 WAIT_TAG 等待窗与 VERIFY 校对预算， 自 IR 触发时刻起算（放标即计时的直觉口径）。

10. 验证方案（台架用例）

#用例通过判据
M1单张全流程（m=1, soft=0）ACK→确认帧(含 seq/confirmed/total/confirmMs)→硬标完成帧→终帧；蜂鸣 200ms×1+300ms×1（听感计时）；全程 ~8s
M2两张同时放（m=2）确认帧×2（各自判据独立）→ n=2=m 完成帧；两声 200ms
M3逐张放取（A 确认→取走→放 B）A 确认后 MASKED；B 重新累计并确认；无重复帧
M4部分超时（只放 1/m=2，窗 W 到期）硬标完成帧 endReason=PARTIAL + 位图明示；实况进软标/结账
M5放错标签（清单外）失配事件帧×N（红闪 3s）流程不终止；换正确标签后照常确认
M6响应矩阵解锁态内发 0x08/CONFIGURE/其他 → 均 BUSY NAK 单帧；STOP/0x09 正常
M7STOP 各阶段（WAIT_TAG/VERIFY 升起中/回降中）WAIT_TAG→IDLE 零动作；升起中→免疫回降后 ABORTED 终帧；回降中不被打断
M8蜂鸣专项阻塞全程听感：每确认一短鸣 200ms 自动停（不长鸣——验证泵循环 BeepPulseActive 补丁）；两帧间隔 ≥3s 无粘连
M9软标计数（AM 解码器接回后；接回前以事件注入桩验证）softCnt=2：解码帧×2(k=1,2) → 结账终帧 softDone=2

11. 设计决策记录（D1~D8）

#决策理由 / 取舍
D1新子命令 0x0A，不动 0x08；不做 ADD 多帧累加 0x08 v2.3 已 17/17×3 闭环且上位机已按新语义联调；单帧 m≤4 覆盖零售绝大多数单据，大清单属调试场景留给业务状态机路径
D2锁定态其余命令回 BUSY NAK 单帧，非纯静默静默无法区分忙/死机；NAK 成本极低，泵循环内协议层本在收发
D3失配推帧不终止（与 0x08 终止语义不同） 多标签场景客户可能"放错→拿走→换对的"；终止会误杀换标流程，窗口兜底更稳；0x08 单标签保留终止（已验证不动）
D4W = 120s + (m−1)×30s，自 IR 触发起算；holdMaxMs 非零则 min(host, 上限) "预留 2min，每多一标签加 30s" 直译；上限宏放开到 240s（现 ONE_HOLD_MAX_MS=60s 会截断 2min 规格）
D5磁块模型甲：首确认升起、n==m/窗满回降；硬标收尾即回降，再进软标 动作最少、复用已修时序；软标解码器与硬标磁铁无关，磁块无需为软标保持升起（比现 Locker 全程升起更安全）
D6确认判据双门限（3s 在场 + ≥2 hits），禁止连续轮判据25% 单轮漏读实测下，连续判据会发散；双门限误确认防掠过、漏确认概率 <5%
D7静默=设备侧掩码为主；模块 Session 真静默只作台架实验 现盘点模式同标签跨轮重复上报（实测），不依赖不可控的模块行为；掩码正确性与模块无关
D8确认提示音 200ms/张，与完成音 300ms 分宏；蜂鸣到期推进入泵循环 需求指定 200ms；BeepPulseActive 仅主循环推进是阻塞流程长鸣隐患（main.c:199），必补

12. 相关建议

  • 确认帧时间基准写进协议注释：confirmMs 自 IR 触发时刻起算，方便上位机对账各张耗时。
  • 上位机勿依赖 seq 顺序：确认顺序受盘点轮相位影响，跨标签无严格次序保证，以 EPC 匹配为准（协议文档注明）。
  • NO_IR 现场验证：v2.3 已实现但台架不可测（在场标签恒触发 PC4），本轮 M 用例同受此限，建议现场不放标签跑一次 W 窗满路径。
  • 蓝灯硬件补齐（Round_010 遗留建议）：本方案 WAIT_TAG 青慢闪/保持白常亮等图样依赖蓝分量，无蓝灯时走既有降级表。
  • 容量扩展预留：若未来单据超 4 张，优先压缩命令固定开销（tmoMs/holdMaxMs 可砍 4B→m=4 变 m≈5），不建议引入多帧组装（时序复杂度不成比例）。

13. 范围边界（本轮不做的事）

  • 不改 ONE_SHOT 0x08 语义（已闭环已部署）；不删改业务状态机路径。
  • 不做 ADD 多帧累加大清单（容量受单帧约束是接受的设计前提，非缺陷）。
  • 不做模块 Session/选择性盘点（SELECT）固件级改造——静默由设备侧掩码承担。
  • 不做 AM 解码器协议新增（软标沿用现有消磁计数机制；AM 未接回设备侧前 M9 用桩）。
  • 不改 Boot 侧任何代码；不动 RGB 仲裁器既有图样（只新增复用）。
