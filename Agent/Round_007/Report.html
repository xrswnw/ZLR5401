1. 结论与最终配置

2. 问题背景：为什么"一顿一顿"

原实现（commit 70b8c9f 之前）的 STEP 脉冲来源于 1ms 主循环软件累加 + 引脚翻转忙等（pin_step_pulse，10µs 级 GPIO 电平切换 + us 级忙等）。其缺陷：

  • 时基抖动：1ms 时间片只在主循环"轮到"时才翻转一次，脉冲在时间轴上成团聚集（burst），间隔不均。
  • CPU 忙等：每个 STEP 都占用 CPU 做 10µs 忙等，步频升高后主循环被拖死，其它任务饿死。
  • 宏观表现：电机肉眼可见地"一顿一顿"、走走停停，噪声断续 —— 与微步/速度无关，是脉冲时序质量问题。
根因定位 — 不是微步档位或速度选错，而是脉冲产生机制。软件时基无法在高速下提供微秒级均匀脉冲，只有硬件定时器能根治。

3. 架构改造：TIM4 硬件脉冲生成

引入 App_Stepper_Tim4.c/h，用 TIM4_CH1 (PB6) PWM 以微秒级精确间隔自动产生 STEP 脉冲：

  • 定时器时钟 72MHz（PCLK1=36MHz，APB1 预分频2 → 2×）；ARR = 72×interval(µs) − 1，CCR = ARR/2，一个完整 PWM 周期 = 一个 STEP 脉冲（50% 占空）。
  • TIM4 更新中断内完成步数计数、限步停机、斜坡调速（起步逐步升频，避免起步丢步）。
  • 方向 DIR、使能 EN_OUT、故障检测仍走 App_Stepper / DRV SDK —— 职责清晰不耦合。
// TIM4 更新中断：每周期=1个 STEP，计数+限步+斜坡升频
void TIM4_IRQHandler(void){
  if(TIM_GetITStatus(TIM4,TIM_IT_Update)!=RESET){
    TIM_ClearITPendingBit(TIM4,TIM_IT_Update);
    if(!s_run){ TIM_Cmd(TIM4,DISABLE); return; }
    s_stepsDone++;
    if(s_stepsReq && s_stepsDone>=s_stepsReq){ TIM_Cmd(TIM4,DISABLE); s_run=0; return; }
    if(s_targetHz){                                 // 斜坡：升到目标速
      uint32_t iv=tim4_ramp_interval(s_stepsDone,s_targetHz);
      uint32_t arr=72*iv-1; arr=arr>65535?65535:arr;
      TIM_SetAutoreload(TIM4,arr); TIM_SetCompare1(TIM4,arr/2);
    }
  }
}

成效 用户实测"好了很多"，脉冲均匀连续、噪声平滑；并附带释放了 600RPM——这是软件时基时代无法达到的速度（此前全步 600RPM 会丢步甚至导致整机掉 USB）。

4. S 型加减速曲线（新增）

将 ISR 内的升频斜坡由线性升级为S 曲线（两端加速度低、中段快），削减启停冲击，进一步降噪声与机构应力。

/* 8位定点 S 曲线 LUT: P(0..100) -> 升频权重 S(0..100), 免浮点/免软库 */
static uint32_t tim4_sin8(uint8_t p){
  static const uint8_t lut[11]={0,2,10,21,35,50,65,79,90,98,100};
  if(p>=100) return 100;
  uint32_t i=p/10, f=p%10;
  return lut[i] + (lu[t+1]-lut[i])*f/10;
}
// 斜坡: hz = MIN + (target-MIN)*S/100  -> 起步缓升, 中段加速, 接近目标再放缓
实测结论 — 3/3 行程往返通过（DONE / 无 FAULT / 步数 4333 ≈ 4288 基准），运动启停明显更柔。S 曲线为可持续化优化，已随本轮定稿提交。

5. 失速软保护（新增）

诊断上，DRV8434S 通过基于反电动势的失速检测（DIAG2 STALL，硬件检测真实转子丢步）；软件层面因 STEP 由 TIM4 生成、其脉冲时序只反映"命令速度"而非转子实转，纯计时无法测真实失步。因此在故障判定中补充对 DIAG2 失速位的动作，作为软保护守卫：

// App_Stepper_Process: 运行态故障判定 (FAULT 位 / 失速 DIAG2 / nFAULT 拉低)
if ((s_fault & DRV8434S_FLT_FAULT) ||
    (s_diag2 & DRV8434S_DIAG2_STALL) ||
    (drv8434s_check_fault_pin(&g_hMotor)==0)) { StepperTim4_Stop(); ...FAULT; }
硬件限制实测 — 使能 EN_STL（失速检测）在本硬件 600RPM 高转速下会误置 SPI_ERROR/FAULT（约 60 步即报，非真实失步）。经单变量隔离排除总线与 S 曲线影响后确认，失速检测功能在此设备保持关闭，仅保留 DIAG2 动作守卫。若后续需要真失速保护，应为 EN_STL 配置/学习更合适的 STALL 阈值或改用较低转速档评估。

7. 微步 × 速率 × 转矩 × 实际转速 联动分析

维度提高的影响代价
微步档位 ↑步距角更细 → 更平滑、更低噪声、更低共振幅值每转步数 ↑ → 同转速需更高脉冲率；发热轻微上升
速率(脉冲率) ↑转速 ↑逼近失步极限；负载惯量/摩擦大时需更高转矩
转矩 ↑带载裕量 +，抗失步能力 +相电流 ↑ → 发热、寿命压力、振动噪声 ↑
实际转速= 脉冲率 ÷ 每转微步 × 60微步与脉冲率是一对；乘积相等则转速相同

关键换算：每转微步 = 200 整步 × 微步系数（全步=200、1/2=400、1/4=800、1/8=1600、1/16=3200）。行程基准 10.7 圈，微步变化则步数成正比（1/2→4288、1/4→8560…）。

发热/寿命权衡：高转速 + 高细分 + 满转矩 = "三高发热"。电机温升主要来自相电流持续导通（尤其高细分 Sleep/慢衰减）。60% 转矩在 600RPM 下已实测不失步，是"够用且不烫"的甜点位。

9. 电机保护与健康监控（已实现）

电机是开锁器核心执行件，其损坏代价高（机构堵转、堵转相电流持续导通、长期超温润滑失效等）。DRV8434S 已暴露丰富的保护/诊断信号。本表建立分层"粗—细—遥"监控体系，核心已落地（堵转预警+连续运行时限+运行统计，经 MOTOR_CMD_HEALTH/STATS 协议上报）。

实现要点 — 运行态每 100ms 采样 TRQ_COUNT：持续低于阈值(默认 400, 可配)600ms → 判高负载并自动降速(800 微步/s)；降速后仍低 400ms → 强制停机。单次连续运行上限 60s → 强制停机。统计(RAM)：累计运行秒/启动次数/最近停止原因。新协议：HEALTH(0x08)、STATS(0x09)。实测自由运行 TRQ=4095(无负载)不误触发，行程测试仍 DONE/4341。

10. 后续扩展建议

  • 斜坡/加减速曲线精细化：已落地 S 型曲线；可进一步做 S 曲线减/停段、S 型 S 曲线或自适应冲度（jerk）控制。
  • 速度闭环/失速软保护：DIAG2 守卫已落地；因 EN_STL 在 600RPM 误锁，真失速保护建议改用更合适的 STALL 阈值或低速档评估（见 §5）。
  • 多档位动态切换：协议层已支持 TORQUE/速度调节，可加"运行加速段用低细分、平稳段切高细分"的两段式控制，兼顾高速与平滑（注意中途切换会改变每转步数，需同步重标定行程）。
  • 电流自适应：按负载/转速动态调 TRQ_DAC，低速大转矩、高速降流，延长寿命并降噪。
  • 休眠功耗优化：空闲时拉低 nSLEEP 关电流（已在 Stop 后有磁制动保持，可并入低功耗策略）。
  • 机械研发：600RPM 已接近细链机构的舒适上限，若需更高吞吐建议评估皮带/减速比，把步进留在中速区保平滑。
